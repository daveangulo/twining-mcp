# 1.24.0 — Field-Findings Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Executed unattended per Dave's authorization 2026-07-04; all design decisions below are locked — no user input required.

**Goal:** Fix the actively-costing field findings from the three-repo usage analysis (archive loop, record 200-char failures, silent finding loss, stuck pending queue, hook noise, dangling depends_on, migrate orphan gap) as server 1.24.0 + plugin 1.11.0, and durably capture the design-work findings as GitHub issues.

**Source:** Field analysis of twining-mcp@1.20.0 across 3 heavy-use repos (2,317 tool calls, 2,713 decisions, 3.9 GB archives). Findings verified against 1.23.0 source 2026-07-04; #2 and #3a additionally reproduced live in this session.

**Gating:** v2.0 beta is now gated on this release (v2 proposal amended).

## Locked design decisions

- **A (archive loop):** The auto-archive trigger counts only *archivable* entries — exclude `entry_type === "decision"` (never archived while `keep_decisions` defaults true) and entries tagged `"archive"` (the archiver's own summaries). The archiver's summary post is skipped entirely when 0 entries were archived, and is posted with a new internal `_skipAutoArchive` flag so it can never re-arm the trigger. `keep_decisions` default unchanged.
- **B (record 200-char):** `twining_record`'s status post truncates `summary` to 200 chars (197 + "…") instead of rejecting; when truncated, the FULL summary is prepended to `detail` so nothing is lost. The tool schema description states the cap. Direct `twining_post` keeps strict validation (its schema declares maxLength 200).
- **C (silent finding loss):** findings in `twining_record` get the same truncate-with-full-text-in-detail treatment, and the bare `catch {}` is replaced with a `findingErrors` collector mirroring the existing `decisionErrors` pattern — failures appear in the tool response, never dropped silently.
- **D (stuck pending queue):** `PendingProcessor` gains a periodic drain — `setInterval` 60s, `unref()`d, wired in server.ts alongside the startup call. Concurrency: the drain must be safe against a concurrent server draining too (read file, truncate immediately after read via atomic rename-based swap, or tolerate at-least-once posting — verify existing truncate semantics and preserve them; duplicate posts from a rare race are acceptable, lost posts are not).
- **E (hook noise, PLUGIN):** `subagent-stop-hook.sh` posts NOTHING when it cannot extract a meaningful agent identity (silence beats "Subagent completed: unknown-subagent" noise — the field analysis shows 100% of its output is this). Try `agent_type`, then `agent_name`, then `description` from hook input; if all empty → exit 0. Plugin bump 1.10.1 → **1.11.0** via `scripts/bump-plugin-version.sh` (both manifests); `bash scripts/measure-plugin-tokens.sh --ci` MUST pass (only ~107 bytes headroom — if the edit grows the byte count, trim the hook's comments to compensate).
- **F (dangling depends_on):** `DecisionEngine.decide` validates `depends_on` IDs against the decision store; unknown IDs are dropped from the stored decision, and the dropped list is surfaced in the tool response of BOTH `twining_decide` and `twining_record` ("ignored N unknown depends_on id(s): …"). Valid links kept. No retroactive sweep in this release (issue filed instead).
- **G (migrate orphan salvage):** `migrateForward`'s decision export enumerates `decisions/*.json` by DIRECTORY SCAN (excluding index.json), unioned with `getIndex()` ids — decision files orphaned from a desynced index are migrated instead of silently dropped. Report gains `orphans_salvaged` count + a note when >0; CLI prints it. (Side effect worth a test assertion: reverse migration then regenerates index.json from sqlite's getIndex, healing the desync.)

## Out of scope (design work — captured as GitHub issues in Task 5, NOT lost)

1. Decision cross-post contradiction (#5): decide() mirrors to blackboard, assemble hard-filters it — kill the cross-post or make assemble consume it. Touches ranking design.
2. Decision-retirement adoption (#7 residue): staleness/housekeeping tools shipped 1.21.0 but nothing drives their use; `superseded_by` back-links never written. Plugin/skill-surface design.
3. Agent identity (#10): auto-touch/upsert on record/post/decide, 72% agent_id "unknown", registry TTL semantics. W4-daemon adjacent.
4. Handoff redesign (#11): built-in handoffs lost to rich markdown docs; API too shallow. Rethink or retire at v3.
5. Config weights merge trap (#9): partial priority_weights + defaults sum ≠ 1.0 → silent full-defaults fallback; confusing UX.
6. Archive-repair tooling: existing repos hold GBs of loop-generated junk ("Archive: 1 entries archived" ×7.6M); a housekeeping repair/compaction path, plus release-notes guidance meanwhile.

## Tasks

**T1 — Archive loop (A).** Files: src/engine/blackboard.ts (trigger + `_skipAutoArchive` post option), src/engine/archiver.ts (skip-0-summary, flag on summary post), test/blackboard-engine.test.ts + test/archiver.test.ts additions. Tests: (a) 600 decision cross-posts + threshold 500 → post() does NOT trigger archive; (b) archiver summary post does not re-trigger even over threshold; (c) archive of 0 entries posts no summary; (d) mixed archivable entries over threshold still triggers (regression guard).

**T2 — record hardening (B+C+F).** Files: src/tools/record-tools.ts, src/engine/decisions.ts, src/tools/decision-tools.ts (response plumbing), tests in test/unit/record-tools.test.ts + test/decision-engine.test.ts. Tests: >200-char summary succeeds with truncation + full text in detail; >200-char finding posted (not dropped) with truncation; a finding that still fails (simulated engine error) appears in response errors; depends_on with 1 valid + 2 unknown ids stores only the valid link and reports the 2 ignored via both tool paths.

**T3 — pending drain (D) + migrate orphan salvage (G).** Files: src/engine/pending-processor.ts, src/server.ts, src/migrate/forward.ts, src/migrate/cli.ts (print orphans note), tests in test/pending-processor.test.ts + test/migrate/forward.test.ts. Tests: post appended to pending-posts.jsonl after startup is drained by the interval path (use fake timers or expose a drain method and call it); orphaned decision file (on disk, absent from index.json) is migrated, counted, noted, and after reverse the regenerated index.json contains it.

**T4 — hook silence + plugin 1.11.0 (E).** Files: plugin/hooks/subagent-stop-hook.sh, both plugin manifests via bump script, plugin CHANGELOG entry. Gate: `bash scripts/measure-plugin-tokens.sh --ci` green; hook tests in test/hooks/ if a harness exists for this hook (check test/hooks/ first — extend, don't invent).

**T5 — docs + backlog issues.** CHANGELOG 1.24.0 (server) + Plugin [1.11.0] section; amend docs/superpowers/plans/2026-07-04-v2.0-prep-proposal.md (Gate 0: 1.24.0 ships first; orphan-salvage moved to shipped); file the 6 GitHub issues above (each: field-analysis evidence, code pointers, "design needed" label if available, target "1.x or v2.0"); STATE.md one-line touch at release.

**T6 — gate + ship.** Full suite, SOAK_SCALE=5 soak, build, dist smoke of record truncation via MCP is impractical — instead unit-level acceptance + `node dist/index.js --version`. PR → CI → squash-merge → `npm version 1.24.0` → tag → publish → verify registry + marketplace (plugin 1.11.0 rides the merge). Known publish failure mode: E404 = expired NPM_TOKEN; retry via workflow_dispatch before declaring blocked.

## Risks

- Trigger-count change alters auto-archive timing for healthy repos → regression test (d) pins that real findings still archive.
- Plugin token budget overflow → measured in T4 with trim-comments fallback.
- Interval drain racing a second server process → at-least-once semantics accepted and documented in code comment.
