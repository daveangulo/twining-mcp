`decision-store.ts`:

```ts
export const STORE_UNSERVABLE_DIRECTIVE =
  "STOP — this store is sqlite-era (.twining/records/ present) and this host has no node:sqlite (Node >= 22.13 required). " +
  "Decision data is present but cannot be served here. Do not record decisions or commit on this host; escalate.";

function isIndexEnoent(err: unknown, indexPath: string): boolean {
  const e = err as { code?: string; path?: string; message?: string };
  return e?.code === "ENOENT" && (e.path === indexPath || String(e.message ?? "").includes("decisions/index.json"));
}

export class DecisionStore implements IDecisionStore {
  private readonly unservableReason: string | undefined;
  constructor(twiningDir: string, options?: { unservableReason?: string }) {
    this.decisionsDir = path.join(twiningDir, "decisions");
    this.indexPath = path.join(this.decisionsDir, "index.json");
    this.unservableReason = options?.unservableReason;
  }

  /**
   * ENOENT on decisions/index.json is translated to a NAMED, directive-bearing
   * error ONLY on a store the factory marked unservable (sqlite-era tree served
   * by the files fallback). Nothing else is intercepted — FORMAT_VERSION_TOO_NEW
   * and every other error propagate untouched (2.17.1 J-2b; R-1 rejected a
   * tolerant read, R-7 rejected recreating the file).
   */
  private unservable(err: unknown): never {
    if (this.unservableReason && isIndexEnoent(err, this.indexPath)) {
      throw new TwiningError(STORE_UNSERVABLE_DIRECTIVE, "STORE_UNSERVABLE");
    }
    throw err;
  }
```

## Plan discipline

### Assumptions (challenge at review)
- **A1** 2.17.0 (W2) has shipped first; line anchors here drift by its edits — every task re-greps before editing.
- **A2** The files fallback remains a supported runtime path in 2.17.x (the v3 removal is DD-12+ territory); J-2 invests in making it honest, not in removing it.
- **A3** The field's old-Node host exists or existed (their ENOENT statement reads as measured, cross-host plan A3); if hypothetical, this release keeps its vehicle and loses urgency — nothing changes in scope.
- **A4** `proper-lockfile` throws an `ENOENT`-coded error whose `path`/message names the index when the lock target is absent (observed in the fallback matrix, §1.1). If a different shape appears at TDD time, widen `isIndexEnoent` to match on the message and pin it with a test — never on `code` alone.

### What we don't know that would change the approach
- Whether the field's agents read `warnings[0]` at all (#16) — decides whether the directive also needs the hook-readable sentinel now (DD-6/DD-11 — NOT this release; record the input when it arrives).
- Whether any drain automation parses `active_decisions` as a number — `null` is the spec'd shape; note it in the CHANGELOG as the one non-numeric case.

### Decision points without Dave, with criteria
- **Match width for the ENOENT translation:** start narrow (`code === "ENOENT"` AND the index path/name); widen only on an executed failing test, never speculatively.
- **`degraded_reason` when both store and config failures occur in one call:** `"store"` wins (the more dangerous cause); test-pinned.
- **Warning order on status:** unservable FIRST, then S0 legacy-unread, then records-unread, then desync — pinned by Task 2's test; do not reorder for aesthetics.
- **Unanticipated point:** lower-risk action, decision recorded at the moment with rationale (standing instruction).

### Failure modes and recovery
| Risk | Recovery |
|---|---|
| The translation hides a real ENOENT on a files-era store | Only stores the factory marked `records_unread` get the option; Task 1 test pins raw ENOENT on a plain store |
| `repairIndexDesync` regresses on a fallback host | Task 1 chassis-style test pins the preview; the option touches no code path that `ensureFileExists` precedes |
| `null` counts break a consumer | Additive field types; CHANGELOG names it; `summary` string stays human-readable with `?` |
| J-1b warning spam | Dedupe by (scope, detail) among unresolved warnings — identical to the lifecycle-revert mechanism; one per kind per ingest |
| Review workflow stalls | Inline review from salvaged executed evidence (memory note); never a single point of failure on the release gate |

### Strongest alternative, and why not
Fold 2.17.1 into W2 (one release). Rejected at plan time (cross-host plan §4.3, ruling #2): W2 already carries the field-facing lineage bundle, the sync disclosure, the search batch and a write-path rider; adding eight fallback-diagnosability surfaces would push the pre-tag review past the size at which it has reliably caught majors.
