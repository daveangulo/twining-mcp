# Memo send: delivering the wave-2 ship memo to the field repos

The payload is `docs/field-responses/2026-08-13-wave2-ship-memo.md`
(covers 2.8.0–2.15.0, includes the D14/D15 dispositions and two
verification questions). This file is the delivery wrapper: retrieval,
cover note, and a ready-to-paste session prompt for the field machine.

## 1. Getting the memo onto the field machine

Both files are on `main` of `daveangulo/twining-mcp`. From the field
machine, either:

```sh
# from a twining-mcp checkout on that machine
git -C ~/code/twining-mcp pull
cp ~/code/twining-mcp/docs/field-responses/2026-08-13-wave2-ship-memo.md \
   <field-repo>/docs/twining/2026-08-13-wave2-ship-memo.md
```

or without a checkout:

```sh
curl -fsSL https://raw.githubusercontent.com/daveangulo/twining-mcp/main/docs/field-responses/2026-08-13-wave2-ship-memo.md \
  -o <field-repo>/docs/twining/2026-08-13-wave2-ship-memo.md
```

Destination path assumption: wherever the field repo keeps prior Twining
memos — adjust `docs/twining/` to match; the session prompt below takes
the path as its first line.

Deliver to `agentic-platform-design` first (the corpus-review lane the
memo addresses); the `agentic-platform-code` / `agentic-platform-oss`
siblings get the same file, and their only actions are the upgrade +
CLAUDE.md retirements (the D14/D15 questions are design-lane only).

## 3. Session prompt for the field machine (paste into a Claude session
in the field repo)

```
Read docs/twining/2026-08-13-wave2-ship-memo.md — the Twining wave-2
ship memo (2.8.0–2.15.0). Execute it:

1. Upgrade: `claude plugin update twining@twining-marketplace` in EVERY
   scope that pins it (check both user and project scope — a stale
   project pin shadows user scope; verify with `claude plugin list`
   afterward: both must read 1.33.0). Restart the session, then confirm
   the server banner or twining_status reports 2.15.0.
2. Apply the CLAUDE.md retirements from the memo (carrier rule, and the
   D14 workaround rule if you adopted one — override IS the sanctioned
   provisional-withdrawal path).
3. Answer the two verification questions from "Your D14/D15 addendum":
   - D14: was the id twining_why displayed the same id you overrode?
     Then `git log -p` on records/decisions/<that-id>.json — which
     commit restored the provisional bytes, and what operation made it?
   - D15: search the blackboard AND .twining/archive/ for a status post
     "Promoted 1 provisional decision(s) to active" whose detail names
     your id, timestamped between your pre-promote commit and the
     promote call.
4. Re-run the two probe incidents from "One request back".
5. Write the answers + probe results as a response doc
   (docs/twining/2026-08-16-wave2-verification.md), record it with
   twining_record, and commit — it gets carried back to the twining-mcp
   repo.
6. Archive the memo per its STATUS line once 1–2 are done.
```

## 4. What comes back
