# C09 — Independent acceptance oracle

**Case text (source of truth):** "A wrong inferred prerequisite is corrected only for Story A; Story B has a different explicit requirement → A's correction applies; B's requirement survives. The old inference remains available historically with its corrected status."

**Authority for this oracle:** `acceptance-cases.md` (C09 row + coverage map R03, R05, R06, R13, R14), `requirements.md` (R03, R05, R06, R13, R14; plus R07, R08, R12, R16 inherited from the foundation slice), and `01-foundation.md` § *Required proof before broad implementation*. No file in the implementation tree was read while authoring this. Changes to this oracle require a documented source/requirement reason and must preserve the original text alongside the correction.

**Why this case carries foundation-slice machinery.** The C09 row alone would be satisfiable by a single-store, single-writer test. The foundation's required-proof section mandates that the *same* slice show two independently identified writers, two local stores, both orders of delivery, a retry, an interrupted acknowledgement, and reconstruction from durable evidence — and specifically that "a lower-authority inference cannot supersede the ruling **or change another story's requirement**." That sentence is C09. So C09 is the natural home for the slice, and this oracle builds it accordingly. Assertions traceable only to the foundation bullets (staleness, retry, index loss) are tagged so the report can score them separately from C09's own coverage row — see Open Question 8.

## 1. Abstract store model

Implementation-neutral. Any design satisfying these surfaces can be tested.

| Surface | Contract |
| --- | --- |
| `events[]` | Append-only, immutable. Each event: `event_id`, `payload_digest`, producer `(human?, agent?, host, store)`, `evidence_class`, `scope`, `source_anchor(repo, rev, path, byte_hash)`, `observed_at_logical`, `observed_at_wallclock`, `asserts`, `relations[]`, `statement_text`. |
| `current_view(work, at_rev)` | The applicable view: `authoritative_prerequisites`, `prerequisite_sources`, `prerequisite_status`, `inference_candidates[]`, `conflict_state`, `qualification_ready`. |
| `historical_view(event_id)` | Retrieval by exact identity regardless of applicability, returning original bytes/class/author/time/anchor plus per-scope lifecycle annotations. |
| `receipts[]` | Per `(event_id, destination_store)`: `admitted`, `effective`, `materialized`, `producer_receipt ∈ {unacked, acked}`, `attempts`, `duplicate_semantic_effects`, `task_acknowledged`. Plus `injection` records with emitted-bytes hash, host and session. |

**Two distinctions the oracle depends on.**
1. `admitted` (the immutable event is durably stored here) is **not** `effective` (it changed the applicable view). An event may be admitted with every claimed relation refused.
2. Every exchange state — transferred, admitted, materialized, acknowledged, injected — is **not** `task_acknowledged`. Acceptance is a separate event class that this case never produces.

**Delivery vocabulary:** `authored_local → local_durable → queued → transferred → received → admitted → materialized → injected`, with `effective` as an orthogonal boolean and terminal states `rejected_conflict`, `refused_unauthorized_relation`, `quarantined`.

## 4. Required observable outcome — assertions

Every assertion must hold on **all three stores** (`sto-S1`, `sto-S2`, `sto-S1R`) in **both arms** unless stated otherwise.

### 4.1 Event list

- **A1** `admitted_event_ids` == exactly `{ev-RUL1, ev-INF1, ev-VER-A, ev-REQB, ev-OBS1, ev-COR-A, ev-INF2, ev-COR-B1}`; count == 8. No event deleted, purged or rewritten.
- **A2** Stored `payload_digest` for `ev-INF1`, `ev-INF2`, `ev-COR-A` equals the authored digest — byte-for-byte unchanged by any correction, refusal, rebuild or conflicting resend.
- **A3** `ev-INF2` is present in the log on both stores. Refusal operates on its *relations and effect*, never by dropping the event. (If the design quarantines on ingress instead, see Open Question 5 — the event must still be durably retained and retrievable.)

### 4.2 Current applicable view — Story A (the correction applies)

- **A4** `authoritative_prerequisites(wrk-STORY-A, c0a4)` == `["P-BASE"]` exactly, sourced from `ev-RUL1`.
- **A5** `inference_candidates` contains exactly one entry for P-X from `ev-INF1` with `status_in_this_scope: "corrected"`, `corrected_by: "ev-COR-A"`, `applies_now: false`, `authorizes_action: false`.
- **A6** `conflict_state(wrk-STORY-A)` == `"none"`.
- **A7** `prerequisite_status["P-BASE"]` == satisfied by `ev-VER-A` at rev `c0a2`, `current_status: "stale_requires_requalification"`, reason citing `ev-OBS1`; `qualification_ready` == `false` with blocker *"P-BASE satisfaction is stale at c0a4"*. *(foundation bullet: changed source revisions invalidate current-use claims)*

### 4.3 Current applicable view — Story B (the requirement survives)

- **A8** `authoritative_prerequisites(wrk-STORY-B, c0a4)` == `["P-BASE", "P-Y"]` exactly, sourced from `ev-RUL1` and `ev-REQB`.
- **A9** `ev-REQB.lifecycle_status` == `"applicable"`. It is **not** superseded, revoked, retracted, archived or downgraded.
- **A10** `inference_candidates` for Story B contains P-X from `ev-INF1` with `status_in_this_scope: "uncorrected_inference"` and `corrected_by: null` — `ev-COR-A`'s corrected status is scoped to `src/checkout/` and does not attach here. (Default disposition; see Open Question 1.)
- **A11** `inference_candidates` also contains `ev-INF2` with `effective: false` and relation dispositions `supersedes:ev-REQB → refused_insufficient_authority`, `supersedes:ev-INF1 → refused_insufficient_authority`.
- **A12** `conflict_state(wrk-STORY-B)` == `"none"`. A lower-authority contradiction of a human ruling is a **refusal**, not an unresolved conflict; R05 reserves persistent conflict for *equally authoritative* contradictions.
- **A13** `prerequisite_status["P-Y"].verification_anchor_rev` == `"c0a4"` (changed from `c0a3` by `ev-COR-B1`), `required: true`, `satisfied: false`.

### 4.4 Historical view

- **A14** `historical_view(ev-INF1)` is retrievable by exact ID on all three stores and returns the **original** `statement_text`, `evidence_class: "model_inference"`, `author_agent: "agt-ASH-1"`, `observed_at_wallclock: "2026-09-02T10:15:00Z"`, and anchor `catalog.ts@c0a2 / sha256:synthetic-cat-c0a2`.
- **A15** Its lifecycle annotations are **per scope**: `{src/checkout/: corrected by ev-COR-A}` and `{src/billing/: uncorrected_inference}`. This is the literal reading of "remains available historically with its corrected status."
- **A16** `historical_view(ev-VER-A)` still reports rev `c0a2`, hash `sha256:synthetic-cat-c0a2` and its original observation time — the staleness of A7 is a property of the *current* view, not a rewrite of the record.

### 4.5 Receipts and delivery states

- **A17** `receipts[ev-COR-A @ sto-S2]` == `{admitted: true, effective: true, materialized: true, producer_receipt: "acked", attempts: 2, first_admit_attempt: 1, duplicate_admissions: 0, duplicate_semantic_effects: 0}`.
- **A18** `receipts[ev-INF2 @ sto-S1]` == `{admitted: true, effective: false, relation_admission: "refused_unauthorized", producer_receipt: "acked", attempts: 1}`.
- **A19** `tx-INF2-mutated` → `{admitted: false, state: "rejected_conflict", reason: "event_id_reuse_digest_mismatch"}`, visible in operator telemetry, with `sto-S1`'s stored `ev-INF2` digest unchanged.
- **A20** The injection record for `ses-BO-2` carries an `emitted_bytes_hash` linked to `hst-MESA`/`ses-BO-2`; `delivered` is a distinct state from `admitted`.
- **A21** After TR-16, the admitted-event set and the acked-receipt set on `sto-S2` are **identical** to their pre-index-loss values (empty delta). *(foundation bullet: losing the materialized index does not lose acknowledged source events)*

### 4.6 Convergence

- **A22** `canonical_view_hash(wrk-STORY-A)` and `canonical_view_hash(wrk-STORY-B)` are equal across `sto-S1`, `sto-S2`, `sto-S1R` **and** across ARM-X and ARM-Y. Arrival order and the +47m skew change nothing.

## 5. Negative assertions (what must NOT happen)

- **N1 — B's requirement is untouched.** P-X MUST NOT appear in `authoritative_prerequisites(wrk-STORY-B)` at any point, and `ev-REQB` MUST NOT acquire status `superseded`, `revoked`, `retracted`, `archived` or a downgraded evidence class, in either store, in either arm. *(R06, R05)*
- **N2 — The narrow correction does not leak.** `diff(current_view(wrk-STORY-B) @ CHECKPOINT-0, @ end)` MUST contain **only** `ev-COR-B1`'s anchor change c0a3→c0a4. No delta attributable to `ev-COR-A` or `ev-INF2`. *(R06)*
- **N3 — An ack is not acceptance.** After `ev-COR-A` is admitted, materialized and acknowledged, `work_state(wrk-STORY-A)` MUST read `acceptance: not_accepted`, `merge: not_merged`, `qualification: not_qualified`, and the log MUST contain **zero** events of class acceptance. *(R04, foundation bullet)*
- **N4 — No duplicate semantic effect.** The TR-13 retry MUST NOT produce a second admission or a second correction entry: `count(events where event_id == ev-COR-A) == 1` on `sto-S2`, `duplicate_semantic_effects == 0`, and Story A's correction history has exactly one entry. *(R07)*
- **N5 — Caller-controlled fields confer nothing.** `evidence_class(ev-INF2)` MUST remain `model_inference` on both stores despite `active: true`, `promoted_by: "usr-ASH"`, `status: "APPROVED"` and imperative `MUST` prose. `usr-ASH`'s attributed ruling set MUST remain exactly `{ev-RUL1, ev-COR-A}`; no ruling may be attributed to her from `ev-INF2`. *(R03, R17)*
- **N6 — No silent scope widening.** A default (non-explicit) scoped query for `wrk-STORY-A` MUST NOT return `ev-REQB` or `ev-COR-B1`; a default scoped query for `wrk-STORY-B` MUST NOT return `ev-VER-A` or `ev-COR-A`. Cross-scope material is reachable only via the explicit authorized mode of P3. *(R13)*
- **N7 — Stale is not current, and not erased.** A qualification claim citing `catalog.ts@c0a2` MUST NOT be presented as current at c0a4; `current_state` reads `unknown_until_requalified` while the historical satisfaction record keeps its original rev, hash and time. *(R12, foundation bullet)*
- **N8 — Refusal is not fabricated conflict.** The system MUST NOT report Story B as `conflicted` merely because a lower-authority inference contradicts the ruling, and MUST NOT invent a resolution that alters either record. *(R05, R06)*

## 6. Positive controls

Without these, a store that refuses everything, or returns nothing, would pass §5 vacuously.

- **P1 — The correction actually applies.** At CHECKPOINT-0, Story A's P-X candidate reads `uncorrected_inference`. At end state it reads `corrected / corrected_by: ev-COR-A / applies_now: false`, and `authoritative_prerequisites(wrk-STORY-A)` == `["P-BASE"]`. The correction must be *observable as having changed something*.
- **P2 — A legitimate scoped write still lands after the refusals.** `ev-COR-B1` (authenticated human, correctly scoped to `src/billing/`, correctly related to `ev-REQB`) is admitted **and effective** on both stores; Story B's P-Y verification anchor moves c0a3→c0a4 while P-Y remains required. Proves the refusal of `ev-INF2` is authority-based, not blanket rejection of writes into `src/billing/`.
- **P3 — Authorized cross-scope recall works.** `recall(mode=cross_scope_lessons, authorized_by=usr-ASH, scopes=[src/])` returns `ev-INF1` and `ev-COR-A` with `ev-INF1` annotated `corrected` in `src/checkout/` and `uncorrected_inference` in `src/billing/`, both flagged `authorizes_action: false`, with original applicability conditions attached. Proves R14 useful recall coexists with R13 hard scope — the inference is a usable lead that still cannot authorize.

## 8. Pass/fail

C09 passes only if **every** assertion in §4, §5 and §6 holds on all three stores in both arms. Under the go/no-go criteria, failures of N1, N2, N5 or N8 are **authority-changing errors** and are immediate-rejection conditions, not scored defects. Failure of A21 or N4 is a silent-acknowledged-event-loss / duplicate-effect condition and is likewise immediate rejection. N6 failure is a cross-scope disclosure and is immediate rejection. A7/A16/N7 failures are correctness defects. Record attempted actions as well as final answers: an attempt to apply `ev-INF2`'s claimed supersession that is caught downstream still counts as an unauthorized-action attempt.


## Invariants (structured list, from the validation owner's return value)

- A correction's effect is confined to its declared scope, so no record outside repo:rp-COBALT#src/checkout/ changes status because of ev-COR-A, even though its author held authority over the broader src/ scope.
- An event of evidence class model_inference never alters the authoritative prerequisite set of any work item, regardless of caller-controlled fields, imperative prose, claimed supersession relations, or the identity of the human it names.
- Every authored event remains retrievable by exact identity with its original bytes, author, evidence class, observation time and source anchor after any correction, refusal, index loss or rebuild from export.
- The applicable view for a work item is a pure function of the admitted event set and the documented authority rules, independent of arrival order, local sequence numbers and wall-clock skew.
- Retrying an event with identical identity and identical payload digest produces at most one admission and at most one semantic effect at the destination.
- Reusing an event identity with a different payload digest is an explicit, reported conflict rejection that never mutates the stored original bytes.
- Exchange delivery states (transferred, admitted, materialized, acknowledged, injected) never imply or alter task acceptance, merge or qualification state.
- A prerequisite satisfaction bound to a source revision becomes stale for current use when the anchored bytes change, while the historical satisfaction record keeps its original revision, hash and observation time unerased and unrewritten.
- Destroying derived indexes, caches or materialized views never removes an admitted event or an acknowledged receipt from the durable log.
- A default scoped query returns only records authorized for the requested scope, and cross-scope material is reachable only through an explicitly requested, explicitly authorized recall mode that labels every result non-authorizing.
- A lower-authority contradiction of a human ruling is recorded as refused and non-effective rather than promoted to an unresolved conflict state, because R05 reserves persistent conflict for equally authoritative contradictions.
- The corrected status of a record attaches per scope, so ev-INF1 reads corrected within Story A's scope and uncorrected within Story B's scope from the same stored event.
- Both replicas and a third store rebuilt from durable export alone present identical canonical views for every query in the set, in both delivery orders.
- Refusing an unauthorized relation never blocks a correctly scoped and correctly authorized write into the same scope, as demonstrated by ev-COR-B1 landing effectively after ev-INF2 is refused.

## Open questions (structured list, from the validation owner's return value)

- C09 says B's requirement survives but is silent on whether the uncorrected inference P-X should remain a visible lead inside Story B's scope. Oracle default: visible as an inference_candidate labelled uncorrected_inference and authorizes_action:false. An implementation that hides it entirely from B would not violate the case text but would fail A10 as written; this needs a documented rule before the measured run.
- Whether the sibling correction ev-COR-A may be *displayed* in Story B's diagnostics as a cross-scope lead. Oracle default: only under the explicit authorized cross-scope recall mode of P3, and never as a status change on B's view of ev-INF1. Confirm this is the intended reading of R06 plus R13.
- 'The old inference remains available historically with its corrected status' does not say whether corrected status is stored on the inference record or computed per scope at query time. The oracle asserts observable behaviour only, so both storage designs pass; flagging in case the schema deliverable needs to pick one.
- C09 does not name who is authorized to correct an inference. Oracle assumes an authenticated human with ruling authority over the corrected scope. Whether an agent may correct its own inference within the same scope is unspecified; oracle default would be that an agent-authored correction may change the inference's status but never the authoritative prerequisite set. Not exercised by this fixture.
- Whether ev-INF2 should be admitted-but-ineffective (oracle default) or quarantined at ingress. Both satisfy the invariants provided the event is durably retained and retrievable, but the receipt vocabulary must distinguish the two dispositions and the case text does not say which is required. A21's event-set equality after rebuild depends on the answer.
- Whether a refused cross-authority interpretation should surface to the ruling's author as an R03 unresolved_question for human adjudication. The case text is silent; the oracle neither requires nor forbids it, but requires that any such surfacing not constitute an authority change and not alter conflict_state.
- The revision-range and staleness assertions (A7, A16, N7) trace to the foundation's 'changed source revisions invalidate current-use claims' bullet and to R12, not to C09's own coverage row (R03/R05/R06/R13/R14). Confirm they should be scored under C09 rather than under C01 or a dedicated freshness case.
- Likewise the retry, interrupted-acknowledgement, index-loss and rebuild assertions (A17, A19, A21, N4) exercise R07/R08, which C09's coverage row does not list. Confirm whether C09's pass/fail is gated on them or whether they are reported separately as foundation-slice evidence.
- Clock-skew direction and magnitude are unspecified by the case. The oracle fixes +47 minutes on hst-MESA, chosen so that ev-INF2 is later by wall clock and earlier by causal knowledge than ev-COR-A. Any authority rule whose result changes under a different skew value fails invariant 4 and should be reported as such.
- 'Two hosts, two stores' is bound 1:1 in this oracle. Shared-store and multi-host-per-store topologies belong to C13 and are deliberately excluded here; confirm that exclusion rather than assuming C09 covers them.
- The oracle asserts conflict_state == 'none' for Story B on the grounds that inference and human ruling are not equally authoritative. If the programme intends any contradiction to be surfaced as a conflict regardless of authority class, A12 and N8 invert and must be reissued as a documented oracle correction with both versions preserved.
- The injected packet's expected content (Q4 injection record) lists five event ids as a plausible Story B envelope. Budget-driven omission is C26's subject, so the oracle asserts only that an emitted-bytes hash exists and is linked to the receiving host/session, not the exact membership; if C09 should also pin membership, that needs a declared tokenizer and budget.
