# C10 — Independent acceptance oracle

**Case text (verbatim):** *Setup/trigger:* "Repeat, reorder and redeliver an event after a lost remote acknowledgement; deliver a correction before its predecessor." *Required observable outcome:* "Stable event identities, no duplicate semantic effects, explicit pending causal dependencies and reconciled receipts; no new operation silently replacing an uncertain one."

**Requirements in scope (coverage map):** R04, R07, R08, R16. Secondary, because the sequence necessarily touches them: R01 (identity separation), R02 (evidence envelope preservation), R05/R06 (lifecycle and scope).

**Provenance of this oracle:** written from `acceptance-cases.md`, `requirements.md`, and the "Required proof before broad implementation" section of `01-foundation.md` only. No Twining source file, test, or plan document was read. Expected outcomes below are stated as assertions over an abstract store; nothing here presumes a schema, a storage engine, a transport, or a Twining API.

**Change control:** this is oracle v1.0.0. Per the acceptance-cases preamble, any later change requires a documented source/requirement reason, and both the original and corrected outcomes are preserved.

## 1. Abstract store model

The implementation under test must expose six read-only projections. Names are illustrative; an equivalent surface under other names is acceptable, but every projection must be *separately* observable — collapsing any two of them is itself a failure, because R08 requires local persistence, queued transfer, remote receipt, validated admission, materialization and context inclusion to be modelled independently.

| Projection | Contents |
| --- | --- |
| `events` | Durable append-only log of produced or received evidence envelopes, keyed by `event_id`. Includes envelopes received but not yet admitted. |
| `admitted` | The subset of `events` that passed validation **and** has all causal prerequisites satisfied. Only admitted events may feed `current_view`. |
| `current_view` | Map of scoped key → currently applicable record, derived only from `admitted`. |
| `receipts` | One row per `(event_id, from_store, to_store)`: `delivery_state`, `attempts_total`, `admissions`, `duplicate_suppressed`, `conflict_rejected`, `uncertain`, `uncertain_windows`, `pending_on`. |
| `history_view(event_id)` | Full lifecycle chain: original bytes/digest/revision, plus superseded / corrected / quarantined status. |
| `quarantine` | Received-but-refused envelopes with an explicit reason. Never merged into `events`. |

Plus one axis that no delivery mechanism may move:

| `acceptance` | Independent booleans/states for `qualified`, `source_published`, `merged`, `delivered`, `scoped_accepted`. |

**Delivery states:** `local_durable` → `queued` → `sent_unacked` → `received` → (`received_pending_causal`) → `admitted` → `admitted_acked` → `materialized` → `context_included`; terminal side-state `quarantined`.

**Receipt counter identity (checkable arithmetic):** `attempts_total == admissions + duplicate_suppressed + conflict_rejected` for every row.

## 2. Synthetic identities

Two users, two hosts, two stores, one repository with a revision range — all fictional, no customer names, no real repository.

| Kind | Identity | Notes |
| --- | --- | --- |
| Tenant | `tnt-orchard` | One tenant on purpose. Cross-scope disclosure is C25's job, not C10's. |
| Human 1 | `usr-avery` | Home host `host-north`. |
| Human 2 | `usr-blake` | Home host `host-south`. |
| Agent | `agt-south-worker` | Service principal on `host-south`, acting under `sess-south-1`. Distinct identity from `usr-blake` (R01). |
| Host 1 | `host-north` / installation `inst-north-01` | Clock offset 0. |
| Host 2 | `host-south` / installation `inst-south-01` | Clock offset **+90 s**. Deliberate skew. |
| Store 1 | `store-north` | Bound to `host-north`, label `/synthetic/north/.store`. |
| Store 2 | `store-south` | Bound to `host-south`, label `/synthetic/south/.store`. |
| Sessions | `sess-north-1`, `sess-south-1` | |
| Work definition | `wd-pricing-rounding`, scope `svc/pricing/` | |
| Repository | identity `rep-7f3a` | Mutable labels: two different checkout paths, remote `ssh://synthetic.invalid/orchard/ledger.git`, branch `main`. Labels must never serve as identity. |
| Revision range | `c100` → `c101` → `c102` → `c103` | Base `c100`, head `c103`. |
| Scope under test | `svc/pricing/` | Out-of-scope control path: `svc/shipping/`. |

**Events.** `E0 evt-0001-ruling` (seeded, `authenticated_human_ruling` by `usr-avery` @ `c100`, digest `d0`). `E1 evt-1001-obs` (`verified_observation` by `usr-blake` @ `c102`, digest `d1`). `E2 evt-1002-infer` (`model_inference` by `agt-south-worker` @ `c101`, digest `d2`, value `HALF_UP`). `E3 evt-1003-corr` (`model_inference`, **corrects E2**, @ `c103`, digest `d3`, value `HALF_EVEN`, `requires: [evt-1002-infer]`). `E4 evt-2001-obs` (positive control, `verified_observation` by `usr-avery` @ `c103`, digest `d4`).

**Adversarial envelopes.** `E1-CONFLICT` = same `event_id` `evt-1001-obs`, different digest `d1x`. `E1-REMINT` = new id `evt-1001b-obs` carrying digest `d1` — this one must *never exist*; its appearance anywhere is the case's central failure.

E2 and E3 are both model inferences on purpose. If E3 were human-authored, "a correction arrived before its predecessor" would be entangled with "does a human correction outrank the seeded ruling", and the pending-causality assertion would stop being clean. Keeping both at inference class also gives N7 real teeth.

## 3. Exact trigger sequence

| Step | Actor | Action |
| --- | --- | --- |
| T0 | harness | Seed `E0` admitted on both stores with a complete receipt. Set `host-south` clock +90 s. |
| T1 | `usr-blake` @ `host-south` | Record `E1` into `store-south`. No transport yet. |
| T2 | `store-south` outbox | Transfer `E1` to `store-north`. `store-north` validates and **admits** it and emits receipt `rcpt-A`. **The return path drops `rcpt-A`.** |
| T3 | `store-south` outbox | **Retry `E1` byte-identical** (same id, same digest). `store-north` dedups, re-emits a receipt referencing the *same* admission. Receipt arrives. |
| T4 | `agt-south-worker` | Record `E2`, then `E3` (which corrects `E2`) into `store-south`. |
| T5 | transport | **Deliver `E3` to `store-north` before `E2`.** |
| T6 | transport | Deliver `E2`. `E2` admits; `E3`'s prerequisite is satisfied and `E3` admits from the pending set. |
| T7 | harness | **Hard-kill the `store-north` process**; cold-start from durable evidence only. |
| T8 | transport | Consumer cursor rewind: **replay `[E3, E1, E2, E1, E3]`** into `store-north`. |
| T9 | harness (injected frame, **not** `store-south`'s outbox) | Deliver `E1-CONFLICT` (`evt-1001-obs` with digest `d1x`). |
| T10 | `usr-avery` @ `host-north` | **Positive control:** record `E4`, deliver once to `store-south`, then deliver one byte-identical retry. |
| T11 | harness | Probe every acceptance axis on both stores for `wd-pricing-rounding` @ `c103`. |
| T12 | harness | Delete `store-north`'s materialized/derived index; rebuild from the durable event log. |
| T13 | harness | Re-run T1–T12 on fresh stores for each of 4 delivery permutations × 3 clock skews (+90, −90, 0). |

## 4. Assertions

### 4.1 Event list and identity

| ID | Assertion | Req |
| --- | --- | --- |
| A01 | `store-north.events` and `store-south.events` each contain exactly `{E0, E1, E2, E3, E4}`, one entry per `event_id`; `events_total == 5`; `admitted` has the same five at end. | R07 |
| A02 | `events['evt-1001-obs'].payload_digest == sha256:d1` on both stores at **every** observation point, including immediately after T9. | R02, R07 |
| A03 | On both stores, every event carries `repo == rep-7f3a`, and `E1.origin_store == store-south` even when read from `store-north`. Store location never rewrites producer or repository provenance; no path/URL/branch label is used as identity. | R01, R02 |
| A04 | `E1.revision == c102` at end — the later `E3 @ c103` does not restamp it; `E2.revision == c101` survives its own correction. | R02 |
| A05 | `E3` is admitted exactly once across T5, T6 and both T8 replays; `admissions == 1` for every event on every store. | R07 |

### 4.2 Receipts and delivery states

| ID | Assertion | Req |
| --- | --- | --- |
| A06 | `store-north` receipts at end: `E1` → `attempts_total 5, admissions 1, duplicate_suppressed 3, conflict_rejected 1`; `E2` → `2/1/1/0`; `E3` → `3/1/2/0`. Every row satisfies `attempts_total == admissions + duplicate_suppressed + conflict_rejected`. | R07, R16 |
| A07 | `store-south` records **4** outbound attempts for `E1`. The one-attempt gap versus `store-north`'s 5 is accounted for exactly by `conflict_rejected == 1`; no projection credits `store-south` with producing the conflicting bytes. | R01, R07 |
| A08 | Throughout the T2→T3 window, `store-south.receipts[E1].delivery_state == sent_unacked` and `uncertain == true`, and that state is queryable while the window is open. | R08, R16 |
| A09 | After T3, the receipt reconciles to `admitted_acked, uncertain=false`, **and `uncertain_windows` retains the closed interval**. Reconciliation records the uncertainty, it does not erase it. | R08, R16 |
| A10 | `E3`'s receipt records `admission_trigger == prerequisite_satisfied`, not a transport attempt — admission is decoupled from arrival. | R08 |
| A11 | Receipts distinguish `selected`/`emitted`/`delivered`/`unavailable` rather than collapsing them, and expose `attempts_total` and `uncertain` on every row. | R16, R08 |

## 5. Negative assertions (what must NOT happen)

| ID | Must not happen | Req |
| --- | --- | --- |
| **N1** | **No `event_id` other than `evt-1001-obs` ever carries digest `sha256:d1`** — not in either store, not in any outbox, not in any transport log, at any step. Re-minting an ack-uncertain operation under a fresh identity is the case's central prohibition. | C10 clause 4 |
| N2 | Between T5 and T6, `E3` never appears in `admitted` or `current_view`, and `E2` is never synthesized, guessed or back-filled by the consumer to unblock it. | R08 |
| N3 | `E1-CONFLICT` never overwrites, merges into or silently replaces `E1`; `E1`'s digest is `d1` before and after T9. | R07 |
| N4 | Between T2 and T3, no store reports `E1` as `delivered` or `acknowledged`. Optimistic reporting of an unacknowledged send is a failure even though the event was in fact admitted remotely. | R08, R16 |
| N5 | No receipt, admission, dedup or reconciliation moves any acceptance axis. A storage/exchange acknowledgement never becomes qualification, publication, merge or scoped acceptance. | R04 |
| N6 | No event that reached `admitted` is ever absent afterwards — across the T7 restart, the T8 replay, or the T12 index loss. | R07 |
| N7 | `E3` (class `model_inference`) never supersedes, weakens or restates `E0` (the human ruling), and never writes a key outside `svc/pricing/`. | R05, R06 |
| N8 | No projection or report claims exactly-once network delivery. Idempotent application must not be narrated as exactly-once transport. | R08 |

## 6. Positive controls

| ID | Control | Expected |
| --- | --- | --- |
| **P1** | `E4`, a legitimate in-scope write by `usr-avery` on `store-north`, delivered once to `store-south`. | Traverses `local_durable → queued → received → admitted → materialized → context_included`; `admissions == 1`; complete receipt; appears in `current_view` on both stores. Proves the pipeline admits valid traffic and is not passing by refusing everything. |
| P2 | One byte-identical retry of `E4`. | Returns **success** referencing the existing admission: `admissions 1, duplicate_suppressed 1, errors 0`. Dedup must not degrade into refusal — "no duplicate effect" and "reject the retry" are different outcomes and only the first passes. |
| P3 | An event written to `svc/shipping/` by `usr-avery`. | Admitted normally; absent from every `svc/pricing/` view query. Proves scope filtering is a filter, not a blanket block. |

## 7. Pass / fail

**Pass** requires A01–A23, N1–N8 and P1–P3 to hold for all 12 permutation×skew combinations. **Immediate rejection** (per the go/no-go criteria, irrespective of every latency or token measurement) on any failure of N1, N3, N5, N6 or N7 — these are respectively a silent replacement of an uncertain operation, a silent rebinding of evidence, an authority-changing error, a silent loss of an acknowledged event, and a lower-authority supersession.

**Scoring denominators to report:** 12 runs × (23 + 8 + 3) = 408 assertion evaluations; report per-assertion pass counts, not an aggregate percentage, and report any assertion that could not be evaluated because the implementation does not expose the projection it reads.

**Explicitly out of scope for C10**, to keep the case from silently absorbing its neighbours: two-writer incompatible successors and convergence (C11), credential/authority forgery (C12), Git ref rewinds (C14), kill-between-every-durable-step (C18), and identity reuse across renames/rotations beyond the single `E1-CONFLICT` probe (C24). T9 and T12 are included here only because R07 binds conflicting-bytes reuse to the retry path and the foundation proof section explicitly demands the index-loss check; both are flagged in open questions as overlapping other cases.
