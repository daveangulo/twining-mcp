# C23 Oracle — Saturation and derived-service loss

**Case text (authoritative, from `acceptance-cases.md`):** "Saturate queues and indexes under many writers; lose embedding/extraction/reranker service → Observable backpressure and failures; durable exact facts remain recoverable. Degraded retrieval is labeled; no dropped acknowledged events or endless commit/stop enforcement loops."

**Requirements this case must carry (from the coverage map):** R07, R11, R18, R20. Secondary obligations touched by the fixture and asserted here because the case cannot be judged without them: R02 (byte/hash envelope), R03 (evidence class of derived claims), R08 (distinct exchange states), R13 (scope before ranking), R15/R16 (budget, omissions and packet proof).

Authored before any observation of implementation output. Expected outcomes below are derived only from `requirements.md`, `acceptance-cases.md` and `05-verification-and-operations.md`. Any later change to this oracle requires a written source/requirement reason and must preserve the original text alongside the correction.

---

## 1. Abstract memory store under test

The oracle is written against an abstract store, not any particular implementation. A conforming system must expose the following observable surfaces by some means (API, CLI, log, export — the binding is a design choice; the observability is not):

| Surface | Meaning |
| --- | --- |
| `submit(event) -> outcome` | `outcome ∈ {ACK, REFUSED_BACKPRESSURE, UNKNOWN}` with `event_id`, `payload_digest`, `ack_ts`, `durable_at`, and on refusal a retryable code plus the queue depth at refusal. `ACK` is the declared durable acknowledgement boundary (R07). |
| `recall(query, mode)` | `mode ∈ {exact_id, exact_fact, lexical, semantic, graph, cross_scope_lesson}`. Returns `results[]`, `degraded`, `degraded_paths[]`, `ranking_confidence`, `scope_filter_applied`, `index_freshness{state, lag_ms}`. |
| `current_applicable_view(record_id)` | The revision the system will act on now, or an explicit `unknown/stale`. |
| `historical_view(record_id)` | All prior revisions with lifecycle state; never pruned by saturation. |
| `exchange_state(event_id)` | Independent states: `local_persisted`, `queued`, `remote_receipt`, `admitted`, `materialized/indexed`, `injected_into_turn`, `task_acknowledged` (R08). These are separate booleans/timestamps, not one status enum collapsing them. |
| `qualify(action, required_facts) -> decision` | `{qualified, missing[], packet_id, reason}`. |
| `packet(packet_id)` | Persisted emitted bytes + hash, `selected[]`, `emitted[]`, `delivered[]`, `unavailable[]`, `omissions[]`, receiving `host/session/turn` (R16). |
| `observability()` | `queue_depth`, `queue_oldest_age_ms`, `acked_count`, `refused_count`, `reported_unknown_count`, `admitted_count`, `gaps[]`, `retries`, `rejected_records`, `scope_denials`, `index_lag_ms`, `derived_path_health{}` (R20). |
| harness faults | `fail(service)`, `restore(service)`, `kill(process)` (SIGKILL, process restart — not connection close), `inject_index_error(rate)`, `inject_clock_skew(host, ms)`. |

Everything is measured over synthetic identities and synthetic bytes only.

## 2. Declared envelope — fixed before the run

Published in `fixtures_json.declared_envelope`. Key values: queue capacity 256 in-flight; declared sustained admit rate 40 events/s; offered aggregate rate 200 events/s from 8 writers × 250 events = 2,000 submissions against a 1,000-record preloaded corpus; enforcement gate bound 3 attempts / 10,000 ms; index-fresh threshold 30,000 ms; p95 local durable capture target 100 ms; clock skew +2,400 ms / −1,800 ms across hosts.

The run is deliberately driven **above** the declared envelope. The oracle therefore does not require the latency targets to hold under saturation; it requires the breach to be **reported** (A14, A15). A system that silently exceeds its own declared envelope fails; a system that reports it passes.

## 3. Synthetic identities

Tenants `tnt-quillon` (in scope) and `tnt-mirefield` (never in scope). Humans `hum-marek` (publisher), `hum-tova` (reviewer), `hum-esker` (other tenant). Eight agent principals `svc-scribe-a1..c2` across hosts `host-nimbus-01`, `host-nimbus-02` (backend-alpha) and `host-cinder-03` (backend-beta, also the consumer). Stores `store-harbor-main`, `store-harbor-edge`, and `store-drift-main` co-resident on a Quillon writer host. Repositories `repo-atlas-ingest` (query scope), `repo-atlas-web` (same tenant, out of query scope) and `repo-drift-core` (**identical path label `atlas/ingest`**, different tenant). Derived services `svc-embed`, `svc-extract`, `svc-rerank`. Receiving session `sess-cinder-77`, turns `turn-77-01..03`. Revisions: `REC-PREREQ` at `rev-1` then `rev-2`.

Two backends are used deliberately so R11 health/coverage reporting is exercised: each adapter must declare what it captures, injects and cannot observe, and the test must not infer backend-beta capture from backend-alpha configuration.

## 4. Trigger sequence

| Step | Trigger |
| --- | --- |
| **T0** | Preload 1,000 in-scope synthetic records plus the three decoys (`DEC-MIREFIELD-1/2`, `DEC-WEB-1`), including into warm caches, graph-neighbour fixtures and the diagnostic endpoint fixture. |
| **T1** | Healthy baseline. Write `REC-CTRL-BYTES` (UTF-8 BOM + CRLF, 95 bytes) and `REC-PREREQ@rev-1`. Run the baseline recall battery while all three derived services are healthy. |
| **T2** | Record baseline observability snapshot: queue depth ~0, index fresh, all derived paths healthy. |
| **T3** | Start 8 writers at 200 events/s aggregate against a 40 events/s drain and a 256-slot queue. |
| **T4** | While the queue fills, `svc-extract` emits `REC-INFER-SUMMARY` — a model-produced claim that a publisher signed off on skipping the catalog-output review during the window. |
| **T5** | Mid-saturation: `hum-marek` writes `REC-PREREQ@rev-2` superseding `rev-1`; inject 40 identical retries (same event id **and** digest), 3 conflicting reuses (same id, different bytes), 60 out-of-order delivery pairs and 5 corrections delivered before their predecessors; SIGKILL a writer mid-submit, the admitter mid-admit and the indexer mid-index, then restart the processes. |
| **T6–T8** | Stop `svc-embed` (120 s), then `svc-extract` (120 s), then `svc-rerank` (120 s). Run the recall battery and the qualification battery during each. |
| **T9** | All three derived services down simultaneously (180 s). Run the full battery, including exact-ID recall of `REC-CTRL-BYTES`, and attempt `ACT-PUBLISH-CATALOG`, `ACT-PROMOTE-RELEASE`, `ACT-SKIP-GATE`. |
| **T10** | Inject index write failures (EIO on 5% of index writes) for 120 s while load continues. |
| **T11** | Restore all derived services; allow 600 s of catch-up; writers resubmit every event that was refused under backpressure. |
| **T12** | Cold restart of every process; then reconciliation and the final recall/qualification battery. |

Throughout T3–T12, the commit/stop enforcement gate (the "record before commit/session end" gate) is exercised at least 10 times, including while the queue is full and while the derived services are down.

## 5. Assertions

Identifiers are the executable assertion names. `POS` = positive control, `NEG` = negative assertion.

### Positive controls

- **POS-A1 (label is not stuck on).** At T1 and T2, every recall in every mode returns `degraded == false`, `degraded_paths == []`, `index_freshness.state == "fresh"`. If a system labels everything degraded, this fails.
- **POS-A2 (durable exact fact survives total derived outage).** At T9, `recall(exact_id, "REC-CTRL-BYTES")` returns bytes of length **95** with `sha256 == 5b20106bf3e2524ed8ba446f42b0be88f0642a3d5add5ab904549606d29da242`, `encoding == "utf-8-with-bom"`, `newline == "CRLF"`.
- **POS-A3 (a legitimate write during backpressure is durable).** At least one in-scope write that receives `ACK` while `queue_depth >= 0.9 * capacity` is recoverable byte-exact after the T12 cold restart.
- **POS-A4 (explicit cross-scope mode works).** `recall(cross_scope_lesson, scope=["atlas/ingest/","atlas/web/"])` with the explicit authorization returns `REC-LESSON-WEB`. Scope enforcement must be a filter, not a blanket denial.
- **POS-A5 (complete exact packet still qualifies an action).** At T9, `qualify(ACT-PUBLISH-CATALOG, [REC-PREREQ@current])` returns `qualified == true` — the prerequisite is an exact durable record, and derived-service loss must not block actions that never needed derived paths.

### Durability, backpressure and identity

- **A6 (no dropped acknowledged event).** `set(event_ids with outcome ACK)` minus `set(event_ids recoverable by exact id after T12)` is **empty**.
- **A7 (ledger closes).** `submitted == acked + refused_backpressure + reported_unknown`, with `submitted == 2000`. No fourth bucket; no unexplained delta.
- **A8 (uncertainty is reported, not absorbed).** Every `reported_unknown` event id appears in `observability().gaps[]` with a cursor and a reason. `reported_unknown` may be > 0 — an honest "uncertain" is a pass; a silent omission is a fail.
- **A9 (backpressure is observable).** `refused_count > 0`; each refusal carries a retryable outcome code, the queue depth at refusal time, and **no** `ack_ts`; peak `queue_depth >= 230`; `queue_oldest_age_ms` is non-null for every sample across T3–T12.
- **A10 (retries do not duplicate).** The 40 identical retries create **0** additional records and **0** additional semantic effects; each retry returns the original `ack_ts`/`durable_at` or an explicit idempotent-replay marker.
- **A11 (reused id with different bytes is a conflict).** All 3 conflicting reuses are rejected as explicit conflicts; `conflicting_reuse_admitted == 0`; the original payload digests are unchanged.
- **A12 (exchange states stay independent).** For every event, `local_persisted`, `queued`, `remote_receipt`, `admitted`, `materialized`, `injected_into_turn` are separately observable; no event is reported `admitted` without a recorded receipt; no event is reported `injected` without an emitted packet.

### Degradation labeling and retrieval

- **A13 (degradation is labeled).** Every recall issued while any derived service is down has `degraded == true` and `degraded_paths` equal to exactly the set of down services (no more, no fewer).
- **A14 (degraded ranking is not presented as ranked).** During the `svc-embed` and `svc-rerank` outages, semantic/reranked modes return either an empty result with an explicit unavailable reason, or exact/lexical results with `ranking_confidence == "unavailable"`. A silently reordered list presented as ranked is a fail.
- **A15 (index freshness is honest).** During T5–T10, `index_freshness.state == "stale"` with a numeric `lag_ms`; by the end of T11, `state == "fresh"` with `lag_ms <= 30000`. Either p95 local durable capture is ≤ 100 ms, or the over-envelope condition is explicitly reported for the entire interval in which it is exceeded.
- **A16 (stale index cannot mislabel the current view).** `current_applicable_view("REC-PREREQ")` returns `rev-2`, or explicitly `unknown/stale`. Returning `rev-1` labeled *current* at any point after T5 is a fail. After T11 the current view is `rev-2` and the historical view contains both `rev-1` and `rev-2` with `rev-1` marked superseded.

### Authority and action qualification

- **A17 (incomplete packet cannot qualify).** At T9, `qualify(ACT-PROMOTE-RELEASE, ...)` returns `qualified == false`, `missing` naming the unavailable extraction-derived relation set, and the linked packet's `omissions[]` is non-empty.
- **A18 (derived claim is not authority).** `REC-INFER-SUMMARY` keeps `evidence_class == "model_inference"` in storage and in every rendering; `qualify(ACT-SKIP-GATE, ...)` is `false` in every phase; **0** `authenticated_human_authorization` records are created from it; no attempted execution of any instruction contained in it appears in the attempted-action log.
- **A19 (packet proof).** For `turn-77-01..03`, the persisted emitted-packet hash equals the hash of the bytes the receiving turn reports, the packet is linked to `host-cinder-03` / `sess-cinder-77` / the exact turn, and `selected`, `emitted`, `delivered`, `unavailable` are distinguished.
- **A20 (enforcement gate terminates).** Across all ≥ 10 gate invocations: attempts per invocation ≤ 3, wall time ≤ 10,000 ms, exactly **one** terminal gate-decision record per commit attempt, terminal outcome ∈ {`captured_local_pending_remote`, `refused_with_reason`}. A gate that re-fires the same prompt after its bound, or blocks indefinitely on a full queue, fails.

### Negative assertions

- **NEG-1 (no cross-scope disclosure under degradation).** Across **all** modes, caches, graph-neighbour expansion, chunk paths and diagnostic endpoints, in **all** phases: count of returned items whose tenant ≠ `tnt-quillon` or whose repository is outside the query scope == **0**. The `repo-drift-core` decoy shares the path label `atlas/ingest`; a path-label match is not identity (R01, R13).
- **NEG-2 (no acknowledged event lost).** Same set difference as A6 — asserted as an explicit emptiness check on the difference, not on a count.
- **NEG-3 (no unlabeled degraded answer).** The set of recalls issued during T6–T10 carrying `degraded == false` is **empty**.
- **NEG-4 (no byte normalization).** The normalized-variant hash `8ff0e8df6cc3c22a56fc9268c932cfbcda9a1107c7e8bc7252bd4f470f1dbadb` is returned by **no** path, at **no** phase, for `REC-CTRL-BYTES`.
- **NEG-5 (no fabricated human ruling).** No record of class `authenticated_human_authorization` exists whose provenance chain terminates in `svc-extract` or any model-produced text.

## 6. Verdict rule

All of POS-A1..A5, A6..A20 and NEG-1..NEG-5 must pass for C23 to be marked **passed**. NEG-1 and NEG-5 are go/no-go immediate-rejection conditions (cross-scope disclosure, fabricated human ruling); A6/NEG-2 is the silent-acknowledged-loss rejection condition. Unavailable ≠ passed: if a surface required by an assertion does not exist, the assertion is recorded **unavailable** and C23 does not pass. Record attempted actions as well as final answers.

## Invariants (structured list, from the validation owner's return value)

- Every event that received a durable acknowledgement is recoverable byte-exact after saturation, process kills and a cold restart, with the acknowledged-minus-recoverable set difference empty.
- Submitted events partition exactly into acknowledged, explicitly refused under backpressure, and reported-unknown, with no fourth or unaccounted bucket.
- Every reported-unknown event appears in the observable gap list with a cursor and a reason, so uncertainty is exposed rather than absorbed.
- Backpressure is refusal with a retryable code, the queue depth at refusal, and no acknowledgement timestamp, never a silent drop and never an acknowledgement the store cannot honour.
- Queue depth and oldest-queued-item age are observable and non-null for every sample throughout the saturation and outage window.
- Identical retries carrying the same event identity and payload digest produce no additional records and no additional semantic effects.
- A reused event identity carrying different bytes is surfaced as an explicit conflict and never admitted.
- Local persistence, queued transfer, remote receipt, validated admission, materialization and injection into a receiving turn remain independently observable states for every event, including across a partition.
- Loss of the embedding, extraction or reranking service never prevents exact-identity and exact-fact recall of a durable record.
- Original source bytes, encoding, newline convention and hash survive saturation and degradation unchanged, and no normalized-variant hash is ever returned in their place.
- Every recall issued while any derived service is unavailable is labeled degraded and enumerates exactly the unavailable paths.
- Degraded retrieval never presents a ranking as authoritative; it returns an explicit unavailable reason or an explicit unavailable ranking confidence.
- Index freshness is reported as stale with a numeric lag while the index is behind, and as fresh only when the lag is within the declared threshold.
- A stale or lagging index never causes a superseded revision to be returned labeled as the current applicable view; the only alternatives are the correct current revision or an explicit unknown.
- Authorized tenant, repository and scope filters apply before ranking, expansion, caching and diagnostics, so no out-of-scope item is ever returned even when the ranking path has collapsed.
- An identical repository path label under a different tenant is never treated as the same repository identity.
- Cross-scope retrieval exists only as an explicitly authorized query mode and returns its designated record there, never as a silent widening fallback during degradation.
- An action whose required fact is unavailable because a derived path is down is not qualified, and the linked packet lists the omission explicitly.
- An action whose required facts are all present as exact durable records remains qualified during a full derived-service outage.
- A model-produced or extraction-produced claim keeps its inference evidence class in storage and in every rendering, and can never create or satisfy an authenticated human authorization.
- The commit and stop enforcement gate terminates within its declared attempt and wall-clock bounds and writes exactly one terminal decision record per commit attempt.
- The persisted emitted-packet bytes and hash match what the receiving host, session and turn actually received, with selected, emitted, delivered and unavailable distinguished.
- When the run exceeds the declared latency or throughput envelope, the breach is explicitly reported for the whole interval in which it holds rather than silently tolerated.
- Historical revisions and prior evidence survive saturation, index failure and recovery without pruning.

## Instrument-can-fail controls

- IC-1 scope filter off: disable the pre-ranking authorization filter on the dense, lexical, graph, cache and diagnostic paths. NEG-1 (dev) / HNEG-1 (held-out) MUST flip to fail, with the tenant-mirefield / tnt-calder decoys (identical repository path label) appearing in degraded-phase results. If NEG-1 still passes with the filter off, the assertion is not reading the retrieval paths it claims to read and the whole scope result is void.
- IC-2 degradation labeling off: force the degraded flag and degraded_paths to their healthy values while svc-embed / svc-vector is stopped. A13 and NEG-3 (HA13, HNEG-3) MUST flip to fail. POS-A1 / HPOS-A1 must still pass, proving the labeling assertion distinguishes healthy from degraded rather than asserting a constant.
- IC-3 dedup off: disable event-identity plus digest deduplication on admission. A10 (HA10) MUST flip to fail with 40 (55) additional records and a non-zero duplicate semantic-effect count. A11 (HA11) must also be watched: if conflicting-reuse detection is implemented on the same code path, both fail together and the two assertions are not independent — that coupling is itself a finding.
- IC-4 byte preservation off: enable newline normalization and BOM stripping on write. POS-A2 (HPOS-A2) and NEG-4 (HNEG-4) MUST flip to fail, with the exact-ID recall returning the normalized-variant hash 8ff0e8df6cc3c22a56fc9268c932cfbcda9a1107c7e8bc7252bd4f470f1dbadb (dev) / 097c9482dd54f781e0639e421354c0193f508a46ec800c9de1b90a435e4cf555 (held-out) and a byte length of 90 / 83 instead of 95 / 88.
- IC-5 acknowledgement accounting off: make the backpressure refusal path return an acknowledgement without a durable write (or drop the refusal counter). A6, A7, A9 and NEG-2 (HA6, HA7, HA9, HNEG-2) MUST flip to fail, with the acknowledged-minus-recoverable difference non-empty and the ledger not closing. If A6 still passes, the recoverability check is reading the submission log rather than the store and is worthless.
- IC-6 enforcement-bound off: remove the attempt and wall-clock bound on the commit/stop gate while the queue is full. A20 (HA20) MUST flip to fail with attempts exceeding 3 (4) or wall time exceeding 10,000 ms (8,000 ms), or with more than one terminal gate-decision record per commit attempt. The harness must cap the observation itself so a genuinely endless loop is recorded as a failure rather than hanging the run.
- IC-7 trust check off: allow an incomplete packet to satisfy qualification (treat missing derived facts as satisfied). A17 (HA17) MUST flip to fail with ACT-PROMOTE-RELEASE / HACT-CLOSE-DEFECT qualified during the outage. POS-A5 / HPOS-A5 must still pass, proving the qualification assertion is not simply refusing everything.
- IC-8 evidence-class check off: promote extraction-produced records to authenticated human authorization on ingest. A18 and NEG-5 (HA18, HNEG-5) MUST flip to fail, with ACT-SKIP-GATE / HACT-WAIVE-CAPTURE qualified and an authenticated-human-authorization record tracing back to svc-extract / svc-distill.
- IC-9 index-freshness reporting off: pin index_freshness to fresh with lag_ms 0 while the indexer is stopped and index writes are failing. A15 and A16 (HA15, HA16) MUST flip to fail — A16 specifically by returning the superseded revision labeled current once the freshness signal no longer forces an explicit unknown.
- IC-10 gap reporting off: suppress the observability gaps list while leaving the unknown counter intact. A8 (HA8) MUST flip to fail. This separates 'the system knows it is uncertain' from 'the system reports its uncertainty'; if A8 passes with gaps suppressed, it is reading the counter and not the exposure.
- IC-11 packet-persistence off: persist the intended packet rather than the emitted bytes (skip re-hashing after formatting). A19 (HA19) MUST flip to fail whenever the formatter drops or truncates a selected record — run this control together with a deliberately over-budget packet so the formatter actually diverges from the selection.
- IC-12 positive-control nullification (meta-control): remove REC-LESSON-WEB / HREC-LESSON-CONSOLE from the corpus. POS-A4 (HPOS-A4) MUST flip to fail. This proves the cross-scope positive control reads a real record and that IC-1's negative result is not being produced by an empty corpus.

## Open questions (structured list, from the validation owner's return value)

- The case says 'saturate queues and indexes under many writers' without defining 'many' or the saturation threshold; this oracle fixes 8 writers / 256-slot queue / 200 vs 40 events-per-second (dev) and 12 / 192 / 180 vs 25 (held-out), but the real declared queue capacity and drain rate must come from the implementation's published envelope before the run, and a materially different envelope requires re-deriving the peak-depth and ledger numbers.
- The case requires 'durable exact facts remain recoverable' but does not say whether an event refused under backpressure counts as durable; this oracle rules that only an acknowledged event is durable and that a refusal must carry no acknowledgement timestamp — if the implementation defines a different acknowledgement boundary, that boundary must be declared in writing before the run and the ledger assertion re-derived against it.
- 'No endless commit/stop enforcement loops' does not specify the terminal behaviour when local durable capture itself cannot complete; this oracle accepts either capture-local-with-remote-pending or explicit refusal-with-reason, but which of the two is correct policy (fail-open versus fail-closed on the commit gate) is a design decision the requirements do not settle and should be declared before testing.
- 'Degraded retrieval is labeled' does not say at what granularity — per response, per result item, or per retrieval path; this oracle requires per-response labeling plus an enumeration of unavailable paths, which is the weakest form that still satisfies R20, and a per-item requirement would be stricter.
- The case does not state whether a stale index may serve a superseded revision as current if it is labeled stale; this oracle forbids returning a superseded revision labeled current under any labeling, allowing only the correct revision or an explicit unknown — a deliberately stricter reading of R05 and R12 that should be confirmed.
- R18 requires documenting every embedding, extraction, graph, reranking, summarization and telemetry path and confirming local or approved-provider deployment by observing actual traffic; C23 kills three of those services but the case text does not require outbound-traffic observation during the outage, so whether first-use model downloads or provider retries fire during degradation is asserted here only as an additional check and may belong to a separate data-flow test.
- The corpus tiers in the trial design (1,000 / 10,000 / 100,000) are not bound to specific cases; this oracle uses 1,000 for the development set and 10,000 for the held-out set, and the 100,000 tier is left to the scale run — if C23 is meant to be the 100,000-record saturation case, the fixture counts must be re-scaled and the expected latencies re-declared.
- The case does not define what counts as a 'duplicate semantic effect' when the effect is derived (an embedding row, a graph edge, a summary) rather than a record; this oracle counts records and action-relevant effects, and whether duplicated derived artefacts after index catch-up are a violation or benign needs an explicit ruling.
- Whether a partition or derived-service outage may legitimately shrink the injected context below the token budget in a way that changes selection is not addressed by C23; the packet-proof assertion here checks omission reporting, not selection stability, and selection stability under degradation may need its own case.
