# C11 — Independent acceptance oracle

**Case (verbatim):** "Two users on disconnected computers author incompatible successors to the same scoped record → Both histories survive. Replicas converge to the same qualified or explicitly conflicted view under the documented authority rules, independent of arrival order and clock skew."

**Coverage claimed by the programme:** R05 (lossless semantic lifecycle), R08 (distributed exchange state), R09 (transport). This oracle additionally exercises R01 (repository identity vs. mutable labels), R03 (evidence classes / caller-controlled fields), R06 (scoped relations) and R12 (source freshness), because the foundation's "Required proof before broad implementation" folds those into the same slice.

**Derivation statement.** Every expected outcome below was fixed from `acceptance-cases.md`, `requirements.md` and the "Required proof" section of `01-foundation.md` only. No Twining source, test or design document was read. Oracle version 1.0.0, frozen 2026-09-15. Changes require a documented source/requirement reason and must preserve the original alongside the correction.

## 1. Synthetic identities

| Kind | Identity | Notes |
| --- | --- | --- |
| Tenant | `tenant:T_SYN` | single tenant; C11 is a convergence case, not an authorization case |
| Human A | `user:U_ALPHA` | authenticated; declared authority over `repo:R1/src/policy/`, `/src/export/`, `/src/ingest/` |
| Human B | `user:U_BETA` | authenticated; **peer** of U_ALPHA over the same scopes (no seniority — see OQ-2) |
| Agent A | `agent:A1` on `host:H1`, acts for U_ALPHA | service principal |
| Agent B | `agent:A2` on `host:H2`, acts for U_BETA | service principal |

| Host 2 | `host:H2`, install `inst-H2-0002` | clock **−20 min slow** |
| Store 1 | `store:S1` (resident on H1) | local durable |
| Store 2 | `store:S2` (resident on H2) | local durable |

| Revision range | `rev:G0 → rev:G1 → rev:G2` | all records anchor at `G1`; `G2` changes the bytes of `src/policy/retention.ts` only |

Three anchors: `ANC-POL` = `src/policy/retention.ts` (`sha256:a1a1a1a1` at G1, `sha256:c3c3c3c3` at G2), `ANC-ING` = `src/ingest/dedupe.ts` (unchanged), `ANC-EXP` = `src/export/writer.ts` (unchanged).

## 2. Authority rules — declared **before** the run

These must be published by the implementer before measurement; the oracle checks conformance to *these* rules, not to whatever the implementation happens to do.

- **rule_A** — a `human_ruling` by a principal with declared authority over the record's scope may supersede a record in that scope.
- **rule_B** — `model_inference` / `proposal` / `reported_worker_result` / `open_question` may **never** supersede a `human_ruling`, regardless of recency, prose form, or any caller-supplied `active` / `actor` / `promoted_by` / `authority` field.
- **rule_C** — two admitted successors of the same ancestor in the same scope, both authorized under rule_A and neither causally descended from the other, are **equally authoritative** → surfaced as an **explicit conflict**, no automatic winner.
- **rule_D** — arrival order, wall-clock time and prose similarity are never inputs to authority resolution; any deterministic display ordering derives from content identity (`event_id`/digest) plus causal order only.
- **rule_E** — a supersession edge takes effect only inside the superseding record's authorized scope and never alters a neighboring scope.

## 3. Records

| Record | Scope | Class | Author | Relation | Role |
| --- | --- | --- | --- | --- | --- |
| `REC-000` | `src/policy/` | human_ruling | U_ALPHA | ancestor | the prior scoped ruling both sides see |
| `REC-A01` | `src/policy/` | human_ruling | U_ALPHA | supersedes REC-000 | **correction**, authored offline on S1 |
| `REC-B02` | `src/policy/` | human_ruling | U_BETA | supersedes REC-000 | **incompatible successor**, authored offline on S2 |
| `REC-B01` | `src/policy/` | model_inference | agent:A2 | *claims* to supersede REC-000 | **conflicting interpretation** at lower authority; carries `active:true`, `promoted_by:"U_BETA"`, `MUST`-styled prose |
| `REC-N00` | `src/ingest/` | human_ruling | U_BETA | — | **negative control** — neighbouring scope, must stay untouched |
| `REC-E00 → REC-E01` | `src/export/` | human_ruling | U_ALPHA → U_BETA | REC-E01 supersedes REC-E00 | **positive control** — uncontested successor under the same partition/retry/skew conditions |

**Clock-skew trap.** True authoring order is A01 (10:00) → B02 (10:30) → E01 (10:40) → B01 (11:20). Recorded wall clocks, after skew, are B02 10:10 → E01 10:20 → A01 10:45 → **B01 11:00 (latest)**. A last-writer-wins-by-clock resolver therefore promotes the *model inference*; a first-writer-wins-by-clock resolver promotes B02 over A01. Both are failures.

## 4. Trigger sequence

- **T0** seed: EV-0001..EV-0003 admitted + materialized in S1 and S2; repo at `G1`; zero conflicts.
- **T1** partition H1 ⇄ H2; both stores stay locally writable.
- **T2** offline on S1: author `EV-1001` (REC-A01). Local durable, queued, **no peer receipt**.
- **T3** offline on S2: author `EV-2001` (REC-B02), `EV-2002` (REC-E01), `EV-2003` (REC-B01). Local durable, queued.
- **T4** reconnect; exchange in **order O1**: E01 → B02 → A01 → B01.
- **T5** re-deliver `EV-1001` to S2 **twice more**, byte-identical, same event id and digest.
- **T6** S2 admits `EV-1001` but the **acknowledgement is lost**; S1 retries; S2 must re-ack from durable state without re-applying.
- **T7** destroy S2's materialized/derived index; rebuild from retained durable evidence only.
- **T8** repo advances `G1 → G2`; `ANC-POL` bytes change; `ANC-ING`/`ANC-EXP` unchanged.
- **T9** build empty `store:S3` from S1's durable export only (no index copy).
- **T10** **mirror run**: replay T0..T9 into a fresh store pair using **order O2** (A01 first; B01 arrives *before* its causal prerequisite B02; lost ack moved to a different retry) with the host skews **swapped**.

## 5. Required observable outcomes

Assertions are over four projections of an abstract store S: `events(S)`, `current(S, scope)`, `receipts(S, event_id, peer)`, `history(S, record_id)`.

### Convergence and history survival
- **A01** `events(S1)` and `events(S2)` contain the same 7 `(event_id, payload_digest)` pairs; nothing deleted or rewritten.
- **A02** `current(S, "repo:R1/src/policy/")` → status `conflicted`, members exactly `{REC-A01, REC-B02}`, ancestor `REC-000`, parties `{U_ALPHA, U_BETA}` — **in both stores**.
- **A08** O1-final and O2-final are equal on events, current views, history statuses and conflict membership (receipt timestamps, cursors and local display order may differ).
- **A18** `store:S3`, built only from S1's durable export, reproduces the same current views and history statuses.

### Authority rules
- **A04** `REC-B01` is retained in history with status `claim_rejected`, reason `lower_evidence_class_cannot_supersede_human_ruling`, original text preserved; its supersedes edge is stored as a **claim**, never as an admitted edge.
- **A12** During the lost-ack window S1's peer state for `EV-1001` is uncertain/pending; after the retry it reconciles to `admitted` with exactly one admission in S2.
- **A15** After `G1→G2`, every record anchored at `ANC-POL@G1` is marked `requalification_required` for current use while retaining its original G1 anchor, hash and effective time.
- **A17** Both clone paths and both remote URLs resolve to exactly one repository entity `repo:R1`; store location is recorded independently of repository provenance.
- **A19** In O2, `EV-2003` arriving before its causal prerequisite `EV-2001` is held as an **explicit pending dependency** — never applied early, never dropped.

### Negative assertions — what must NOT happen
- **A03** `current(…/src/policy/)` never returns exactly one of `{REC-A01, REC-B02}` as a resolved winner.
- **A05** `REC-B01` never appears in any `current()` result for any scope, and its `active` / `actor` / `promoted_by` / `authority` fields never change its evidence class from `model_inference`.
- **A06** `current(…/src/ingest/)` equals `[REC-N00]`, unchanged, zero incoming supersession edges, no conflict flag — the narrow policy-scope fight must not leak into a neighbouring scope (rule_E / R06).
- **A09** Swapping host clock skews changes no outcome; `EV-2003` (latest clock) never wins on recency and `EV-2001` (earliest clock) never loses on age.
- **A11** No retry mints a new event identity, and no new operation silently replaces the uncertain one during the lost-ack window.
- **A13** Scoped task acceptance for `repo:R1/src/policy/` stays `not_accepted` even when every delivery state reaches `admitted+materialized` — an exchange acknowledgement is not acceptance.
- **A16** The `G1→G2` source change neither deletes any record nor resolves the policy-scope conflict, and nothing is auto-rebound to `G2` without a live re-observation.

### Idempotence and durability
- **A10** After the two identical retries, S2 holds exactly **one** admission of `EV-1001` and the conflict set still has exactly 2 members.
- **A14** After destroying and rebuilding S2's index from durable evidence, A01–A07 still hold and **zero** acknowledged events are lost.

### Positive control
- **A07** `current(S, "repo:R1/src/export/")` equals `[REC-E01]`, **non-conflicted**, with `REC-E00` historical and `superseded_by: REC-E01`. This record travelled through the same partition, the same reorder, the same skew and the same retries as the conflicting pair. It proves the system still *resolves* when the rules say it should, so "everything is conflicted" and "everything is refused" are not passing answers.

A second, weaker positive control is embedded in A04: `EV-2003` is **admitted as an event** (it appears in `events(S)` on both replicas) while its **supersession claim is rejected** — admission of an event must not be conflated with acceptance of the claim it carries.

## 6. Pass / fail

Pass requires all 19 assertions on both O1 and O2. Per the go/no-go criteria, any single failure of A03, A05, A06, A09, A11 or A13 is an **authority-changing error or silent loss** and is an immediate rejection, not a scored deficiency — no latency or token saving offsets it. A14/A18 failures are silent-loss rejections. Anything else is a correctness failure.

**Scope limit to state in the report:** this is a two-store, two-host slice. Per `01-foundation.md`, passing C11 does **not** constitute the multi-computer qualification required by C28, and the report must say so rather than counting C11 toward it.


## Invariants (structured list, from the validation owner's return value)

- INV-01 Every event durably captured on either side of the partition appears exactly once, by stable (event_id, payload_digest), in every converged replica and in any store rebuilt from durable evidence.
- INV-02 No admitted record is ever deleted, rewritten or re-authored; supersession, rejection and conflict are expressed as additional state over a preserved original.
- INV-03 Two authorized, causally concurrent successors of the same ancestor in the same scope resolve to an explicit conflicted view naming both members, their common ancestor and both parties, never to a single winner.
- INV-04 A record of lower evidence class than the record it targets can never take effect as a supersession, and its claim is retained as an unadmitted claim with its original text.
- INV-05 No caller-supplied field (active, actor, promoted_by, authority) and no prose form (MUST, headings, finality language) may raise a record's evidence class or place it in a current view.
- INV-06 Arrival order, recorded wall-clock time and prose similarity are never inputs to authority resolution; only declared principal authority, scope and causal order are.
- INV-07 The converged current view, history statuses and conflict membership are identical across delivery orders and across swapped host clock skews.
- INV-08 A supersession takes effect only inside the superseding record's authorized scope; a neighbouring scope's current view is bit-for-bit unchanged by a conflict elsewhere.
- INV-09 Byte-identical retries of the same event identity produce exactly one admission and exactly one semantic effect, and produce no new conflict instance.
- INV-10 A retry after a lost acknowledgement never mints a new event identity and never substitutes a new operation for the uncertain one.
- INV-11 Local durability, queued transfer, remote receipt, validated admission, materialization, injection and task acceptance are independently observable states, and an unacknowledged delivery is reported as uncertain rather than as admitted.
- INV-12 No exchange-layer state transition (admission, materialization, injection, acknowledgement) may set or imply scoped task acceptance or qualification.
- INV-13 Admitting an event is not accepting the claim it carries; a rejected claim still leaves its carrier event durably present in the event list.
- INV-14 Destroying the materialized index loses no acknowledged event, and rebuilding from durable evidence reproduces the same current and historical views.
- INV-15 A causal prerequisite that has not yet arrived holds its dependant as an explicitly pending dependency; the dependant is neither applied early nor dropped.
- INV-16 A source revision change marks records anchored to the superseded revision as requiring requalification for current use while leaving their original anchor, hash and effective time intact.
- INV-17 A source revision change never deletes a record, never rebinds an anchor without a live re-observation, and never resolves an authority conflict.
- INV-18 One repository is one identity across differing clone paths and remote URLs, and memory-store location is recorded independently of repository provenance.

## Open questions (structured list, from the validation owner's return value)

- OQ-1 The case says 'under the documented authority rules' but never states them; this oracle therefore fixes an explicit rule table (rule_A..rule_E) that the implementer must publish and agree BEFORE the measured run. If the implementation's real rules differ, the oracle's expected outcomes for the policy scope change and must be re-frozen with a documented source/requirement reason.
- OQ-2 Are two authenticated humans holding the same declared scope authority 'equally authoritative'? The fixture assumes peers with no seniority, which forces the conflicted outcome for {REC-A01, REC-B02}. If the design documents a role hierarchy (tenant admin > contributor) or a scope-ownership rule, that branch becomes a qualified single-current outcome instead and assertion A02/A03 must be restated before the run.
- OQ-3 'Converge to the same view' is not defined as byte equality or semantic equality. The oracle uses semantic equality over (record ids, statuses, conflict membership) and explicitly excludes receipt timestamps, cursors and local display order. If byte-identical serialization is intended, the deterministic serialization order must be declared and must still not derive from arrival or wall clock.
- OQ-4 The case requires an 'explicitly conflicted view' but does not say what a conflicted scope may serve. The oracle asserts only that it cannot qualify an action (qualifies_action=false); whether reads are refused, served with a conflict marker, or served with both members is an undeclared policy that must be fixed before the run and may interact with C19.
- OQ-5 'Incompatible' is undefined. The oracle triggers conflict structurally (two authorized successors of one ancestor in one scope, neither causally descended from the other) because R05 forbids prose similarity as an authority input. Whether the system should ALSO flag structurally forking but semantically compatible successors, or should merge them, is unspecified.
- OQ-6 No maximum clock skew is stated. The fixture uses +45/-20 minutes and asserts skew-independence; if the design relies on a bounded-skew assumption (for example hybrid logical clocks with a ceiling), that bound must be declared in advance and the fixture re-parameterized to exceed it as a separate negative probe.
- OQ-7 The case does not say whether a lower-authority conflicting interpretation should be rejected at admission (quarantined, absent from events()) or admitted-and-marked. The oracle requires only that it be retained and visible with its original text and rejected claim, and asserts it is admitted as an event; if the design quarantines instead, A04 and the delivery-state table for EV-2003 need restating while INV-04/INV-05 stand unchanged.
- OQ-8 The oracle assumes 'scoped task acceptance' is a distinct queryable state per scope (needed for R04's ack-is-not-acceptance separation and the foundation's 'exchange acknowledgements do not become task acceptance'). If acceptance is not modelled per scope, an equivalent observable must be nominated before the run or A13 cannot be evaluated.
- OQ-9 The case does not state whether requalification after a source revision change applies to every record anchored at the old revision or only to those carrying a current-use claim. The oracle takes the narrower reading (current-use claims only) and preserves all historical anchors; the broader reading would change the expected freshness labels but none of the invariants.
- OQ-10 Two stores on two hosts is what C11 asks for, but 01-foundation.md warns not to call a two-process demonstration a multi-computer qualification. Whether C11 must run on genuinely separate machines or may run as two isolated processes is unresolved; the oracle is transport- and topology-neutral, but the report must state the actual topology and must not count C11 toward C28.
