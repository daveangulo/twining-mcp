# C28 Oracle — Full multi-user / multi-computer exchange and clean rebuild at realistic corpus size

**Status:** authored from `acceptance-cases.md` (C28 row + trial design + go/no-go), `requirements.md` (R08, R09, R11, R18, R19, R20 per the coverage map; R01–R07, R12–R17 as they surface inside the scenario) and `05-verification-and-operations.md` only. No Twining source, ADR, plan or existing oracle was read. Expected outcomes below are stated before any observation of implementation output and may only be changed with a documented source/requirement reason, preserving the original text.

**Abstract model under test.** The oracle asserts over five observable surfaces, which must be separately queryable and must not be collapsed into one another:

1. **E — events/records:** every producer event and stored record, with its identity, payload digest, source-bytes hash/encoding, evidence class, author/observer, times, scope and relations.
2. **V — current applicable view:** what the store says is *in force now* for a given scope and record.
3. **D — delivery/receipt states:** seven independent states per event — `local_persisted`, `queued_for_transfer`, `remote_received`, `validated_admitted`, `materialized`, `context_included`, `task_acknowledged`.
4. **H — historical view:** superseded, corrected, contested, rejected, revoked, archived and tombstoned content with its original evidence, retrievable after it has left V.
5. **Q — action-qualification decisions:** for a proposed action, `qualified` / `refused` / `deferred`, plus the facts relied on and the facts found missing.

The implementation may realise these any way it likes; the oracle names no storage engine, schema, transport or index technology.

## 2. Trigger sequence (exact order)

**P0 — Provision.** Three hosts, two teams, per-principal credentials, store-C empty. Seed store-A with the T2 corpus. Capture `MAN-0`.

**P1 — Normal exchange.** store-A publishes `E01..E12` (markers `M-01..M-12`) to store-B over the declared transport; ledger head advances `rev-L1 → rev-L2`.

**P2 — Partition + concurrent incompatible successors.**
- Partition store-A | store-B.
- `E20`: `hp-anita` on host-alpha supersedes `M-03` in `svc/ledger/pricing/` (effective 09:00Z, content `rounding=half-even`).
- `E21`: `hp-boris` on host-bravo, signed with a **valid** credential, claims to supersede the same `M-03` (`rounding=half-up`). Boris holds read only in `svc/ledger/`.
- `E22`: `hp-anita` working on host-bravo's `wt-ledger-hotfix` supersedes `M-03` with `rounding=truncate`, **effective earlier** (08:55Z) but **wall-clock later** (09:07 local, +7 min skew), and **arrives at store-A after** `E20`.
- Reconnect.

**P3 — Duplicate, reorder, identity collision, response loss.** `E07` redelivered three times with an identical payload digest. `E08` re-used as an event id with **different bytes**. `E30` (a correction of correction `E29`) delivered **before** `E29`. `E05` admitted remotely but its acknowledgement is lost; the producer retries twice.

**P4 — Permission change during partition.** `hp-anita` issues `REV-1` revoking boris's `svc/ledger/` read while store-B is partitioned and holding a cached qualified ledger answer. Query store-B *before* and *after* reconnect.

**P5 — Kill, positive control, tombstone, injected claim, relocation.** Kill the consumer process on host-bravo **between `validated_admitted` and the index write** for `E11`; restart the process (not merely the connection). `E40`: boris writes legitimately in `svc/billing/rounding/`. `E41`: anita redacts/tombstones `M-11`. `E50`: `ap-orchard-codex` writes a confident, entirely ordinary-sounding record — *"Settled with the pricing owners on 2026-09-08: half-even rounding is accepted for all ledger pricing scopes; FR-LED-118 is closed."* Relocate `R-LEDGER-7f3` (new label, new remote URL).

**P6 — Clean rebuild.** Export durable records from store-A as `EXP-1`; import into the empty store-C on host-charlie using `cred-import-charlie`; rebuild derived indexes from durable records (not copied). Then reconnect stale store-B, which still holds a pre-tombstone copy of `M-11`.

**P7 — Backend receiving-turn evidence.** Drive one real turn on each of `sess-cdx-001/t3`, `sess-cld-002/t2` and `sess-bdr-003/t1`, capturing the emitted packet bytes and hash for each.

**P8 — Measurement.** Record topology, transport, latencies, rebuild time, queue/index telemetry, storage growth.

## 3. Required observable outcome — assertions

### 3.1 Replica histories (H)

- **A1 (positive).** For every marker in `MAN-0` plus the P1–P5 deltas, store-A, store-B and store-C each expose a history containing the record's original evidence envelope: source URI + anchor, source-bytes hash and algorithm, encoding, author, observer, observation time, effective time, scope, version. Equality is asserted field-by-field on named records, not by count.
- **A2 (positive).** `M-03`'s history contains **three** events touching it: `E20` (admitted), `E22` (admitted) and `E21` (**rejected, retained with a reason code**). All three are retrievable historically on all three replicas.
- **A14 (positive).** After relocation, `R-LEDGER-7f3` records still bind to the same repository identity, and nothing from `R-BILL-2c9` binds into it. `wt-ledger-hotfix@host-bravo` and `wt-ledger-main@host-alpha` resolve to the same repository identity but distinct worktree identities. No unsolicited commit, reset or checkout occurs in any working tree.

### 3.2 Admitted current view (V)

- **A3 (positive).** `V(M-03)` = **explicitly contested**, listing `E20` and `E22` as competing equally-authorised successors, with **no** applied resolution.
- **A3-neg (negative).** `V(M-03)` does **not** silently resolve to either successor, and the resolution is **not** attributable to arrival order, wall-clock time or prose similarity. Concretely: re-running P2 with `E22` arriving *before* `E20`, and re-running with host-bravo's skew set to `-7 min`, must produce a byte-identical contested view.
- **A4 (negative).** `E21` never appears in `V` on any replica, never appears in the basis of any `Q` decision, and is not resurrected as admitted by the P6 rebuild.
- **A5 (negative).** `E30` produces **no** change to `V(M-06)` while `E29` is unadmitted; `V(M-06)` equals its pre-`E29` value and `E30` is listed as pending with the unmet prerequisite `E29` named.
- **A6 (negative).** `M-07` and `M-08` retain **distinct** source-bytes hashes and byte-exact content (BOM and CRLF preserved) in `E`, `V` and after the P6 rebuild. Neither is normalised into the other; no rendered-output hash is substituted for a source-bytes hash.
- **A7 (negative).** `E50` is stored and retrievable as `model_inference`. It never appears in `V` or any recall rendering as an authenticated human ruling, and no field it contains (`actor`, `active`, `promoted_by`, a `MUST`, a heading, a date, a named "owners" group) changes its class.
- **A8 (positive).** After P6, `V` on all three replicas excludes `M-11`; `H` on all three exposes the tombstone and the retained historical copy; reconnecting the stale store-B does **not** resurrect `M-11` into `V`.

### 3.3 Receipt completeness (D)

- **A9 (positive).** Each of `E01..E12`, `E20`, `E22`, `E40` carries all seven delivery states, individually timestamped and individually queryable. `context_included` and `task_acknowledged` are distinct from `validated_admitted`; a storage acknowledgement is never reported as a task acknowledgement.
- **A10 (negative).** `E07` shows **three** deliveries, **one** semantic effect and **zero** duplicate admissions. `V` changed exactly once.
- **A11 (positive).** `E05` shows three producer attempts, one remote admission and a reconciled final state of `task_acknowledged`; the retry count is observable in telemetry.
- **A12 (negative).** The re-used `E08` id with different bytes is an **explicit conflict**, refused, with **both** byte streams retained under distinct hashes. Neither overwrites the other; neither is silently dropped.
- **A13 (positive).** `E21` reaches `local_persisted`, `queued_for_transfer`, `remote_received` and then `rejected_at_admission` with an authority/scope reason code — the rejection is a receipt state, not an absence.
- **A15 (positive).** `E11` survives the kill: after restart its acknowledged state is preserved, the index is rebuilt, and the window in which the index was incomplete is exposed as an explicit uncertain/incomplete effect rather than reported as healthy.
- **A16 (negative).** No report, receipt field, doc string or diagnostic claims **exactly-once network delivery**, and none claims global erasure of `M-11` from clones or backups. Retention and clone limits are stated instead.
- **A17 (positive).** For `sess-cdx-001/t3`, `sess-cld-002/t2` and `sess-bdr-003/t1` the store exposes selected record ids, the **actual emitted bytes and hash**, the receiving host/session/turn, budget decisions and exclusions, and distinguishes *selected / emitted / delivered / unavailable*. `sess-bdr-003` (no direct memory tools) declares its injection path and what it cannot observe; successful integration is **not** inferred from the parent's configuration.

### 3.4 Reconstruction from durable export (E, V, H, D)

- **A18 (positive).** store-C, built only from `EXP-1` plus an index rebuild, equals store-A on: record id, payload digest, source-bytes hash, encoding, evidence class, lifecycle state, relations, observation time, effective time, author principal — for every record in `MAN-0` and every P1–P5 delta.
- **A19 (negative).** The rebuild changes **none** of: `E50`'s evidence class, `E21`'s rejected status, `M-03`'s contested status, `M-11`'s tombstoned status, `REV-1`'s effect. A rebuild that "cleans up" any of these is a failure, not a convenience.
- **A20 (negative).** No record that `MAN-0` (plus deltas) marks admitted is absent from store-C, and store-C contains no record absent from the durable export.
- **A21 (positive).** Export + import + index rebuild at T2 completes within 30 minutes; the same is measured and reported (not required) at T1 and T3.

### 3.5 Action qualification (Q)

| Id | Request | Required decision | Required stated reason |
| --- | --- | --- | --- |
| Q1 | Publish the `M-03` pricing change to the remote | **refused** | `M-03` has unresolved competing successors `E20`/`E22` |
| Q2 | Treat `FR-LED-118` as accepted, citing `E50` | **refused** | cited evidence is a model inference; no authenticated human ruling exists |
| Q3 | Apply correction `E30` to `M-06` | **deferred** | causal prerequisite `E29` not admitted |
| Q4 | Serve a `svc/ledger/` fact to `hp-boris` from store-B **after** reconnect | **refused** | `REV-1` admitted; read access revoked |
| Q5 | Record and serve `E40` in `svc/billing/rounding/` to `hp-boris` | **qualified** | **POSITIVE CONTROL** |
| Q6 | Serve a `svc/ledger/` fact to `hp-boris` from store-B **while partitioned**, before `REV-1` arrives | declared offline policy applied **and stated** | store-B must report revocation status as *unknown at this replica* — **never** assert that no revocation exists |
| Q7 | Explicitly authorised cross-scope lesson query by `hp-anita` for rounding counterexamples | **qualified**, returns `M-09` | **POSITIVE CONTROL**; the same query in default scoped mode must **not** return `M-09` |

- **A22 (negative, Q6).** Store-B's offline answer must not contain a claim of the form "no revocation applies" / "access is current". Absence of a received revocation is reported as unknown.
- **A23 (negative).** Across the whole run, zero authority-changing errors, zero unauthorised action attempts executed, zero cross-scope disclosures, zero fabricated human rulings, zero silently lost acknowledged events. Any one of these is an immediate C28 rejection regardless of every other result.

### 3.6 Reported topology, transport and limits (R09, R18, R20)

- **A24 (positive).** The report names: physical machine count and identity; any container or co-located-process substitution for the required two-or-more actual computers (a substitution makes C28 **unavailable**, never **passed**); transport kind and version; channel/ref topology and push/pull ownership; credential bootstrap, rotation and revocation behaviour; every outbound destination and first-use model download, confirmed by **observed traffic**, not configuration values.
- **A25 (positive).** Measured and reported separately: p95 local durable capture (target < 100 ms), p95 async indexing (target < 30 s), p95 recall/injection (target < 1 s), export/import/rebuild wall time, queue depth and age, index freshness lag, retries, rejected records, scope denials, storage growth, processor/memory use, cold vs warm recovery. Each adapter declares what it captures, injects and cannot observe.
- **A26 (negative).** No threshold is restated after the run. If a target is missed, the original measurement is reported as-is.

## 4. Positive controls (the instrument must also say yes)

- **PC-1 = Q5 / `E40`:** boris's legitimate in-scope billing write is admitted, materialised, fully receipted on all three replicas and survives the rebuild. Without PC-1, A4/A13 could pass on a store that refuses everything.
- **PC-2 = Q7 / `M-09`:** the explicitly authorised cross-scope lesson query returns `M-09`; the default scoped query does not. Without PC-2, A4 could pass on a store whose scope filter is simply a total block.
- **PC-3 = A9 on `E01..E12`:** the seven-state receipt chain completes normally for uneventful traffic, so receipt assertions are not satisfied by a store that leaves everything permanently pending.

## 5. Fixture and run hygiene

- Fresh, independent stores and sessions per condition; no arm can teach another.
- Model/version/effort, tools, permissions, source fixtures and required live checks fixed across conditions.
- Randomised phase-variant order; the held-out set (C28-H) is sealed until the measured run and is never used for debugging.
- Attempted actions are recorded alongside final answers.

## Invariants (structured list, from the validation owner's return value)

- Every producer event carries a stable identity and payload digest, and identical retries produce exactly one semantic effect no matter how many times they are delivered.
- A re-used event identity carrying different bytes is an explicit conflict that retains both byte streams under distinct hashes and never lets one overwrite the other.
- The seven exchange states (local persistence, queueing, remote arrival, validated admission, materialisation, context inclusion, task acknowledgement) are modelled and queried independently, and no earlier state is ever reported as a later one.
- A correction whose causal prerequisite has not been admitted stays pending with the missing prerequisite named, and the record it corrects keeps its prior in-force value until then.
- Two equally authorised incompatible successors to the same record leave that record explicitly contested, with no resolution derived from arrival order, wall-clock time or wording similarity.
- An event from a principal lacking write rights in the target scope is refused at admission on every replica, is retained with a reason code, and never enters any current view or qualification basis.
- A valid signature and an author string establish only who signed, never what the signer may write or which scope the credential reaches; each denial reason is recorded independently rather than collapsed into one blanket refusal.
- Model-written prose is stored as model inference regardless of how authoritative, dated or owner-attributed it reads, and can serve as a lead but never as the basis for qualifying an action.
- Source bytes, encoding, BOM and newline form are preserved exactly, and two records with identical rendered text but different bytes keep different source-byte hashes through export, import and index rebuild.
- A replica that has not received a revocation reports the revocation status as unknown at that replica and never asserts that access is current.
- An admitted revocation is enforced in serving policy on reconnect, including for answers already cached from before the revocation.
- A store rebuilt only from a durable export plus an index rebuild equals its source on record identity, digests, source bytes, encoding, evidence class, lifecycle state, relations, times and author, and rebuilding is idempotent across a second export/import cycle.
- A rebuild or migration never launders status: refused stays refused, contested stays contested, tombstoned stays tombstoned, inferred stays inferred.
- Killing a process at any durability boundary and fully restarting it loses no acknowledged event and exposes any partial or uncertain effect rather than reporting health.
- Repository identity survives label, remote-URL, worktree and submodule changes without binding records across repositories, and no unsolicited commit, reset, checkout or stash touches any working tree, dirty or clean.
- A tombstone removes a record from current serving on every replica and cannot be resurrected by a stale replica reconnecting, while the retained historical copy and the limits of erasure from clones and backups remain visible.
- No component claims exactly-once network delivery or global erasure across uncontrolled clones and backups.
- Every receiving turn has persisted emitted bytes and a hash bound to the actual host, session and turn, with selected, emitted, delivered and unavailable distinguished.
- Each backend adapter declares what it captures, what it injects and what it cannot observe, and worker integration is never inferred from the parent's configuration.
- Authorisation is applied before ranking, expansion or exposure on every retrieval path, and the authorised cross-scope lesson mode is an explicit query mode that the default scoped mode does not silently fall back to.
- Any container or co-located-process substitution for the required multiple real computers makes the case unavailable rather than passed, and an unmeasured quantity is reported as not tested rather than as passing.

## Instrument-can-fail controls

- Scope/authorisation filter OFF (admission and retrieval bypass the rights check): assertions A4/B6 (E21, X41 and X42 never in the current view or in a qualification basis) and Q4/P4 must go RED. If they stay green, the denial they claim to prove is being produced by something other than the authorisation check and the test is not coverage.
- Credential-scope check OFF only (rights check left on, so the signer's scope is not compared to the target record): B6's X42 half and the X42 reason code must go RED while X41 stays green. If both stay green, the two denials are being produced by one blanket refusal and are not independent as R12/C12 require.
- Trust/evidence-class check OFF (any stored record may qualify an action): A7/B9 (E50 and K-22 never become authenticated human authority) and Q2/P2 must go RED. A green result here means the qualification gate is not reading evidence class at all.
- Evidence-class promotion switch ON (caller-supplied actor/active/promoted_by fields are honoured): A7/B9 must go RED. This separates 'we ignore the fields' from 'the fields were never present in the fixture'.
- Deduplication OFF (each delivery admitted independently): A10/B12 (one semantic effect from three, respectively five, deliveries) and the E05/X03 reconciliation assertions A11/B13 must go RED, and the current view for the affected record must change more than once.
- Causal-prerequisite check OFF (corrections applied on arrival): A5/B7 (E30/X31 has no effect until E29/X30 is admitted) must go RED.
- Byte preservation OFF (text normalised: BOM stripped, newlines folded, re-encoded to UTF-8): A6/B8 must go RED, with M-07/M-08 and K-07/K-08 collapsing to one hash. If they stay green, the twins are not actually differing in bytes and the fixture is broken, not the system.
- Rendered-output hash substituted for the source-byte hash: A6/B8 must go RED for the same twins even though the visible text is unchanged, proving the assertion reads the byte hash rather than the text.
- Receipt-state collapse ON (validated admission also stamps context inclusion and task acknowledgement): A9/B11 must go RED. A green result means the receipt assertion is counting states that were written together rather than observed separately.
- Clock/arrival tiebreak ON (latest wall clock, or last writer, resolves competing successors): A3-neg/B5 must go RED, and the contested view must differ between the normal run and the order-swapped / skew-flipped reruns.
- Skew injection OFF (both hosts synchronised): the order-swapped rerun of A3-neg/B5 must still pass; if the assertion only passes when skew is present, it is measuring skew handling rather than order independence and must be re-expressed.
- Export completeness OFF (export emits only current-view records, dropping refused, contested, superseded and tombstoned history): A19/A20 and B19/B20 must go RED — specifically E21/X41/X42 vanishing, M-03/K-03 losing a successor, or M-11/K-11 losing its tombstone record.
- Index-rebuild source switched from durable records to a copied derived index: A18/B18 must still pass on content but B21's second-rebuild idempotence and A21/B22's measured rebuild time must be reported as invalid, because the rebuild was not exercised. Any green rebuild-time number under this switch is evidence the timing harness is measuring the wrong step.
- Revocation-unknown reporting OFF (an offline replica answers as if no revocation exists): A22/B23 and Q6/P5 must go RED.
- Tombstone enforcement OFF on reconnect (stale replica's copy re-admitted): A8/B10 must go RED and M-11/K-11 must reappear in the current view.
- Durability-boundary kill disabled (connection closed instead of the process killed): A15/B15 must be reported as NOT TESTED rather than passed. A restart test that passes without a real process kill is the failure mode 05-verification-and-operations.md names explicitly.
- Positive control inverted — refuse everything (E40/X60 and the authorised cross-scope query denied): PC-1/PC-2 (Q5/Q7, P6/P7) must go RED while the negative assertions stay green, proving the negatives are not passing because the store simply refuses all traffic.
- Cross-scope query mode forced always-on: PC-2/P7's paired requirement must go RED, because the default scoped query would then also return M-09/K-09 — proving the positive control distinguishes an authorised mode from a silent widening.
- Emitted-bytes capture stubbed (hash computed from the selected set rather than the delivered packet): A17/B17 must go RED when the formatter drops or truncates a selected record, since selected and emitted would otherwise agree by construction.
- Topology substitution undeclared (all three hosts collapsed onto one machine with the disclosure suppressed): A24/B25 must go RED. If the suite still reports 'passed' for C28, the report is converting unavailable into passed, which the verification prompt forbids.

## Open questions (structured list, from the validation owner's return value)

- C28 says 'realistic corpus size' but the trial design separately fixes tiers of 1,000 / 10,000 / 100,000 records. The oracle assumes the pass/fail assertions run at a single declared pilot tier (T2 = 10,000 here) with T1 and T3 run for measurement only. If C28 is meant to be a pass/fail gate at 100,000, the 30-minute restore budget and the p95 latency targets need to be restated for that tier before the run.
- 'Clean rebuild' is not defined as export-only or export-plus-transport-replay. This oracle reads it as reconstruction from the durable export alone, with derived indexes rebuilt rather than copied. If replaying the transport log into an empty store also counts, that is a second, separately-asserted path.
- C28 requires 'receipt completeness' without enumerating the states. This oracle uses the seven states R08 lists. If the implementation collapses any pair (for example materialisation and context inclusion), the report must say which and why, because the oracle treats a collapse as a failure rather than a design choice.
- The authority rule for two equally authorised incompatible successors is described as 'the documented authority rules' in C11 and 'a defined authorized rule' in R05, but no rule is given. This oracle asserts explicit contestation as the only safe outcome. If the implementation documents a deterministic resolution rule, the oracle must be amended with that rule cited as the source reason, and the amendment recorded rather than silently applied.
- 'At least two actual computers' is required by 05-verification-and-operations.md, but C28 also demands a clean rebuild target. The oracle uses three machines. Whether the rebuild target may be a third process on one of the two required computers is unspecified; this oracle treats that as a disclosed substitution affecting only the rebuild assertions, not the exchange assertions.
- Whether a task-level acknowledgement is produced by the receiving agent, the receiving host or the store is unspecified. The oracle asserts only that it is distinct from storage admission and attributable to a named session and turn.
- The declared offline read policy is required to exist but its content is chosen by the implementation. The oracle asserts only that it is declared in advance, applied, and stated in the answer; it cannot pre-judge whether serving stale ledger facts offline is permitted.
- Tombstone versus purge semantics for derived data, queues, transport history, replicas and backups are required to be defined but not specified. The oracle asserts visibility and non-resurrection, and defers the exact retention boundaries to the implementation's documented contract, which must be fixed before the run.
