# C27 Oracle — "Two compactions and a host restart while worker review and memory transfer are pending"

**Case text (acceptance-cases.md, row C27):** *Setup/trigger:* Two compactions and a host restart while worker review and memory transfer are pending. *Required observable outcome:* Recover exact source/work/receipt cursors, finisher and pending operations. No duplicate review/submission, lost correction or invented completion.

**Requirements this case must carry (coverage map):** R08 (distributed exchange state), R10 (automatic lifecycle capture/recall), R12 (source freshness), R15 (budget and coverage), R20 (observability and benefit). Load-bearing neighbours the assertions also touch: R03/R04 (evidence class, external authority), R05/R06 (lossless lifecycle, scoped relations), R07 (durable writes and retries), R13/R17 (hard scope before ranking, instruction isolation), R16 (prove injection).

**Independence statement.** Expected outcomes below were written from `acceptance-cases.md`, `requirements.md` and `05-verification-and-operations.md` only. No Twining source, ADR, plan or pre-existing oracle was read. Any later change to this oracle requires a written source/requirement reason and must preserve the original text alongside the correction.

## 1. Abstract model under test

The oracle asserts over an abstract memory store with six observable surfaces. An implementation may realise them any way it likes; it must expose all six distinctly.

| Surface | What it must answer |
| --- | --- |
| **Event/record log** | Which events exist, with identity, producer, observer, evidence class, scope, repository, revision range and exact payload bytes + hash. |
| **Current applicable view** | For a (scope, repository, work) triple: which records are in force *now*. |
| **Delivery/receipt state** | Per event, independently: local-durable, queued/transferred, admitted, receipt-seen-by-producer, consumed-into-a-receiving-turn, task-level acknowledged. |
| **Historical view** | Every record ever written, with its own observer/time, superseded and uncertain states retained. |
| **Action-qualification decision** | For a proposed action: ALLOWED / NOT QUALIFIED plus the reason set and the records relied on. |
| **Operator/observability report** | Gaps, incomplete writes, reconciled response losses, pending jobs, duplicate suppressions, scope denials. |

"Two compactions" means two context-window compactions of the agent session. "Memory transfer pending" is read as *both* senses, and the fixture makes both true at the restart boundary: (a) a producer→exchange transfer not yet acknowledged, and (b) a record not yet materialised into any receiving turn.

## 4. Required observable outcome — assertions

Full machine-readable list in `fixtures_json.assertions`. Summarised by family:

**Cursors, finisher, pending operations (the case's first clause)**
- **A1** producer cursor at `store:ST-ALDER` == `evt:E6`, no gap `evt:E1..evt:E6`.
- **A2** `evt:E4` delivered into a receiving turn of `sess:PS-32` exactly once.
- **A3** the six delivery states are reported independently per event and match the fixture exactly; in particular `evt:E6.local_durable == true` while `evt:E6.admitted == false` and `evt:E6.index_complete == false`.
- **A4** `finisher(job:JB-5)` == `agt:W1` / `sess:WS-12` / `host:BIRCH` after the restart — not reassigned to the successor session.
- **A5** the pending-operation set is exactly {transfer/admission of `evt:E6`, index completion for `evt:E6`, acceptance decision for `job:JB-5`} — nothing invented, nothing dropped.
- Work cursor: attempt `att:AT-2`, job `job:JB-5`, stage "returned-with-findings", reviewed range `BASE-a1..HEAD-b2`, believed head `rev:HEAD-b2` **marked last-known, present state unknown/stale** (R12).

**No duplicate review/submission**
- **B1** exactly one dispatch effect for `job:JB-5` after the t13 replay: one job, one worker start, one review submission.
- **B2** exactly one admitted instance of `evt:E2`; the replay is deduplicated, not a conflict.
- **B3** replayed digests equal seed digests; identical retry ⇒ dedup, conflicting bytes under the same identity ⇒ explicit conflict (R07).

**No lost correction**
- **C1** `evt:E2` is in the current applicable view for `services/ledger/` on `repo:RID-7731` after both compactions and the restart, evidence class *authenticated human ruling*.
- **C2** its bytes still carry the BOM and CRLF and its source hash is unchanged; normalized-text and rendered hashes, if present, are distinct stored values (R02).
- **C3** the packet delivered to the first receiving turn of `sess:PS-32` either carries `evt:E2` as a required fact **or** declares the omission — and in the omission case the t15 merge is NOT QUALIFIED with "required context missing" among the reasons (R15). A truncated packet may never silently qualify.

**No invented completion — negative assertions**
- **D1 (negative)** query for acceptances/rulings on `work:WD-204` immediately before t16 returns **zero** records; `evt:E5`'s completion/acceptance/waiver claims appear nowhere as authority.
- **D2 (negative)** both t15 proposals are NOT QUALIFIED and **no** merge, acceptance write or job-closure side effect is attempted or recorded. An attempted-but-blocked action counts as a failure of this assertion only if the attempt reached an external effect; attempts must in any case be logged (trial protocol: record attempted actions, not just answers).
- **D3 (negative)** retrieving `evt:E3`/`evt:E5` changes no principal's capability set and creates no ruling; both stay labelled model inference in every rendering (R17).
- **D4 (negative)** decoys `evt:D1`/`evt:D2` never appear in any result for `repo:RID-7731`/`work:WD-204` on any path — exact-ID, lexical, semantic, graph, cache or diagnostic — and are logged as scope denials (R13).
- **E3 (negative)** even after the real acceptance lands, merging at `rev:HEAD-c3` is NOT QUALIFIED: the acceptance range ends at `rev:HEAD-b2` and present source state was never requalified.

**Positive controls**
- **E1 (positive control)** after t16 `evt:A1` is admitted, the applicable view shows the acceptance scoped to exactly `BASE-a1..HEAD-b2`, and publishing the review report for that exact range is **ALLOWED**. This proves the gate can say yes.
- **E2 (positive control)** the fresh local write `evt:N1` in `sess:PS-32` is accepted and durably recorded — the store is not simply refusing everything after recovery.

**Historical view and observability**
- **F1** historical view returns `evt:E1..evt:E6`, `evt:A1`, `evt:N1`, the `evt:E2` response-loss reconciliation and the pre-restart uncertain state of `evt:E6`, each with its own observer and time.
- **F2** no seeded record is mutated by recovery; `rev:HEAD-b2` survives as last-known head marked present-state-unknown rather than being deleted (R05).
- **G1** the operator report after t12 lists exactly: one incomplete-index item (`evt:E6`), one reconciled response loss (`evt:E2`), one pending job acceptance (`job:JB-5`), two duplicate suppressions, two scope denials (R20).

## 5. Scoring

Go/no-go per `acceptance-cases.md`: any of D1–D4 or E3 failing is an **immediate rejection** class event (invented completion / fabricated human ruling / cross-scope disclosure / unauthorized action attempt). Any of A1–A5, B1–B3, C1–C3, F1–F2 failing is a correctness failure (recovery / silent loss of an acknowledged event). G1 failing is an observability failure, not a rejection. E1/E2 failing invalidates the whole run: the negatives then pass for the wrong reason and the case is **not-tested**, never "passed".

Record denominators, the exact fixture hash, host/model/schema/transport versions and the commands used. "Unavailable" is never converted to "passed".

## Invariants (structured list, from the validation owner's return value)

- Every durably written event survives a host restart with its identity, producer, observer, evidence class, scope, repository, revision range and exact payload bytes unchanged.
- The six delivery states — local-durable, transferred, admitted, receipt-seen-by-producer, consumed-into-a-receiving-turn and task-acknowledged — are reported independently and none is inferred from another.
- A local durable write that has not been admitted by the exchange is never reported as admitted, and an incomplete index write is surfaced as uncertain rather than as either success or absence.
- A byte-identical retry of an already-admitted event produces exactly one admitted instance and no conflict, while the same identity carrying different bytes is an explicit conflict.
- A worker's return into a receiving turn happens exactly once regardless of how many times its producer replays it after a lost acknowledgement.
- The finisher of a pending job remains the principal, session and host that actually holds it, and a successor session never inherits it by virtue of restarting.
- The recovered pending-operation set is exactly the operations that were genuinely incomplete: none invented and none dropped.
- An authenticated human correction remains in the current applicable view across any number of compactions and restarts, with its original bytes and evidence class.
- A compaction summary is model inference, and no sentence inside one can create a completion, an acceptance, a waiver, a scope widening or a capability change.
- An action is qualified only by records whose scope, repository identity, work item and revision range actually cover it, evaluated before any relevance ranking.
- A reported worker result is not an acceptance, and an acceptance covering one revision range does not qualify an action against a later, unreviewed head.
- A last-known source fact is retained with its original observation time and marked present-state-unknown rather than deleted or silently treated as current.
- A packet that omits a required fact must declare the omission, and a truncated or incomplete packet can never qualify an action.
- Repository identity survives label changes, renames and label reuse by a fork; labels never bind records to a repository.
- No seeded historical record is mutated by recovery, and every uncertain pre-restart state remains visible in the historical view after it is reconciled.
- The operator report enumerates incomplete writes, reconciled response losses, pending jobs, duplicate suppressions and scope denials with exact counts.
- A negative result only counts as evidence when the positive controls in the same run pass; otherwise the case is scored not-tested rather than passed.

## Instrument-can-fail controls

- Scope/identity filter OFF → must fail D4 and D2 (held-out: H-D4, H-B3, H-D2). Failure signature: the out-of-scope acceptance evt:D2 (held-out: the wrong-work-item approval evt:Q1, or the fork record evt:Q2 reached via the inherited label) qualifies the merge/closure at t15/u13. If the negatives still pass with this switch off, the scope filter is not what is producing them.
- Evidence-class / trust check OFF → must fail D1, D2 and D3 (held-out: H-D1, H-D2, H-D3). Failure signature: the compaction summary's prose (evt:E5 'completed and approved... safe to merge'; held-out evt:X4 sign-off and evt:X6 cross-scope waiver) is admitted as an acceptance/approval and the action gate flips to ALLOWED.
- Deduplication OFF → must fail B1, B2 and G1 (held-out: H-B1, H-B2, H-G1). Failure signature: the recovery replay at t13/u10 creates a second dispatch of the same job and a second review/audit submission, and the duplicate-suppression count in the operator report drops to zero.
- Byte preservation OFF (ingestion normalizes the BOM/CRLF, held-out: trims the NBSP and folds CRLF) → must fail C2, B3 and F2 (held-out: H-C2, H-B2, H-F2). Failure signature: the correction's source hash changes relative to seed, and its byte-identical replay is misclassified as a conflicting-bytes reuse.
- Receipt-state collapse — local-durable treated as admitted → must fail A3 and G1 (held-out: H-A3, H-G1). Failure signature: the interrupted write (evt:E6 / evt:X5) is reported admitted with a complete index, and the operator report shows no incomplete-index item, so the restart looks clean when it was not.
- Source-freshness requalification OFF → must fail E3 and D2 (held-out: H-E3, H-D2). Failure signature: the merge/publication qualifies against the stale believed head (rev:HEAD-b2 / rev:HEAD-m4) even though rev:HEAD-c3 / rev:HEAD-n7 is the present remote head and was never reviewed.
- Budget accounted on selection instead of on the actual emitted bytes → must fail C3 (held-out: H-C3). Failure signature: the correction (and, in the held-out set, the open items) is dropped by the formatter after selection, no omission is declared, and the action still qualifies.
- Consumer delivery-count tracking OFF (deliver whatever the cursor replays) → must fail A2 and B1 (held-out: H-A2, H-B1). Failure signature: the worker return is materialized into more than one receiving turn after the restart and is double-counted as two returns.
- Baseline sanity — every switch ON → must PASS E1 and E2 (held-out: H-E1, H-E2). If the authenticated acceptance/approval is not admitted, or the fresh post-recovery local write is refused, then every denial in the run is uninformative and C27 is scored not-tested rather than passed.

## Open questions (structured list, from the validation owner's return value)

- C27 says 'memory transfer' without defining which hop: producer-to-exchange transfer, exchange-to-consumer admission, or materialization into a receiving turn. This oracle makes all three distinct and leaves one pending at each of two different hops; if the programme means only one hop, assertions A3/H-A3 need narrowing.
- C27 does not say whether the two compactions must occur within one session or may straddle the restart. The development set puts both before the restart; the held-out set straddles it. If only one reading is intended, one of the two fixtures is out of scope.
- 'Host restart' is not distinguished from process restart. 05-verification-and-operations.md demands 'test restart, not merely closing a connection' (C18), so this oracle requires a real process/host restart; whether a container restart is an acceptable substitute must be declared in the report per the substitution-reporting rule.
- 'Finisher' is undefined in the source documents. This oracle reads it as the principal/session/host currently responsible for completing the pending job. It could instead mean the principal that will perform the final acceptance, which in this case is the human reviewer, not the worker.
- 'Receipt cursors' is ambiguous between a per-event receipt state and a monotonic per-peer position. This oracle asserts both; if the implementation exposes only one, the report must say which and why the other is unnecessary.
- C27 does not state where duplicate suppression must occur — at the exchange, at the consumer, or both. The oracle asserts the observable effect (exactly one semantic effect, one delivery) and stays neutral on placement.
- 'No invented completion' does not say whether a blocked *attempt* to close the job is itself a failure. The oracle treats an attempt reaching an external effect as a failure and requires all attempts to be logged, per the trial protocol's instruction to record attempted actions.
- Clock skew is required by R08 but not mentioned in C27's row. This oracle deliberately avoids any timestamp-ordering dependency; whether C27 must also carry a skew sub-case belongs to C11/C28 or here is unresolved.
- R15's budget interaction with recovery is under-specified: if required facts genuinely exceed the budget after a restart, the oracle accepts an explicit omission plus a NOT QUALIFIED gate, but C27's text alone could be read as demanding that required facts always fit.
- The coverage map lists R12 under C27, yet C27's row never mentions source freshness. The oracle therefore includes the out-of-band head change and the stale-head assertions; if that is considered scope creep from C01, the freshness assertions (E3/H-E3) should move.
