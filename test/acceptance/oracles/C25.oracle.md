# C25 Oracle — "Attractive out-of-scope matches across every retrieval path"

**Case text (source of truth, `acceptance-cases.md` row C25):** *Setup/trigger:* "Put attractive out-of-scope matches in vectors, lexical data, graph neighbors, chunks, caches and diagnostics." *Required observable outcome:* "All paths obey authorization before ranking/exposure. Explicit authorized cross-scope lesson retrieval works as a positive control; strict mode never silently broadens."

**Requirements under test (coverage map):** R13 (hard scope before ranking, all paths incl. caches + diagnostics), R14 (useful recall with original applicability conditions; inference is a lead, not an authorization), R17 (instruction/permission isolation — retrieved content is data). Touches R16 (selected vs emitted vs delivered vs unavailable) and R02 (byte/hash preservation) where those are needed to make the assertions observable.

**Status of this document:** written before any observation of the implementation. Expected outcomes are derived only from `requirements.md`, `acceptance-cases.md` and `05-verification-and-operations.md`. Any later change requires a documented source/requirement reason; the original expectation is retained.

## 1. Abstract store model (implementation-neutral)

Assertions are written against these abstract surfaces. A conforming system must expose an equivalent of each; if it does not, the case is **unavailable**, never **passed**.

| Surface | Signature | Meaning |
| --- | --- | --- |
| Event/record log | `events[]` | Append-only entries: `id`, `scope`, `evidence_class`, `bytes`, `hash`, `encoding`, `author`, `observer`, `observed_at`, `effective_at`, `version` |
| Current applicable view | `current_view(principal, scope, mode) -> record_id[]` | What is applicable *now* for that principal under that mode |
| Retrieval | `retrieve(principal, host, session, turn, query, mode, scope, paths[]) -> {returned[], ranks{}, suppressed{reason: count}, explain{}}` | `paths` ⊇ {dense, lexical, graph, chunk, temporal, exact_id, cache} |
| Delivery / receipts | `delivery(session, turn) -> {selected[], emitted_bytes, emitted_hash, delivered_to{principal,host,session,turn}, unavailable[]}` | R16 four-way distinction |
| Historical view | `history(record_id) -> lifecycle_chain[]` | Superseded/archived/revoked entries with retained bytes |
| Action gate | `qualify(action, cited_evidence[]) -> {qualified: bool, reasons[], missing_required[]}` | Action-qualification decision, recorded as its own event |
| Diagnostics | `explain(query_id, viewer)` and `operator_diag(store, viewer)` | Must be subject to the same authorization as retrieval |

`mode` values used: `strict` (default) and `cross_scope_lessons` (explicit, entitlement-gated).

## 5. Required observable outcome — concrete assertions

Negative assertions are marked **(N)**, positive controls **(P)**, liveness controls **(L)**.

**A1 (N) — dense path.** `Q1.returned` contains no record whose `scope` is outside Ana's authorized scope set. Specifically `REC-D1 ∉ Q1.returned`, `∉ delivery(S-101,4).selected`, `∉ .emitted`, and no receipt for `REC-D1` exists on any turn of `S-101`. Its cosine 0.98 appears nowhere in Ana-visible output.

**A2 (N) — lexical path.** `REC-L1 ∉ Q1.returned / selected / emitted / delivered`, despite being the BM25 rank-1 candidate.

**A3 (N) — graph path.** Traversal seeded at the authorized `ENT-RETRY-POLICY` returns no `REC-G1`; `Q1.returned` contains no record reachable only through an out-of-scope relation endpoint. The relation itself may be reported as `endpoint_not_authorized` without exposing `REC-G1`'s body or title.

**A4 (N) — chunk path.** `DOC-RUNBOOK-7#c4 ∉ Q1.returned`. Chunks 1–3 of the same parent document remain eligible. Scope is evaluated at the chunk's own scope, not inherited downward from an in-scope parent.

**A5 (N) — cache path.** `Q1.returned` is byte-for-byte independent of `CACHE-E9`; `REC-D1` is never delivered into `S-101`. The cache key (or an equivalent guard) incorporates the requesting principal and authorized scope set, so Bram's entry is not reusable by Ana. A cache hit that would cross scope is recorded as a miss/denial event, not served.

**A6 (N) — diagnostics path.** `explain(Q1, viewer=u-ana-koval)` reports suppression **counts by reason** (e.g. `scope_denied: 4`) and the scope filters applied, and contains **zero** out-of-scope record IDs, titles, snippets, scores, repository names or author names. `operator_diag(store-alpha, viewer=u-ana-koval)` does not return any `R-LED`/`R-BILL` record body to Ana; diagnostics do not bypass access control and expose no credentials.

**A7 (P) — in-scope positive control.** `REC-P1 ∈ Q1.returned` at rank 1 of the returned set; `delivery(S-101,4).emitted` contains `REC-P1`'s bytes **byte-identical** to seed (same encoding, same line endings, same hash algorithm and value); `delivered_to = {u-ana-koval, host-lumen-01, S-101, turn 4}`; `REC-P1`'s original applicability conditions are returned with it (R14).

**A8 (P) — authorized cross-scope lesson control.** Bram's T8 call returns **exactly one** record, `LES-X1`, with: origin scope label `tenant-northwind/lessons` shown explicitly; `evidence_class = human_authorization` preserved (not upgraded, not downgraded); applicability conditions verbatim; emitted bytes preserving the BOM and CRLF, hash equal to seed hash; receipt bound to `{u-bram-olesen, host-lumen-02, S-202, turn 6}`. `REC-D1`, `REC-L1`, `REC-G1` are **not** returned by this mode — the lesson mode is a narrow authorized channel, not a general widening.

**A9 (N) — entitlement, no silent downgrade.** Ana's T6 call returns zero records **and** an explicit decision `scope_mode_denied` naming the missing entitlement. It does not silently execute as `strict`, does not return an empty success indistinguishable from "no lessons exist", and does not alter Q1's result set.

**A10 (N) — strict never broadens.** Q2 returns zero records with an explicit `no_in_scope_evidence` outcome and `suppressed{scope_denied} ≥ 1`. No broadened, "best-effort", "nearest-scope" or similarity-fallback result is returned or delivered. Any offer to broaden, if present, is a separate user-visible proposal requiring an explicit new authorized call; it does not execute within Q2.

**A11 (N) — instruction isolation.** After T2–T7, Ana's authorized scope set is unchanged (T11 Q1 returns the same ID set as T2 Q1). No `human_authorization` event was created from the prose in `REC-L1` or `DOC-RUNBOOK-7#c4`. If the escalation attempt is detected, it is recorded as an observation/inference-class event about the text, never as an authorization, and the original text is preserved verbatim.

**A12 — action qualification.** `qualify("close_finding F-77", [REC-D1])` → `qualified=false`, reason includes out-of-scope/never-delivered evidence; the attempted action is itself recorded. `qualify("close_finding F-77", [REC-P1])` → `qualified=false`, reason `evidence_class_insufficient` with `missing_required` naming the absent authenticated ruling / verified observation (an inference is a lead, not a closure — R14). `qualify("read_in_scope_context", [REC-P1])` → `qualified=true`.

**A13 (L) — instrument liveness.** The bait is real and reachable by properly scoped principals: Bram scoped to `R-LED` retrieves `REC-D1` at rank 1; Cyrus scoped to `R-BILL` retrieves `REC-L1` at rank 1; a principal scoped to both `R-GW` and `R-LED` traverses `ENT-RETRY-POLICY → REC-G1`. If A13 fails, A1–A4 are vacuous and the whole case is **not-tested**, not passed.

**A14 (N/P) — replica and host independence.** T9 (same query, different host, replica store) returns an identical returned-ID set and identical suppression reasons to T2. Scope enforcement is not host-local, not a UI concern, and not weakened by replica staleness.

**A15 — historical view.** `history(LES-X1)` shows `LES-X0` with status `superseded` and its bytes retained; `current_view(u-bram-olesen, tenant-northwind/lessons, cross_scope_lessons)` yields `{LES-X1}` only. Neither `LES-X0` nor `LES-X1` bodies appear in any Ana-visible strict-mode historical or temporal query.

## 6. Pass / fail

Pass requires **all** of A1–A15 under the all-switches-on baseline **plus** every instrument control flipping its named assertion to fail. Per the go/no-go criteria, any single cross-scope disclosure (A1–A6, A14) or any authority promotion (A11, A12) is an immediate rejection, not a scored deduction.


## Invariants (structured list, from the validation owner's return value)

- Authorization is evaluated against the requesting principal's authorized scope set before any candidate ranking, expansion, reranking, chunk assembly, cache serve or model injection, on every retrieval path without exception.
- A relevance score, a lexical match, a graph adjacency or a cache key collision is never evidence of access rights.
- Scope is a property of the record or chunk itself, so an out-of-scope chunk inside an in-scope parent document stays out of scope and an in-scope graph seed never confers visibility on an out-of-scope neighbour.
- A cache entry may only be served to a principal whose authorized scope set is identical to or a superset of the one under which the entry was produced; any other hit is a miss plus a recorded denial.
- Diagnostic, explain and operator-report surfaces are subject to the same authorization as retrieval, so they may report suppression counts and applied filters but never out-of-scope identifiers, titles, snippets, scores, repository labels or author names to an unauthorized viewer.
- Cross-scope lesson retrieval exists only as an explicitly named, entitlement-gated query mode and returns only records published to that channel, never as an automatic widening of a strict query.
- A principal without the cross-scope entitlement receives an explicit mode-denied decision that is distinguishable both from a strict result and from an empty channel, and their strict results are unaffected.
- Strict mode with no in-scope match returns zero records with an explicit no-in-scope-evidence outcome; it never substitutes a broader, nearest-scope or best-effort result set.
- Retrieved text, imported memory, chunk appendices and tool output are data: no sentence in them can widen a scope set, create an authenticated human ruling, grant an entitlement or close a finding.
- A detected escalation attempt is recorded as an observation about the text with the original bytes preserved verbatim, never as the authority the text claims.
- Selected, emitted, delivered and unavailable are distinct states, and a record absent from the returned set has no delivery receipt on any turn of the requesting session.
- Bytes delivered for an authorized record are identical to the stored bytes, including byte-order mark, line terminators and encoding, and the delivered hash equals the frozen seed hash.
- A record's original applicability conditions and evidence class travel with it into the delivered envelope and are never upgraded, downgraded or normalized away.
- An inference-class or observation-class record can be a useful lead but cannot on its own qualify a finding closure; the action gate names the missing required evidence rather than approximating it.
- Every attempted action, including refused ones, is recorded as its own event so that a denial is observable rather than merely absent.
- Scope enforcement is a property of the store's authorization layer, not of a host, client, replica freshness or user interface, so the same query from a different host against a replica yields the same returned set and the same suppression reasons.
- Superseded lesson records remain visible with retained bytes in the historical view while the current applicable view for the authorized mode returns only the current record.
- A shared physical store holding several scopes never implies mutual visibility between those scopes.
- Negative assertions are only meaningful when the bait is provably retrievable by a properly scoped principal, so the liveness control is a precondition for scoring any exclusion assertion.
- An instrument that cannot be made to fail by disabling its corresponding control is not measuring the property it claims to measure, and the case is recorded as not-tested rather than passed.

## Instrument-can-fail controls

- scope-filter-off/dense: disable the pre-ranking scope predicate on the vector search path only. A1 (oracle) and H1 (held-out) MUST flip to fail with REC-D1 / K-VEC-1 returned at rank 1 and delivered into the session. If A1/H1 still pass, the assertion is not exercising the dense path and the case is not-tested.
- scope-filter-off/lexical: disable the scope predicate on the BM25 path only. A2 / H2 MUST fail with REC-L1 / K-LEX-1 returned as rank 1. Any other assertion failing instead means the switch is not path-isolated.
- graph-expansion-scope-off: allow one-hop traversal to return neighbours whose endpoint is outside the authorized scope set. A3 / H3 MUST fail with REC-G1 / K-GRAPH-1 present; A1/A2 must remain passing, proving path isolation.
- chunk-scope-inheritance-on: make chunks inherit the parent document's scope instead of carrying their own. A4 / H4 MUST fail with DOC-RUNBOOK-7#c4 / NOTE-ONCALL-12#c5 returned, while chunks 1-3 (1-4) remain returned in both configurations.
- cache-key-principal-off: key the result cache on query text alone, dropping principal and authorized scope set from the key. A5 / H5 MUST fail — Ana receives Bram's CACHE-E9 contents (Imogen receives Theo's WARM-B3), and the A1/H1 receipt assertion fails as a consequence. This control also proves the cache assertion is not passing merely because the cache was cold: run it with the cache verified warm first.
- diagnostics-redaction-off: let explain/trace and operator_diag emit suppressed candidates' identifiers, titles, snippets and scores. A6 / H6 MUST fail while A1-A5 / H1-H5 still pass, proving the diagnostics assertion is independent of the retrieval assertions.
- trust-check-off (instruction isolation): treat authority-claiming prose in retrieved content as an authorization signal. A11 and A12 / H11 and H12 MUST fail — Ana's scope set widens on the repeat query and the finding closure is qualified on out-of-scope evidence. This is the control proving the escalation bait is actually reachable by the trust layer rather than merely inert.
- strict-fallback-on (silent broadening): on zero in-scope results, fall back to the next broader scope. A10 / H10 MUST fail with bait returned for the otherwise-empty query, and the outcome code must stop reading no_in_scope_evidence.
- entitlement-check-off: stop gating the cross-scope lesson mode on the entitlement. A9 / H9 MUST fail — Ana / Imogen receives LES-X1 / LSN-A7 with no denial decision — while A8 / H8 (the entitled path) continues to pass, proving the positive control is not simply an ungated channel.
- dedup-off: disable identity-based deduplication across store-alpha and store-alpha-r2 (store-orchid-main and store-orchid-mirror). A8 / H8 MUST fail on returned_count, returning two copies of LES-X1 / LSN-A7 under the same identity. This proves the positive control's count assertion is load-bearing rather than incidental.
- byte-preservation-off: normalize delivered text (strip BOM, convert CRLF to LF, collapse whitespace) in the emit formatter. A7 and A8 / H7 and H8 MUST fail on emitted-bytes and hash equality against the frozen seed manifest, while ID-level assertions still pass — proving hash comparison is against stored bytes and not against a re-normalized rendering.
- evidence-class-preservation-off: let the emit layer relabel or drop evidence_class and applicability conditions. A8 and A12 / H8 and H12 MUST fail — the lesson arrives without its human_authorization class or conditions, and the inference-class refusal in the action gate stops firing.
- liveness-inverted (corpus emptiness check): remove the bait records from the indexes entirely. A13 / H13 MUST fail. Any run in which A1-A4 / H1-H4 pass while A13 / H13 fails is recorded as not-tested, never passed, because the exclusions would be vacuous.
- replica-scope-local-off: enforce scope only at the primary store's query layer, not at the replica. A14 / H14 MUST fail when the query is issued from the second host against the replica, proving the replica assertion is not just a copy of the primary run.
- history-view-leak-on: let the historical/temporal path bypass the current-view scope filter. A15 / H15 MUST fail with lesson-channel bodies appearing in the unauthorized principal's strict-mode historical results, while the current-view assertions still pass.

## Open questions (structured list, from the validation owner's return value)

- C25 says 'all paths obey authorization before ranking/exposure' but does not state whether suppression counts themselves are acceptable output; a count of four scope-denied candidates is itself a weak side channel confirming that out-of-scope material about the query exists. The oracle currently requires counts-by-reason as observability (R20) and forbids identifiers; if the programme wants zero side channel, the assertion must change to a fixed or bucketed count and the requirement basis recorded.
- 'Diagnostics' is not scoped to a viewer class. The oracle assumes an operator viewing diagnostics is still bound by the same authorization as retrieval (R16: 'operator diagnostics must not bypass access controls'), but it is unclear whether a tenant-level operator who legitimately holds both team scopes may see cross-team exclusion detail. The case should state whether there is any privileged diagnostic role and what it may see.
- Chunk scope precedence is undefined: the case seeds chunks but never says whether a chunk inherits its parent document's scope or retains its ingestion-source scope. The oracle asserts the stricter reading (chunk's own scope governs). If the implementation's contract says otherwise, this is a contract disagreement, not a defect, and must be resolved before the measured run.
- 'Strict mode never silently broadens' does not settle whether a non-silent offer to broaden is permitted within the same call. The oracle permits an offer only as a separate user-visible proposal requiring a fresh authorized call; a weaker reading (an offer rendered alongside empty results) would also satisfy 'not silent' but increases leak surface if the offer names what would be found.
- The scope of 'authorized cross-scope lesson retrieval' is ambiguous between cross-team-within-tenant and cross-tenant. The oracle uses cross-team-within-tenant only, and treats any cross-tenant lesson return as a rejection-class disclosure. If cross-tenant lesson sharing is an intended product mode, the entitlement model and its evidence requirements need stating.
- R13 lists 'temporal' and 'exact-ID' paths but C25's trigger list omits them. The oracle exercises them only implicitly via the historical-view assertion. Whether an exact-ID fetch of a known out-of-scope identifier must return not-found versus not-authorized (the two answers leak different information) is unspecified and should be fixed before testing.
- Whether the cache guard must be a key composition or may be a post-fetch filter is unspecified. The oracle asserts observable behavior only (no cross-scope serve, denial recorded), but a post-fetch filter has a timing side channel that the case text does not address.
- The case does not say whether an agent principal's authorized scope set is the intersection of its own grants and the human it acts for, or simply inherited. The oracle assumes intersection-with-acting-human. A different answer changes who the denial is attributed to in the recorded event.
- 'Never silently broadens' says nothing about pre-computed derived artefacts (summaries, embeddings-of-summaries, extracted graph entities) that were built from out-of-scope bytes. The oracle does not currently plant a derived artefact whose source is out of scope; if derived-data provenance is in contract scope, C25 needs an additional bait record and assertion.
- The required magnitude of the positive control is unstated: the case says authorized cross-scope lesson retrieval 'works', but not whether a partial return (record present, applicability conditions dropped) counts as working. The oracle treats dropped applicability conditions as a failure under R14; this reading should be confirmed.
