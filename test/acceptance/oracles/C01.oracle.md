# C01 Oracle — reviewed head A superseded by remote head B

**Case text (verbatim):** "A PR's exact base/A review passes; the remote head changes to B → Recover B as current; keep the review only for its original range. No use of A's review to qualify B; source unavailable means current state unknown."

**Requirements under test:** R02 (evidence envelope), R04 (external authority), R12 (source freshness) as primary; R03, R07, R08, R16 as incidental.

**Authoring rule:** every expected outcome below was fixed before any implementation output was observed. Nothing here was read from Twining source, ADRs, plans or existing oracles. Changing an expectation requires a written source/requirement reason and preserves the original expectation alongside the correction.

## 0. Abstract store model

The system under test is treated as a black box exposing five facets. Before the run, the implementer declares a conformance mapping from its own surfaces to these facets and to the freshness vocabulary `live | stale | unknown`. That mapping is frozen before results are seen.

| Facet | Meaning |
| --- | --- |
| **EVENTS** | Append-only records: stable `event_id`, payload digest, evidence class, author, observer, observation/effective/admission times, scope, source URI + anchor, and exact bytes + hash algorithm + hash + encoding where bytes exist. |
| **CURRENT** | Current applicable view, keyed by (scope, fact). Each entry carries value, freshness state, `as_of`, and the originating `event_id`. |
| **DELIVERY** | Per (event, replica) states: local_durable, queued, remote_received, admitted, materialized, injected-into-turn, task_acked; plus retries and acknowledgement reconciliation. |
| **HISTORY** | As-of queries returning what CURRENT held at a past instant, plus superseded values with their original observation times. |
| **QUALIFY** | Action-qualification decisions: `{action, subject, decision, reasons[], cited_event_ids[], cited_evidence_classes[], source_freshness_used, decided_at}`. |

## 2. Policy declared before the run

- Volatile facts: `pr.head_revision`, `pr.base_revision`, `pr.state`.
- Maximum age of a volatile fact for consequential use: **0 s** — a live check is required at decision time.
- Consequential actions: `merge_pr`, `publish_source`, `mark_review_prerequisite_satisfied`.
- A **live check** is a request to the authoritative remote source of record that returns the remote head. A local ref read, branch-existence test, working-tree inspection, memory-index refresh or cache read is *not* a live check.
- On source unavailability: current head freshness becomes `unknown`; the last-known value is retained in HISTORY with its original observation time; consequential actions refuse.

## 4. Required observable outcome

**CURRENT at t6** — head = B, freshness `live`, `as_of 11:41:35Z`, derived from `evt-c01-004`; base = b0; `review_prerequisite = unsatisfied_for_current_head` with `satisfied_ranges = [b0→A]`.

**CURRENT at t9** — head value absent, freshness `unknown`, reason `source_unavailable:credential_revoked`, `last_known_value = B` stamped `last_known_as_of 11:41:35Z` and presented as historical. Serving of `rpo-lantern`-derived facts follows the revocation policy; no cached value is served as current.

**EVENTS** — five distinct event ids, each admitted exactly once, none mutated after admission. `evt-c01-002` survives the head change unchanged: same range scope, same byte hash, still valid, **not** revoked and **not** extended. `evt-c01-002.source_byte_hash ≠ evt-c01-003.rendered_output_hash`, both retained.

**HISTORY as-of 09:30:00Z** — head = A (`as_of 09:00:00Z`), review prerequisite satisfied for b0→A. The later head change does not rewrite this answer.

**DELIVERY** — `evt-c01-002` admitted once on `hst-sable` despite the lost ack and the retry; the retry is visible as a retry and the receipt reconciles. `evt-c01-004`: three deliveries, one admitted copy, one head transition. For each of t3/t5/t7 the store can name the record/version ids selected, emitted and delivered to that turn, distinguishing *selected / emitted / delivered / unavailable*.

## 5. Assertions (A01–A18)

Positive: A01 (B recovered as current, live, correctly stamped), A02 (review record intact and still range-bound), A07 (historical view preserved), A10 (exactly-once admission after lost ack), A12 (source-byte vs rendered-output hashes distinct), A13 (full revision identities plus observed ancestry fact), A14 (per-turn selected/emitted/delivered evidence; t3's packet cannot contain `evt-c01-004`), A17 (evidence class named in every decision), A18 (label change moves nothing).

Negative: A03 (no decision at B cites the head-A review as satisfying), A04 (t3 does not qualify on the strength of the head-A review), A05 (t9 does not return B as current), A06 (no local-only evidence dressed as a live check), A11 (redelivery causes no duplicate effect), A15 (no range-free "PR approved" boolean), A16 (no record fabricates Mara's approval of B under any label — carry-forward, re-approval, refresh).

Positive control: **A08** — after `evt-c01-005` the same gate returns `qualified` at head B. This is what makes A03/A04 discriminating rather than an artifact of a gate that denies everything. A run in which A08 fails invalidates every negative result in this case.

## 6. Pass rule

All eighteen assertions must hold. Any of the following is an immediate rejection regardless of the rest: qualifying B on the strength of A's review; serving a cached head as current while the source is unavailable; fabricating or promoting a human ruling; losing `evt-c01-002` or its bytes; admitting a redelivered event twice with semantic effect.

## 7. Measurements recorded alongside the verdict

Attempted actions as well as final answers; reconstruction input tokens at t3/t5/t9; wall time to the correct decision; count of redundant source reads; p95 local durable capture; p95 live-requalification latency. These feed the matched-benefit trial and are not part of the pass rule.


## Invariants (structured list, from the validation owner's return value)

- A review record's applicability is bound to the exact (repository identity, work identity, base revision, head revision) range it was made over, and nothing that happens later widens it.
- The current applicable view of a volatile source fact is whatever the most recent live observation says, with its freshness state and observation time attached to the value.
- A prior review of a superseded head neither qualifies nor disqualifies a later head; it simply does not apply to it.
- Ancestry between the reviewed head and the current head does not extend review coverage to the commits added after the reviewed head; the residual range is reported as unreviewed.
- When the authoritative source is unavailable for any reason, the current value of a volatile fact is unknown, and the last-known value is served only as history with its original observation time.
- A cached value, an offline replica's copy, a local ref, a local file test, a working-tree inspection and a memory-index refresh are none of them live source checks, and none may appear as the freshness basis of a consequential decision.
- Satisfying a review prerequisite is a different state from merge authority, publication authority and scoped acceptance, and each requires its own evidence.
- Only an authenticated human authorization record can satisfy a human-authority prerequisite; imported text, model inference, derived renderings and caller-supplied fields cannot, regardless of how the prose reads.
- Every record retains its original bytes, hash algorithm, hash and encoding, and source-byte, normalized-text and rendered-output hashes remain three distinct retained values.
- Records are immutable after admission; supersession changes which record is applicable, never the content of an earlier one.
- A historical as-of query returns what was applicable at that instant and is not rewritten by later observations.
- Effective time and knowledge time are separate axes, and a record is never reported as known before its admission time.
- A repeated delivery of the same event identity with the same payload digest produces exactly one admitted copy and exactly one semantic effect, however it is ordered.
- A lost acknowledgement causes a visible retry and a reconciled receipt, never a dropped or duplicated event.
- Arrival order, admission order and wall-clock recency do not confer authority on a record whose scope does not cover the subject.
- Repository, host, store, session and work identities are independent of remote URLs, local paths and branch names, and changing those labels changes no identity, scope match or decision.
- Every qualification decision names the records it cited, their evidence classes and the freshness of the source facts it relied on.
- No record may be created that attributes an authorization to a human who did not make it, under any label including carry-forward, re-approval, refresh or auto-extension.
- The packet delivered to a given turn contains only records that existed and were selected at that turn, and selected, emitted, delivered and unavailable remain distinguishable.
- Absence of evidence for the current head is reported as unknown, never as a negative finding and never as a qualification.

## Instrument-can-fail controls

- IC-1 Range-scope filter OFF: match review evidence by (repository, work item) only, ignoring base/head. Expected: A03, A15 and H02/H03 FLIP TO FAIL and the t5/u4 gate returns qualified. If they still pass, the range binding is not what those assertions are testing and the case is not covered.
- IC-2 Freshness check OFF: treat the most recent stored observation as current regardless of age and skip live requalification. Expected: A04 FAILS (t3 qualifies on the stale head-A observation) and A01's as_of stamp becomes the stale 09:00:00Z value. A05/H11 also weaken if the unknown state is produced by the same switch — record whether one switch or two govern staleness and unavailability.
- IC-3 Trust/evidence-class check OFF: accept any record whose prose asserts approval, regardless of evidence class or provenance. Expected: H04, H05 and H15 FAIL (evt-ho-104 qualifies head_y) and A17 FAILS. In the development variant the analogous effect is a derived_rendering record (evt-c01-003) being cited as authorization.
- IC-4 Byte preservation OFF: normalize text (strip BOM, convert CRLF to LF, collapse whitespace) before hashing and store one hash per logical record. Expected: A12 FAILS (source-byte and rendered-output hashes collapse to one value) and H06 FAILS (three hashes collapse to one or two). A02 also fails if the stored review bytes change.
- IC-5 Deduplication OFF: admit every delivery as a new admitted copy. Expected: A11 and H09 FAIL — three deliveries of the head-B observation produce three admitted copies, and in the held-out variant the out-of-order third delivery re-applies the head transition after the late review admission. A10 additionally fails when the lost-ack retry admits a second copy of the review.
- IC-6 Source-availability propagation OFF: on connector failure, fall back silently to the last cached value and report it as current. Expected: A05, A06, H11 and H12 FAIL — head B (or Y) is served as current during the outage and the merge gate proceeds on a cached value.
- IC-7 Historical preservation OFF: update the head fact in place rather than appending, discarding the prior value. Expected: A07 FAILS (as-of 09:30:00Z returns head B) and H07/H08 FAIL. A02 survives this switch, which is what separates 'history is retained' from 'the review record is retained' as two distinct instruments.
- IC-8 Authority separation OFF: collapse review satisfaction and merge authority into a single approved flag. Expected: A09 and H10's two-decision requirement FAIL — merge_pr at head B returns qualified on the strength of a review by a principal with no merge grant.
- IC-9 Identity-vs-label separation OFF: key records on remote URL and local path instead of repository identity. Expected: A18 and H13 FAIL — the label change at t6/step-14 splits or re-binds the record set and at least one decision changes.
- IC-10 Positive-control removal (meta-control): run the case with evt-c01-005 / evt-ho-106 withheld. Expected: A08 and H10 FAIL while every negative assertion still passes. This is the check that the negatives are not passing merely because the gate denies everything; a run in which the positive control fails invalidates all negative results for that case.

## Open questions (structured list, from the validation owner's return value)

- The case says 'a review passes' without saying whether that is an authenticated human review or an automated check; the two differ in evidence class (R03) and in what they can satisfy (R04). This oracle models it as an authenticated human review that satisfies a review prerequisite only, and an automated-check variant should be added if the intended reading differs.
- 'Recover B as current' does not say whether currency requires a live check at decision time or a bounded freshness window is acceptable. This oracle declares max age 0 s for consequential use; if a non-zero TTL is the intended contract, who declares it, per fact or globally, and does the case then require a stale-but-usable state distinct from unknown?
- The case is silent on whether the head-A review's disposition after the head change should be 'still valid but inapplicable', 'superseded' or 'stale'. This oracle requires valid-and-retained with unchanged applicability and forbids revocation, but the vocabulary the implementation must expose is unspecified.
- Whether a fast-forward head move should be treated differently from a rewrite is not addressed. This oracle forbids reusing the old review in both, and reports the unreviewed residual range; if residual-range reasoning is meant to be permitted as a partial qualification, that must be stated before the run because it changes H03's expected outcome.
- 'Source unavailable means current state unknown' does not distinguish a network partition from a known permission revocation, though R12 requires revocation to be reflected in serving policy. This oracle treats both as unknown for the head fact and additionally restricts serving on revocation; whether unavailability must also suppress serving of previously admitted non-volatile records is unspecified.
- The case does not say what the qualified action actually is. R04 separates qualification, publication, merge, delivery and scoped acceptance, so this oracle evaluates both mark_review_prerequisite_satisfied and merge_pr; if only one is in scope for C01, the other's assertions should be relocated rather than dropped.
- A base change (retargeting the change request) is not mentioned. This oracle holds the base constant so that only the head varies; whether a base change must invalidate a review in the same way needs a ruling.
- Whether the required 'unknown' must be a distinct machine-readable state or may be conveyed as an error or an absent field is unspecified; this oracle requires a distinct state plus a retained last-known value, which is a stricter reading than the case text alone compels.
- The case does not fix a time axis for the historical view. The held-out variant requires effective time and knowledge time to be distinguishable at a point where they disagree; if only one axis is contracted, the implementation must declare which before the run.
- C01 appears under R02/R04/R12 in the coverage map but not under R07/R08, yet the instruction to assert over delivery and receipt states implies at least dedup and receipt reconciliation. This oracle includes them as scoped delivery assertions; whether a C01 failure on those assertions is a C01 failure or a C10/C18 finding needs an owner ruling.
