# C22 — Independent validation oracle (development set)

**Case text under test (verbatim):** *"Cyclic dependencies, dangling supersession, unauthorized cross-scope relation and competing corrections → Reject/quarantine/defer as specified; no invented resolution or silently dropped prerequisite. A valid scoped relation is still admitted."*

**Coverage:** the coverage map binds C22 to **R06** only. This oracle also asserts the R06-adjacent behavior that C22's wording necessarily drags in — R05 (lifecycle preservation), R03 (evidence classes), R07 (identity/digest, retries), R08 (independent exchange states), R13 (scope before exposure), R16 (delivery evidence), R17 (data cannot confer authority), R20 (rejected-record/scope-denial visibility). Verdicts are reported per requirement so an R06 pass is not inflated by the others.

**Authoring rule honoured:** written from `acceptance-cases.md`, `requirements.md` and `05-verification-and-operations.md` only. No Twining source, ADR, plan or existing oracle was read. Expected outcomes below are stipulated, not observed.

## 1. Abstract memory store (implementation-neutral vocabulary)

The system under test must expose, by any mechanism (API, MCP tool, CLI, export), five observable surfaces. Names are ours; a conforming implementation may spell them differently as long as the mapping is declared **before** the run.

| Surface | Must expose |

## 4. Required observable outcome — concrete assertions

Every assertion must hold **on both stores independently** unless stated.

### 4.1 Event dispositions (R06, R07)

- **A01** `E-201`, `E-202` → `admission_state = admitted`; both relations `admitted`.
- **A02** `E-203` → `admission_state ∈ {quarantined, rejected}` with `reason_code = cyclic_prerequisite` and `cycle_members = [R-120, R-121, R-122]`. The disposition chosen must match the implementation's **pre-declared** contract for cycles; a disposition that varies run to run is a failure.
- **A03** `E-204` → record `R-130` admitted; relation `REL-04` in state `deferred` with `reason_code = missing_supersession_target` and `pending_prerequisite = [R-129]` **before** S13; state `admitted` **after** S13.
- **A04** `E-205` → `rejected`, `reason_code = unauthorized_cross_scope_relation`, with `actor_authority_scopes = ["svc/reporting/"]` and `target_scope = "svc/billing/invoices/"` both recorded.
- **A05** `E-206`, `E-207`, `E-208` → `admitted`, each with exactly **one** semantic effect.
- **A06** `E-206#retry` → `deduplicated`; `total_effects_for_E-206 = 1`.
- **A07** `E-206#conflict` → `rejected`, `reason_code = identity_reuse_conflicting_bytes`; **both** digests (`sha256:a140…` and `sha256:b140…`) retained; not merged into `E-206`.
- **A08** `E-210` → record admitted with `assigned_evidence_class = model_inference`; `caller_supplied_authority_fields_honored = false`.
- **A09** Byte preservation: for `E-203`, `E-205` and `E-206#conflict`, `payload_bytes_sha256` on read-back equals the digest at submission, and the stored encoding label is unchanged, **despite non-admission**.

### 4.3 Negative assertions

- **N01** `current_applicable_view("svc/billing/invoices/")` contains **no** record `R-150` and **no** relation whose `authorizing_principal` is `hum-boris` — in `applicable_records`, `contested`, `superseded` **or** `non_authoritative_present`. (The cross-scope actor leaves no trace in the target scope's live view; the attempt lives only in the historical/rejected ledger.)
- **N02** No record is invented. `historical_view.invented_records = []`. Specifically, before S13 there is **no** applicable, authoritative or bytes-bearing `R-129`; a placeholder is tolerated **only** if `evidence_class = unknown` **and** `applicable = false` **and** `bytes_sha256 = null`.
- **N03** No prerequisite is silently dropped. The count of `requires` edges recorded anywhere (admitted + quarantined) for the R-120/121/122 group is **3**, not 2 — `E-203` must be *present and refused*, never absent.
- **N04** The contest is **not** resolved by arrival order, by `asserted_time`, by `observed_time`, by prose similarity, or by record-id ordering. Concretely: on store-A, `E-207` arrives last; on store-B, `E-206` arrives last; the resulting `contested` set is identical on both and neither successor is marked applicable.
- **N05** No probe returns `qualified` by citing `R-170`, `R-150`, or either competing successor alone.
- **N06** `delivery_receipts` for `E-203`, `E-205` and `E-206#conflict` must show `validated_admitted = false`, `materialized = false`, `injected_into_turn = false`, `task_acked = false` while `remote_received = true` — receipt of bytes is never reported as admission.

## 5. Grading

- Any of **N01–N06** failing is an **immediate rejection** under the go/no-go list (authority-changing error, cross-scope disclosure, or silent loss).
- **A02/A03/A04** may pass with any of reject/quarantine/defer **provided the mapping was declared before the run**; an undeclared or run-varying disposition is a fail, not a pass.
- P-CTRL-1 failing means the implementation is merely restrictive, not correct; it is a fail with the same weight as a false admit.


## Invariants (structured list, from the validation owner's return value)

- INV-01 A relation that closes a prerequisite cycle is never admitted, and the acyclic edges authored before it remain admitted unchanged.
- INV-02 A refused relation is always present in the rejected or quarantined ledger with a reason code; absence of the edge is a failure, not a pass.
- INV-03 The system never removes an arbitrary edge to break a cycle, and never reports a cycle as resolved.
- INV-04 A supersession whose target is unknown to every store does not take effect, and the superseding record does not become applicable by virtue of the unresolved relation.
- INV-05 An unknown supersession target is never invented; any placeholder carries evidence_class unknown, applicable false and no bytes.
- INV-06 When the missing target later arrives, the deferred supersession resolves to that target only and touches no neighbouring record.
- INV-07 A principal with authority only in scope X cannot supersede, correct or retract any record in scope Y, no matter which agent submits the event on their behalf.
- INV-08 A rejected cross-scope relation leaves zero trace in the target scope's current applicable view, appearing only in historical and operator surfaces.
- INV-09 A narrow correction changes only its own scope; neighbouring scopes keep their records, revisions and bytes byte-for-byte identical.
- INV-10 Two equally authoritative incompatible corrections to the same record leave that record explicitly contested with both successors visible and neither applicable.
- INV-11 Contest resolution is never derived from arrival order, asserted time, observed time, record-id ordering or prose similarity.
- INV-12 Both replicas converge to the same current view, contested set and rejected ledger regardless of per-replica delivery order and clock skew.
- INV-13 An action whose prerequisite is contested is refused with the contest named, and no default successor is silently chosen.
- INV-14 An action whose prerequisite chain is cyclic is refused with the cycle members named and an empty silently-dropped-prerequisite list.
- INV-15 A valid, in-scope, authorized, acyclic, non-dangling relation is admitted and becomes effective for action qualification even while four malformed relations are pending disposition.
- INV-16 Every rejected, quarantined or deferred event retains its original payload bytes, digest and encoding label unchanged.
- INV-17 A byte-identical redelivery of an already-admitted event produces exactly one semantic effect in total.
- INV-18 Reuse of an event identity with different bytes is an explicit conflict, never a silent duplicate-accept and never a merge.
- INV-19 Caller-supplied fields such as authorized_by, promoted_by, status or active, and emphatic prose such as MUST or REQUIRED, never raise a model-authored record above evidence class model_inference.
- INV-20 A model-authored record can be visible and retrievable while being incapable of resolving a contest or qualifying an action.
- INV-21 Remote receipt of bytes is reported independently of validated admission, materialization and injection, and a non-admitted event never shows admitted, materialized or injected true.
- INV-22 Rejections, deferrals, scope denials and dedup counters are visible on an operator surface without that surface exposing bytes to a principal outside the record's scope.

## Instrument-can-fail controls

- CTRL-01 Scope filter OFF (admit relations without checking the authorizing principal's authority scopes against the target record's scope): E-205 / F-403 must become admitted, N01 / HN01 must fail, A04 / HA04 must fail, and Q1 / P1 must flip from refused to qualified. If all of these still pass with the filter off, the scope filter is not the thing producing the pass.
- CTRL-02 Scope filter set to DENY-ALL (reject every relation regardless of authority): the positive control must break — E-208 / F-404 becomes rejected and Q4 / P4 flips from qualified to refused. This proves the filter is consulted rather than the suite being trivially satisfied by refusing everything.
- CTRL-03 Trust / evidence-class check OFF (honour caller-supplied authorized_by, promoted_by, status and active fields): E-210 / F-410 must be classified as authenticated_human_authorization, A08 / HA07 must fail, A13 / HA09 must fail, and Q1 / P1 must flip to qualified citing R-170 / K-370 — N05 / HN05 fails.
- CTRL-04 Cycle detection OFF: E-203 / F-407 must become admitted, A02 / HA02 and N03 / HN03 must fail, and Q3 / P3 must return either qualified or an arbitrary ordering — A10 / HA08 fails on admitted_requires_edge_count becoming 3.
- CTRL-05 Dangling-reference deferral OFF (apply supersessions whose target is unknown): REL-04 / LNK-08 must apply immediately, A03 / HA03 must fail, and either an invented R-129 / K-329 appears (N02 / HN02 fails) or R-130 / K-330 becomes applicable with no superseded target recorded (A12 / HA09 fails).
- CTRL-06 Deduplication OFF: E-206#retry / F-402#retry must produce a second semantic effect, A06 / HA05 fails, the contested set grows to three successors so A11 / HA09 fails, and the dedup counter in A16 / HA13 reads effects 2.
- CTRL-07 Byte preservation OFF (normalize BOM, line endings, trailing whitespace and encoding before digesting): E-206#conflict / F-402#conflict must be accepted as an identical retry instead of an explicit conflict, A07 / HA06 fails, and the two retained digests in the expected end state collapse to one — A09 also fails for the quarantined events.
- CTRL-08 Contested-view rule OFF, replaced by last-writer-wins on observed_time: one of R-140 / R-141 (or K-340 / K-341) becomes applicable, A11 / HA09 fails, N04 / HN04 fails, and the two replicas diverge so the convergence assertion A15 / HA11 fails — with the +11 minute host-lark skew in the held-out variant the wrong successor wins, which is the point of the skew.
- CTRL-09 Rejected/deferred ledger OFF (drop non-admitted events instead of recording them): A16 / HA13 fails and N03 / HN03 fails because the refused cycle edge becomes indistinguishable from an edge that was never submitted — this control specifically proves the suite can tell 'refused' from 'absent'.
- CTRL-10 Receipt-state collapse ON (report a single boolean 'delivered' instead of the seven independent states): N06 / HN06 fails and the A-series receipt assertions become untestable, which must be reported as not-tested rather than passed.
- CTRL-11 Convergence check bypassed (assert against store-A / store-M only): A15 / HA11 becomes vacuous. Run this control to confirm the harness actually queries both stores and does not silently reuse one projection for both.

## Open questions (structured list, from the validation owner's return value)

- The case says 'reject/quarantine/defer as specified' but does not say which disposition belongs to which trigger; this oracle requires the implementation to pre-declare its mapping and then holds it to that mapping, rather than asserting a specific one. If the programme intends a fixed mapping, it must be stated in the contract before the run.
- No expiry policy is given for a deferred dangling supersession. If R-129 / K-329 never arrives, is the deferral permanent, does it escalate to quarantined after a TTL, and does the deferred edge count against a queue-depth budget? The oracle only covers the arrives-later branch.
- It is unstated whether the endpoint records of a quarantined cyclic edge remain individually applicable. This oracle asserts they do (R-120/121/122 stay applicable as statements); the opposite reading, that the whole cluster is quarantined, would fail assertion A10 for a defensible reason.
- It is unstated whether a cycle is an error for all relation types or only for prerequisite-bearing types. A cycle among advisory relates_to edges may be legitimate. The oracle exercises only requires.
- Length-1 and length-2 cycles (a record superseding itself; A supersedes B and B supersedes A) are not exercised and their disposition is undefined by the case text.
- The case does not say whether 'competing corrections' must end contested or whether a documented authority rule is expected to resolve them. hum-clara / hum-nils hold broad scope in the fixtures but are deliberately never exercised, so a broad-beats-narrow rule cannot silently settle the contest; if the programme intends broad-over-narrow as the resolver, a separate variant is needed.
- Whether a rejection must be reported back to the producing store as a negative receipt, or only logged locally, is undefined. The oracle asserts the receipt tuple shows not-admitted but does not require a push-back notification.
- Whether a deferred record counts as 'delivered' for R16 delivery-evidence purposes is ambiguous; the oracle splits it (record materialized, relation not materialized) but an implementation could defensibly report the whole event as not delivered.
- 'No invented resolution' is not defined operationally. The oracle reads it as: no applicable record or relation exists that was not authored by an admitted event. A weaker reading (a proposal-class suggestion is allowed) would change A13 and N02.
- The case does not say whether the contested state must be exposed to the model in an injected context packet or only to the operator. The oracle requires the action-qualification decision to name it; whether it must also appear in the injected envelope is left open.
