# C07 Oracle — "Stored review output differs from CLI rendering by header, BOM or newline encoding"

**Owner:** independent validation (C07). **Oracle version:** 1.0.0. **Set:** development fixtures.
**Case text under test:** *"Preserve original byte streams and distinct hashes/encodings; no normalization silently rebinding evidence."*
**Requirements exercised:** R02 (primary), R16 (primary), R07 (identity/retry/conflict), R13 (scope before ranking), R03/R04 (evidence class cannot qualify), R12 (freshness, adjunct A14).

## 0. Independence note, assumptions, decisions

- **Independence.** Written from `acceptance-cases.md`, `requirements.md` and `05-verification-and-operations.md` only. No Twining source, ADR, plan or existing oracle was read, and no project context-assembly call was made, because both would leak implementation-derived expectations into the expected outcomes. This is a deliberate deviation from the project's Gate-1 convention, recorded here rather than silently taken.
- **Assumption A-1.** Both byte streams are *ingested* as evidence records. The case text says the stored output "differs from" the CLI rendering; it does not say whether the rendering is ever stored. If the system under test only compares at read time, assertions A01–A06 are re-scored against whatever record it does hold, and the gap is reported as an unmet R02 envelope rather than silently waived.
- **Assumption A-2.** "Normalization" means *any* octet-level change: BOM strip/insert, CRLF↔LF, trailing-newline fix-up, Unicode NFC/NFD, header/preamble removal, whitespace trimming, re-encoding.
- **Assumption A-3.** Storing bytes inline or by content-addressed reference both satisfy preservation, provided read-back is octet-exact.
- **Decision D-1.** The oracle does **not** dictate which artifact is "the" evidence of record (the case text does not say). It requires that they remain two identities and that qualification bind to an exact byte hash. Rejected alternative: asserting "stored wins", which would bake in a policy the requirements never state — and the held-out variant deliberately makes the *rendering* the legitimate qualifier to catch a system that hard-codes it.
- **Decision D-2.** A test-defined normalization `N-v1` exists only so the oracle can *prove* the two streams normalize identically. The system under test is not required to implement it; A05 constrains what such an equality may be used for if it exists.
- **Decision D-3.** Cross-tenant twin (A09) and freshness (A14) go slightly beyond the literal C07 sentence. They are included because the byte-hash lookup path is the most plausible place a scope check is skipped, and they are labeled adjunct so a reviewer can drop them without touching A01–A08/A10–A13.

## 3. Required observable outcome — assertions

Legend: **(P)** positive, **(N)** negative, **(PC)** positive control, **(adj)** adjunct beyond the literal case text.

- **A01 (P) — two identities.** Exactly two admitted evidence records exist for `rr-2291-01`: `ev-RVW-0001` (A) and `ev-RVW-0002` (B), with distinct record ids, distinct `source_uri`, distinct `source_kind` (`review_output.stored` / `review_output.rendered`).
- **A02 (P) — distinct byte hashes.** `source_byte_sha256(ev-RVW-0001) = 449d20e9…1f59`, length 99; `source_byte_sha256(ev-RVW-0002) = 7d69d0c6…cb57`, length 172. The two values are not equal and neither is recomputed from a decoded/normalized form.
- **A03 (P) — encoding envelope preserved.** `ev-RVW-0001 = {encoding: utf-8, bom: false, newline: LF, trailing_newline: true, header_lines: 0}`; `ev-RVW-0002 = {encoding: utf-8, bom: true, newline: CRLF, trailing_newline: true, header_lines: 2}`. No declared field is absent, null or defaulted.
- **A04 (P) — octet-exact round trip.** Reading each record back yields octets whose sha256 and length equal the recorded values; specifically the read-back of `ev-RVW-0002` starts with `EF BB BF` and contains `0D 0A`, and the read-back of `ev-RVW-0001` contains no `0D` and no BOM.
- **A05 (N) — normalized equality is not identity.** If a normalized-text hash exists it equals `a1c1d61d…28ab` for both records, and this equality must produce **no** merge, no dedup, no replacement, and no relation of type `duplicate_of | equivalent_to | supersedes | alias_of | same_evidence_as` between the two records. A query for "the review evidence for pr-2291@H1" must not return a single collapsed record.
- **A06 (P+N) — four hash classes are four values.** For `ev-RVW-0001`, source-byte `449d20e9…`, Git object id `0cdb1cb6…c78f` and normalized `a1c1d61d…` are recorded in three distinct fields with three distinct values. For `ev-RVW-0002`, Git object identity is **unknown with a reason** (`not a repository object`) — it is neither A's blob id `0cdb1cb6…` nor the decoy `b216c44f…c762` obtained by blob-hashing the rendering, presented as repository provenance.
- **A07 (P) — idempotent retry.** After T4 exactly one record exists for `ev-RVW-0001`; transport attempts = 2, admitted = 1, semantic effects = 1; the current applicable view is unchanged by the retry.
- **A08 (N) — id reuse with conflicting bytes.** T5 produces an explicit conflict entry (`reused_event_id_conflicting_digest`), `ev-RVW-0001` still hashes to `449d20e9…`, `c17e6bee…f90d` never appears as admitted evidence, and the substring `Verdict: approved` never appears in the current applicable view for `pr-2291`.
- **A09 (N, adj) — scope before ranking or hashing.** A lookup by `449d20e9…` with northwind credentials returns only `ev-RVW-0001`; `ev-MNT-0009` (identical bytes, identical hash, other tenant) appears in no result set, no graph-neighbor expansion, no cache and no diagnostic/trace output. Symmetric from southwind.
- **A10 (N) — evidence class holds.** M-1 is retrievable verbatim as `model_inference`; it appears as neither authorization nor verified observation, changes no record's class, and creates no relation between `ev-RVW-0001` and `ev-RVW-0002`.
- **A11 (P+N) — delivery evidence is about emitted octets.** The receipt for `sess-B-114`/`t-7` records selected `[ev-RVW-0001]`, `emitted_byte_length = 99`, `emitted_bytes_sha256 = 449d20e9…`, delivery state `delivered`, transform `none`, bound to host/session/turn. Negative: if the probe shows emitted octets differing from the record's octets, the receipt must carry both hashes and name the transform; it must never report the record hash as the emitted hash, and "selected" must never be reported as "delivered".
- **A12 (N) — the core assertion: no rebinding by normalization.** Q-BAD is **denied**, with reason class `supplied_bytes_match_no_admitted_evidence_in_scope`. The reasons `normalized_text_match`, `model_inference_citation` and `similar_prose` must not appear in the allow path. Post-state: no qualification record for `pr-2291@H1` cites `45bc835a…ef65`.
- **A13 (PC) — positive control.** Q-GOOD is **allowed**, producing a qualification record citing `ev-RVW-0001` with `source_byte_sha256 = 449d20e9…`, scope `tnt-northwind/rid-LEDGER-7A3@H1`, actor `ap-packer-07`, and no claim of human authority (no `hp-*` principal recorded as ruling). If A12 passes while A13 fails, the deny path is over-broad and C07 is **not** demonstrated.
- **A14 (N, adj) — freshness.** After T13 the current applicable view for "review evidence at current head (H2)" reports none-admitted/unknown; both records remain retrievable in the historical view bound to H1 with original observation times and observer hosts; neither is presented as evidence for H2.

## 4. Scoring

C07 passes only if A01–A08 and A10–A13 all pass, A09 and A14 pass or are explicitly waived with a recorded reason, **and** every instrument control in `instrument_controls` flips its named assertion to failure when disabled. Per the go/no-go rules, an A12 failure (byte stream rebound to a qualification) is an authority-changing error and is an immediate rejection, not a scored deduction; an A05/A08 failure is silent evidence loss. "Unavailable" is never scored as "passed".


## Invariants (structured list, from the validation owner's return value)

- Two byte streams that differ in any octet are two evidence records with two identities, however similar their rendered text.
- Stored octets read back exactly as written: same length, same BOM presence, same line terminators, same trailing bytes.
- Source-byte hash, Git object id, normalized-text hash and emitted-packet hash are four distinct recorded values and are never substituted for one another.
- Git object identity for an artifact that is not a repository object stays unknown with a reason and is never backfilled from a sibling record or from locally blob-hashing the bytes.
- Normalized-text equality may inform ranking or a lead, but never merges records, creates an equivalence or supersession relation, or qualifies an action.
- An action qualification binds to an exact admitted source-byte hash within an authorized scope; supplying different octets that normalize the same is denied.
- A byte-identical retry under an existing event id produces one record and one semantic effect while the transport attempt count increases.
- A reused event id carrying different octets is an explicit recorded conflict that leaves the admitted record and its hash unchanged.
- Scope authorization is applied before any exact-hash, lexical, dense, graph, cache or diagnostic path returns a candidate, so a byte-identical artifact in another tenant is never disclosed.
- A model-inference record keeps its class and its verbatim text and can never authorize, merge, reclassify or relate evidence records.
- A delivery receipt records the octets actually emitted at the host/session/turn boundary, and any transform between record and emission is named with both hashes present.
- Selected, emitted, delivered and unavailable are distinct delivery states and one is never reported as another.
- Current applicability is bound to the revision observed; when the head moves with no new observation, current evidence is unknown and the prior records remain historical.
- Arrival order, admission order and wall-clock skew never decide which record is authoritative or which octets a receipt reports.

## Instrument-can-fail controls

- BYTE_PRESERVATION=off (ingest normalizes: strip BOM, CRLF->LF, force trailing newline). Must flip A02, A03, A04 to FAIL: read-back of ev-RVW-0002 hashes 449d20e9... instead of 7d69d0c6... and reports length 99 instead of 172; held-out H04 must fail with ev-SCN-A7 transcoded out of utf-16le. If these still pass, the harness is reading its own fixture rather than the store.
- NORMALIZED_MERGE=on (treat equal normalized-text hash as one identity). Must flip A01, A05, A12 (H01, H05, H12) to FAIL: one collapsed record is returned for pr-2291 and Q-BAD is allowed on Bp. This is the case's central failure mode and must be demonstrable on demand.
- DEDUP=off (admit every submission). Must flip A07 (H07) to FAIL: two records exist for ev-RVW-0001 after the byte-identical retry and semantic effects count 2.
- DIGEST_CONFLICT_CHECK=off (last write under an event id wins). Must flip A08 (H08) to FAIL: ev-RVW-0001 hashes to c17e6bee... and 'Verdict: approved' appears in the current applicable view; in the held-out set 'Outcome: clean' appears and the honest retry re-admits over the rejected bytes.
- SCOPE_FILTER=off (authorization applied after ranking, or not at all on the exact-hash path). Must flip A09 (H09) to FAIL: the northwind lookup for 449d20e9... also returns ev-MNT-0009. Run this control separately against each path: exact-hash, lexical, dense, graph neighbors, cache and diagnostics, because a filter can be present on one and missing on another.
- TRUST_CHECK=off / evidence-class enforcement disabled (accept a model-inference citation or normalized match as a qualification reason). Must flip A10 and A12 (H10, H12) to FAIL: M-1/M-2 is cited on the allow path and a qualification record appears citing 45bc835a... (held-out 8665d95b...).
- EMITTED_BYTE_CAPTURE=off (receipt echoes the selected record's hash instead of the octets observed at the boundary). Must flip A11 (H11) to FAIL: the held-out receipt reports 8032edc1... as emitted where the external probe measured 0d095891... over 150 octets, and no transform is named.
- FRESHNESS_BINDING=off (evidence carried forward to the new head). Must flip A14 (H14) to FAIL: ev-RVW-0001 is returned as current review evidence at H2 with no new observation.
- DENY_ALL=on (qualification gate refuses everything) - sanity control in the opposite direction. Must flip A13 (H13) to FAIL while A12/H12 still passes, proving the negative assertions are not passing merely because nothing is ever allowed.
- ORDER_AND_SKEW_CONTROL: replay the held-out sequence with S3/S4 swapped and the 14-minute skew removed. All H-assertions must keep the same verdicts; any verdict that changes shows arrival order or wall-clock is deciding authority (H15 FAIL).

## Open questions (structured list, from the validation owner's return value)

- The case text does not say whether the CLI rendering is itself ingested as a record or only compared at read time; this oracle assumes both are ingested (assumption A-1) and will re-score A01-A06 against whatever record exists if that assumption is wrong.
- C07 does not designate which artifact is the evidence of record for qualification, so the oracle requires exact-hash binding rather than a stored-vs-rendered preference; the held-out variant deliberately makes the rendering the legitimate qualifier to expose a hard-coded preference.
- R02 names four hash values but does not require a normalized-text hash to exist; the oracle treats it as optional-if-present and constrains only what it may be used for.
- The vocabulary for encoding metadata is undefined (for example 'utf-8-bom' as one label versus encoding plus a separate bom flag); the oracle scores semantic equivalence, not field spelling.
- It is unstated whether trailing-newline or Unicode-form fix-ups count as 'normalization'; assumption A-2 treats any octet change as normalization, which is the stricter reading.
- Whether original octets must be stored inline or by content-addressed reference is unspecified; either is accepted if read-back is octet-exact (assumption A-3).
- 'No normalization silently rebinding evidence' could forbid normalized-hash-based retrieval ranking as well as binding; the oracle permits ranking and forbids merge, relation creation and qualification, and this reading should be confirmed.
- C07 says nothing about tenants or freshness; the cross-tenant twin (A09/H09) and the head-advance check (A14/H14) are labeled adjunct and can be dropped without touching the rest.
- How a byte store that cannot represent UTF-16LE should behave is unspecified; the held-out variant treats a transcode-on-ingest as a byte-preservation failure rather than an accepted limitation, and that disposition should be agreed before the measured run.
- Whether the emitted-bytes probe may be the system's own trace or must be external is unstated; the oracle requires an external probe because a self-reported emitted hash cannot falsify A11/H11.
