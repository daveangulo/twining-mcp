# C26 Oracle — "Required context exceeds budget; formatting adds overhead or omits a selected record"

**Owner:** independent validation. **Derived from:** `acceptance-cases.md` C26 row, `requirements.md` R15/R16 (plus R03, R13, R20 as guards). **Not derived from any implementation.**

Case text under test: *"Token limit applies to actual delivered bytes/format under the declared tokenizer. Missing required context is explicit and cannot qualify an action; delivered-record receipts match reality."*

## 1. Abstract model (implementation-neutral)

The system under test is treated as a black box exposing five observable surfaces. Any product that cannot expose an equivalent of each surface fails C26 as **unavailable**, never as **passed**.

| Surface | Observable |
| --- | --- |
| **S1 events/records** | immutable records with id, version, evidence class, scope (tenant/repo/revision), source bytes + hash, required/optional role per request |
| **S2 current applicable view** | which record versions are currently applicable in a given scope, independent of any delivery |
| **S3 delivery/receipt states** | per assembly attempt: `selected`, `emitted`, `delivered`, `acknowledged`, `omitted`, `unavailable`, `unknown`, with the exact emitted byte stream, its hash, the declared tokenizer + version, and the counted tokens |
| **S4 historical view** | prior attempts, their receipts and omission manifests, retrievable unchanged after later attempts |
| **S5 action-qualification decisions** | for a named action: `qualified` / `blocked`, the basis record ids, and the named missing prerequisite ids |

**Budget definition used by this oracle:** the budget is enforced over the *token count of the exact byte stream emitted toward the receiving turn*, under the declared tokenizer, **including** framing/preamble/per-record headers/omission manifest/footer. Body-only or pre-format accounting is a failure, not a variance.

## 4. Trigger sequence

- **T0** Seed S1 with all seven records; S2 shows all seven current in their own scopes.
- **T1 / Attempt A1** — `assemble(action=publish-release-notes, scope=repo-quarry@rev-9f3c1a, budget=4000, host=host-nimbus-a, session=sess-N7A-1142, turn=turn-0009)`. Required set alone costs 5460 framed tokens > 4000.
- **T2** Emit A1's packet `pkt-A1-0001`; host acknowledges.
- **T3** Query S5 for `publish-release-notes` as of A1.
- **T4 / Attempt A2** — same request, `budget=6000`, with a **formatter fault injected**: the renderer's prerequisite template emits at most two required records and silently discards the third (`REQ-B`) *after* selection reported the set complete. Emit `pkt-A2-0002`; host acknowledges.
- **T5** Query S5 as of A2.
- **T6 / Attempt A3 (positive control)** — same request, `budget=6000`, formatter fault removed. Emit `pkt-A3-0003`; host acknowledges.
- **T7** Query S5 as of A3.
- **T8 / Attempt A4** — re-emit the A3 packet (same packet identity `pkt-A3-0003`) toward `host-nimbus-b` / `sess-N7B-0431` / `turn-0003`; **the acknowledgement is lost in transport after remote success**. Query S3 and S5 for that turn.
- **T9** Retry the same packet identity; acknowledgement arrives. Query S3.
- **T10** Re-read S4 for A1 and A2.

## 5. Required observable outcome — assertions

Every assertion is checked against the surfaces above, not against internal logs.

**C26-A01 (budget over delivered bytes).** For every attempt, `receipt.delivered_token_count == tokenizer(tk-bluefin/3.2).count(receipt.emitted_bytes)` and `<= request.budget`. A1: 3930 ≤ 4000. A2: 3930 ≤ 6000. A3: 5855 ≤ 6000.

**C26-A02 (instrument reproducibility).** An independent recount of `receipt.emitted_bytes` under the declared tokenizer reproduces `delivered_token_count` exactly; a ±0 tolerance.

**C26-A03 (formatting overhead is counted).** `delivered_token_count` minus the sum of emitted record bodies equals the framing arithmetic (preamble + 40·emitted_records + manifest + footer). A1: 3930 − 3600 = 330 = 120 + 120 + 70 + 20.

**C26-A04 (tokenizer declared).** Every receipt names `tokenizer_id` and `tokenizer_version`. If a fallback is used, `conservative_fallback == true` and its count is **≥** the true declared-tokenizer count over the same bytes.

**C26-A05 (selected ≠ emitted ≠ delivered).** `receipt.delivered_records` is derived from the emitted byte stream, not from the selection list. For A2, `REQ-B ∈ selected` and `REQ-B ∉ emitted` and `REQ-B ∉ delivered`.

**C26-A06 (omission manifest completeness).** Every record in `selected \ emitted` appears in `receipt.omissions` with id, version, `role ∈ {required, optional}` and a reason. A1 omissions = `{REQ-B: required/does_not_fit, OPT-D: optional/does_not_fit, OPT-E: optional/does_not_fit}`. A2 omissions = `{REQ-B: required/formatter_drop, OPT-D, OPT-E}`.

**C26-A07 (NEGATIVE — missing required cannot qualify).** For every attempt where `required \ delivered ≠ ∅`, `S5.decision != "qualified"`. Holds for A1 and A2. No relaxation, no "qualified with caveats", no confidence-weighted pass.

**C26-A08 (missing required is explicit and named).** A1 and A2 decisions are `blocked` with `missing_required == ["rec-cp-0002@v1"]`, surfaced in the same response the receiving turn sees — not only in an operator log.

**C26-A09 (POSITIVE CONTROL).** A3: `delivered ⊇ {REQ-A@v2, REQ-B@v1, REQ-C@v3}`, decision `qualified`, `basis == ["rec-ga-0001@v2","rec-cp-0002@v1","rec-rv-0003@v3"]` exactly. `rec-if-0007` is delivered in A1/A2/A3 but appears in **no** basis list.

**C26-A10 (NEGATIVE — scope before budget).** `rec-xs-0006` appears in no attempt's `selected`, `emitted`, `delivered` or `omissions` set, consumes zero budget, and its content appears in no diagnostic surface reachable by `ap-scribe-01`. Its absence is a scope denial (visible in S3 denial counters), not a silent omission.

**C26-A11 (byte preservation).** `receipt.emitted_bytes_sha256 == host_received_sha256` for each acknowledged packet. `REQ-A`'s BOM and CRLF survive into the emitted stream. A `normalized_text_sha256` may also be recorded but is a *different* value and is never used as the delivery proof.

**C26-A12 (delivery state ≠ emission).** After T8, `pkt-A3-0003 → host-nimbus-b` has `delivery_state == "unknown"` (not `delivered`), and S5 for `turn-0003` on `host-nimbus-b` is not `qualified`.

**C26-A13 (retry idempotence).** After T9, that packet has one delivery record with `delivery_state == "acknowledged"`, `emission_attempts == 2`, an unchanged delivered-record set and an unchanged token count. No second semantic delivery, no duplicated receipt.

**C26-A14 (dedup inside the envelope).** `REQ-B` is reachable via two selection paths in A3; it is emitted once, listed once in `delivered_records`, and counted once toward the budget.

**C26-A15 (historical view survives).** At T10, A1's and A2's receipts, omission manifests and blocked decisions are byte-identical to what they were at T3/T5; A3's success does not rewrite or supersede them.

**C26-A16 (budget does not alter applicability).** S2 for `repo-quarry@rev-9f3c1a` is identical before T1 and after T9: `REQ-B` remained current and applicable throughout; being omitted from a packet is a delivery fact, not a lifecycle fact.

**C26-A17 (no truncated record passes as complete).** If any emitted record body is cut to fit, it carries `truncated == true`, is excluded from `delivered_records` for prerequisite-satisfaction purposes, and appears in `omissions` as `partial`. In this fixture no truncation is expected; a truncated-and-complete-looking `REQ-A` is a failure.

**C26-A18 (observability without leakage).** The attempt trace exposes budget, tokenizer id/version, selected/emitted/omitted sets, per-record token cost and scope-denial counts, and exposes no content or source bytes of `rec-xs-0006`.

## 6. Acceptable terminal shapes

For A1 the oracle accepts **either** `partial_with_manifest` (the arithmetic above) **or** `refused_incomplete` (nothing emitted, explicit incompleteness report). Both must satisfy A05–A08, A10, A15, A16. What is *not* accepted: emitting a packet that presents itself as complete, or an omission discoverable only by diffing the selection list against the bytes.

## 7. Failure classification

An A07 or A10 failure is an **immediate rejection** condition per the go/no-go criteria (authority-changing error / cross-scope disclosure). A01–A06, A11–A18 failures are correctness failures. Surfaces the product cannot expose are reported **unavailable**.

## Invariants (structured list, from the validation owner's return value)

- The token budget is evaluated over the exact byte stream emitted toward the receiving turn, counted with the declared tokenizer and version, never over pre-format record bodies.
- Framing overhead - preamble, per-record headers, omission manifest and footer - counts against the same budget as record content.
- An independent recount of the persisted emitted bytes under the declared tokenizer reproduces the reported delivered token count exactly.
- Every receipt names the tokenizer identity and version, and any conservative fallback is flagged and must over-estimate rather than under-estimate.
- Selected, emitted, delivered, acknowledged, omitted, unavailable and unknown are distinct states and the delivered set is derived from the emitted bytes rather than from the selection list.
- Every record that was selected but not emitted appears in the omission manifest with its id, version, required-or-optional role and a reason.
- No action is qualified while any required record is absent from the delivered set, regardless of how plausible the delivered substitutes are.
- A missing required record is named explicitly in the same response the receiving turn sees, not only in an operator-side log.
- A model-inference record may occupy budget and be delivered, but can never satisfy a required prerequisite or enter a qualification basis.
- Records outside the authorized scope are excluded before ranking and budgeting, consume zero budget, and appear in no delivery or diagnostic surface.
- The emitted-bytes hash recorded in the receipt equals the hash of what the host actually received, and any normalized-text hash is a separate value that is never used as delivery proof.
- Emission without acknowledgement yields delivery state unknown, which is not delivered and cannot qualify an action.
- Retrying the same packet identity reconciles to a single delivery with an unchanged delivered set and token count, never a second semantic delivery.
- A record reachable by two selection paths is emitted once, listed once and counted once.
- A record whose body is cut to fit is marked truncated, excluded from prerequisite satisfaction and reported in the omission manifest.
- Budget outcomes change delivery facts only; the current applicable view and record lifecycle are unchanged by a record being omitted from a packet.
- Receipts, omission manifests and blocked decisions from earlier attempts remain retrievable unchanged after a later attempt succeeds.
- Attempt diagnostics expose budget, tokenizer, per-record cost and scope-denial counts without revealing out-of-scope content or credentials.

## Instrument-can-fail controls

- Framing-overhead accounting OFF (budget counted over record bodies only, excluding preamble, per-record headers, manifest and footer): with dev A3 at budget 6000 the system will admit OPT-E (rec-tr-0005, 700 body) because body-only total reads 5500 <= 6000, while the actual emitted stream costs 6255 tokens; assertions C26-A01 and C26-A03 must then FAIL. If they still pass, the budget instrument is not measuring delivered bytes and the whole case is uninstrumented.
- Receipt-from-selection ON / receipt-from-emitted-bytes OFF (delivered list copied from the selection list instead of derived from the emitted stream): dev A2 and held-out B2 will report the formatter-dropped record (rec-cp-0002 / rec-sb-7703) as delivered; C26-A05 and C26-A06 (H05) must FAIL and C26-A07 (H04) must FAIL as the gate qualifies on a record never emitted.
- Required-vs-optional role distinction OFF (all context treated as optional / best-effort): dev A1 and held-out B1 will return a qualified decision with an empty missing_required list; the negative assertions C26-A07/C26-A08 (H04) must FAIL. This is the control proving the negative assertion is not passing for the wrong reason.
- Trust/evidence-class check OFF (model-inference records treated as equivalent evidence): rec-if-0007 / rec-in-7707 will be accepted as covering the missing authorization or prerequisite; C26-A07 and C26-A09's basis-exclusion clause (H04, H06) must FAIL. The held-out inference text is deliberately plausible and unmarked, so a label-only trust check will also fail here.
- Scope filter OFF (authorization applied after ranking, or not at all): rec-xs-0006 / rec-zz-7706 will be selected on lexical-semantic strength, consume budget and appear in the delivered set or diagnostics; C26-A10 (H07) must FAIL and C26-A01 arithmetic must shift. This control must be run against the vector, lexical, graph and exact-id paths separately.
- Deduplication OFF (a record reachable by two paths emitted or counted twice): dev A3's rec-cp-0002 and held-out B3's rec-cq-7702 appear twice; C26-A14 must FAIL and C26-A01/C26-A03 arithmetic must diverge from the expected 5855 / 4669.
- Byte preservation OFF (BOM stripped, CRLF normalized to LF, NBSP folded, trailing newline added before hashing or emitting): the emitted stream no longer matches the source bytes and the receipt's hash no longer matches the host-received hash; C26-A11 (H08) must FAIL. A variant of this control - hashing the normalized text but emitting the original bytes - must also make C26-A11 FAIL, proving the assertion compares the right two values.
- Delivery-state collapse ON (emitted treated as delivered, acknowledgement ignored): dev A4 / held-out B4 will report delivered immediately and may qualify the action on the secondary host; C26-A12 (H09) must FAIL.
- Retry idempotence OFF (each emission creates a new delivery record): dev A4 / held-out B4 will show two delivery records and a doubled token attribution; C26-A13 (H09) must FAIL.
- Tokenizer declaration OFF (substitute an undeclared heuristic such as characters-divided-by-four, or omit tokenizer_id/version): the independent recount will not reproduce the reported count and the receipt will lack a declared tokenizer; C26-A02 and C26-A04 must FAIL. A second variant - fallback tokenizer that under-estimates - must make C26-A04's over-estimation clause FAIL.
- Truncation marking OFF (over-long record silently cut to fit): shrink dev budget A3 to 5200 so rec-cp-0002 must be cut; the cut record must appear complete and count toward the prerequisite, making C26-A17 (H11) FAIL and C26-A07 FAIL by qualifying on a partial prerequisite.
- History immutability OFF (later attempt rewrites or supersedes earlier receipts): after dev A3 / held-out B3 succeeds, the A1/A2 (B1/B2) receipts and blocked decisions are altered or dropped; C26-A15 (H10) must FAIL.
- Lifecycle coupling ON (omission from a packet marks the record inapplicable or archived): the current applicable view loses rec-cp-0002 / rec-au-7701 after the over-budget attempt; C26-A16 (H10's second clause) must FAIL.
- Diagnostic access control OFF (operator trace bypasses scope filtering): the out-of-scope decoy's content appears in the attempt trace even though it was never delivered; C26-A18 (H12) must FAIL while C26-A10's delivery clause still passes - showing the two must be asserted separately.

## Open questions (structured list, from the validation owner's return value)

- The case says the token limit applies to 'actual delivered bytes' but does not say whether the authoritative measurement point is the sender's emitted stream or the host's received stream; this oracle requires both and asserts they are equal, which is stricter than the text strictly demands.
- When the required set alone cannot fit any budget allocation, the case does not choose between emitting a partial packet with an explicit manifest and refusing the packet whole; the oracle accepts either shape and asserts only the invariants common to both.
- R15 says the budget covers 'the entire injected envelope' but the case does not say whether host-supplied material outside the memory packet (system prompt, tool schemas, prior turns) counts toward the same limit; the fixtures scope the budget to the memory packet only.
- It is not stated whether the omission manifest itself is charged to the budget; the fixtures charge it, which is the conservative reading and affects the expected arithmetic.
- The case requires 'delivered-record receipts match reality' but does not define whether delivery requires host acknowledgement; the oracle treats unacknowledged emission as delivery state unknown, per R16's selected/emitted/delivered/unavailable distinction.
- For a conservative fallback tokenizer, no bound on acceptable over-estimation is given, and it is unspecified whether a packet must be re-costed once the true tokenizer becomes known.
- It is unspecified whether optional or inference-class context may consume budget while a required record is omitted; the fixtures allow it only when the required record could not fit at any allocation, and assert the qualification consequence regardless.
- Whether a delivered-but-truncated record counts partially toward a prerequisite is not addressed; the oracle treats partial as not-delivered for qualification purposes.
- The case does not say whether a repeated over-budget assembly must yield a stable packet identity or a fresh one; the fixtures only require stability across retries of the same packet, not across re-assemblies.
- 'Formatting adds overhead or omits a selected record' does not distinguish an intentional formatter policy from a defect; the oracle treats both identically at the observable level, which may understate the difference an operator would want reported.
