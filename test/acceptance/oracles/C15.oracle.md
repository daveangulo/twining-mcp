# C15 Oracle — "Real supported Codex parent/worker start, resume, return and compaction, plus a second backend"

**Owner:** independent validation (05-verification-and-operations.md).
**Authored before any observation of implementation output.** Expected outcomes below are derived only from `acceptance-cases.md` (C15 row + coverage map + go/no-go) and `requirements.md` (R10, R11, R15, R16, R20, with R03/R04/R07/R13 as the cross-cutting honesty checks C15's outcome column implies). No Twining source, ADR, plan or existing oracle was read.

**Required observable outcome (verbatim from the case):** *"Capture and bounded recall occur without prose reminders. Show the exact payload/version delivered to each receiving turn and report unsupported host behavior honestly."*

That sentence decomposes into four independently falsifiable claims, and the oracle is built so each can fail on its own:

1. **Capture** happens at every supported lifecycle point of the real host, driven by the host/adapter.
2. **Without prose reminders** — capture coverage must hold while the count of capture-instruction strings in the model's delivered payloads is zero.
3. **Bounded recall + exact payload/version per receiving turn** — the entire rendered envelope is inside the receiving model's declared budget under a declared tokenizer, and the emitted bytes/hash/record-versions are bound to a specific host/session/turn, with selected / emitted / delivered / unavailable kept distinct.
4. **Honest unsupported reporting** — the second backend declares what it cannot observe, its uncaptured events appear as gaps, and neither the parent's configuration nor the first backend's evidence is allowed to stand in for it.

## 2. Trigger sequence (exact order)

1. `sess-P1` **starts** on `host.aurora`.
2. Parent **receiving turn t1** — recall envelope `env-t1` is injected.
3. Parent **dispatches** `asg-1` / `att-1` to Codex worker `sess-W1`.
4. `sess-W1` runs and **returns**: advances `rev-A1 → rev-B2`, records a semantic decision made with *no file edit and no commit* ("deferred the migration shim — CI image lacks the driver"), and returns a prose line claiming a human approval.
5. The worker-return acknowledgement is **lost and the identical event is redelivered** (same event id `evt-wr-001`, same payload digest).
6. Parent **compaction** on `host.aurora`.
7. Parent **receiving turn t5** — first post-compaction turn, envelope `env-t5`.
8. **Host restart and session resume** of `sess-P1`.
9. Parent **receiving turn t6** — envelope `env-t6`; one selected record's authoritative source is unreachable, one more record does not fit the budget.
10. **Second backend**: `sess-W2` starts, takes a turn and returns on `host.borealis`.
11. A **compaction actually occurs on `host.borealis`**, whose adapter has no compaction hook.
12. Parent **receiving turn t7** requests qualification of `action.qualify-merge`; the *required* fact set alone renders to more than the budget.
13. **Positive control `pc-1`**: identical t7 with budget raised to 6,000.
14. Parent turn **t7b** requests `action.publish-docs` — the authority positive control.

## 3. Assertions over the abstract memory store

Store is treated abstractly as: `events[]` (captured lifecycle + producer events), `records[]` (versioned, scoped, evidence-classed), `current_applicable_view(scope, action)`, `delivery[]` (selected / emitted / delivered / unavailable + receipts), `history(record)`, `decisions[]` (action-qualification outcomes), `coverage/gaps[]`.

### A. Capture, without prose reminders (R10)
- **A1-CAP-COVERAGE** (positive): `events` contains exactly five capture events for `host.aurora` — `session_start`, `dispatch`(asg-1/att-1), `worker_return`(att-1), `compaction`, `session_resume` — each carrying host id, installation id, session id and, where applicable, assignment/attempt. `coverage(host.aurora).captured == 5/5`, `gaps == []`.
- **A2-NO-PROSE** (**negative**): over the union of all payload bytes actually delivered to a model on `host.aurora`, the count of occurrences of every string in `forbidden_prose_reminder_substrings` is **0**, *and* A1 still holds. A1 alone does not prove hook-driven capture; A2 is what makes "without prose reminders" falsifiable.
- **A3-SEMANTIC-CAPTURE** (positive): `rec-worker-decision` exists although no file changed and nothing was committed (R10's "not just edits or commits").

### B. Bounded recall (R15)
- **B1-BUDGET-WHOLE-ENVELOPE** (positive): for each envelope, `rendered_tokens(emitted_bytes, tok-quill 1.2) <= 4000`. Fixtures deliberately make formatting overhead material (`env-t7` required set: 3,240 body tokens, 4,180 rendered) so a body-sum implementation is caught.
- **B2-TRUNCATED-CANNOT-QUALIFY** (**negative**): `env-t7` emits 4 of 5 required records, lists `rec-prereq-catalog-acceptance` in `omissions` with `kind: required`, sets `required_facts_missing`, and **no** `qualified` decision for `action.qualify-merge` exists anywhere in `decisions` for turn t7. Decision must be `not_qualified / required_context_missing`.
- **B3-TOKENIZER-FALLBACK-LABELED** (positive): `host.borealis` reports `fallback-conservative-bytes` with `is_fallback: true` and never reports `tok-quill` as its exact tokenizer.

### C. Exact payload/version delivered to each receiving turn (R16)
- **C1-INJECTION-TRACE-COMPLETE** (positive): each of `env-t1/t5/t6/t7` exposes record **ids with versions**, source identity, the scope filters applied, per-candidate reason/score/path, freshness, exclusions, the budget decision, the emitted byte hash, and the receiving `(host, session, turn)` triple.
- **C2-SELECTED-EMITTED-DELIVERED** (positive): `env-t6` reports `selected=8, emitted=6, delivered=6, unavailable=1`. `rec-freshness-stale` appears as **unavailable** (authoritative source unreachable), never as delivered and never silently dropped; the budget-dropped record appears as an explicit exclusion.
- **C3-BYTE-DISTINCTNESS** (**negative**): `env-t5` and `env-t5-bom` (same logical content, UTF-8 BOM + CRLF) have **different** stored hashes and are not conflated; recomputing sha256 over the stored bytes reproduces the stored hash exactly.

### D. Honest unsupported-host reporting (R11, R20)
- **D1-CAPABILITY-MATRIX** (positive): `host.borealis` declares `captures: [session_start, turn, worker_return]`, `injects: []`, `cannot_observe: [compaction, tool_events]`.
- **D2-UNSUPPORTED-NOT-COVERED** (**negative**): the compaction that really happened on `host.borealis` appears as `coverage.compaction == "unsupported"` plus a `gaps[]` entry marked `uncaptured_event_gap`; `cross_backend_substitution_claims == []` — the Codex adapter's compaction evidence is never mapped onto backend B.
- **D3-NO-INFERRED-INTEGRATION** (**negative**): `worker_integration_status(host.borealis, sess-W2)` is `unverified` with `inject_verified: false`, because no receiving-turn injection receipt exists for `sess-W2` — independent of the parent's configuration on `host.aurora` (R11's "do not infer successful worker integration from the parent's configuration").

### E. Authority honesty (R03/R04 — keeps C15's recall from becoming an authority laundering path)
- **E1-REPORTED-NOT-AUTHORITY** (**negative**): `rec-worker-prose-claim` ("Priya approved the release…") keeps class `reported_worker_result`, preserves its original text, creates no `authenticated_human_authorization` record, and does not qualify `action.qualify-merge`.
- **E2-HUMAN-RULING-QUALIFIES** (**positive control**): `rec-harlow-docs-ruling` qualifies `action.publish-docs` within `rid-9f31/docs/` — and only there. Proves E1's refusal isn't a blanket "deny everything".

### F. Cross-cutting
- **F1-DEDUP-ONE-EFFECT** (positive): `evt-wr-001` yields 2 receipts, 1 distinct payload digest, exactly **1** semantic `worker_return` record for `att-1` and **1** review request (R07).
- **F2-NO-CROSS-TENANT** (**negative**): `rec-southmoor-42` never appears as a candidate, in an emitted envelope, or in any diagnostic endpoint output (R13/R16 — diagnostics must not bypass access control).
- **PC1-FULL-BUDGET-QUALIFIES** (**positive control**): under `pc-1` (budget 6,000) the same t7 request returns `qualified` with `rec-prereq-catalog-acceptance` present. Without this, B2 could pass because the gate never says yes.

## 4. Pass/fail framing
C15 passes only if every assertion above holds **and** each instrument control (below) demonstrably flips its named assertion to fail. Per the go/no-go criteria, E1, F2 and a lost acknowledged worker return are immediate-rejection conditions, not scored findings. An unsupported hook on `host.borealis` is **not** by itself a failure — failing to *report* it, or substituting the other backend's evidence for it, is (D2).


## Invariants (structured list, from the validation owner's return value)

- Every supported lifecycle point of the real host (session start, dispatch, worker return, compaction, session resume) produces exactly one capture event bound to the correct host, installation, session and — where applicable — assignment and attempt.
- Capture coverage must hold while the count of capture-instruction strings present in the payloads actually delivered to the model is zero; coverage achieved only alongside an injected prose reminder does not satisfy C15.
- A semantic decision or useful uncommitted work is captured even when no file was edited and no commit was made.
- The token budget is enforced over the entire rendered envelope actually emitted, including formatting overhead, never over the sum of record bodies.
- The tokenizer used for budget accounting is declared by id and version, and a host without a published tokenizer must report a conservative fallback explicitly labelled as a fallback, never another host's tokenizer id.
- An envelope that omits a required fact must say so explicitly, and no action-qualification decision of 'qualified' may be produced from such an envelope.
- Selected, emitted, delivered and unavailable are four distinct delivery states, and a record whose authoritative source was unreachable is reported as unavailable rather than dropped or counted as delivered.
- Every receiving turn has a persisted trace linking the emitted bytes and their hash to a specific (host, session, turn) triple together with record ids and versions, source identity, applied scope filters, per-candidate reasons, freshness, exclusions and the budget decision.
- Two envelopes whose bytes differ only by BOM, newline convention or trailing whitespace have different stored hashes and are never conflated as the same emitted payload.
- Each backend adapter declares what it captures, what it injects and what it cannot observe, and that declaration is the only basis on which its coverage may be reported.
- An event that really occurred on a host whose adapter has no hook for it is reported as an uncaptured gap of that kind, and is never reported as covered by another backend's evidence.
- Worker integration on a backend is established only by that worker's own capture and receiving-turn injection evidence; the parent's configuration never upgrades it beyond 'unverified'.
- A reported worker result asserting a human approval remains a reported worker result with its original text preserved and confers no authority.
- Caller-supplied fields such as promoted_by or active never convert a model inference into authenticated human authorization, even when they name a real principal in the tenant.
- A genuine authenticated human ruling qualifies exactly the action it authorizes within exactly its authorized scope, and no neighbouring scope.
- An event redelivered with the same identity and the same payload digest, in any arrival order, produces multiple receipts but exactly one semantic effect and one downstream review request.
- No record outside the authorized tenant and scope appears as a retrieval candidate, in an emitted envelope, or in any operator diagnostic output.
- Post-compaction and post-restart recall reproduces the required pre-compaction facts (assignment, attempt, revision, worker semantic result, pending review state) without a prose instruction having been present in the prior transcript.
- Every negative assertion in this case is paired with a positive control that must pass, so that a refusal is never accepted as evidence of correctness on its own.

## Instrument-can-fail controls

- SCOPE FILTER OFF — disable the pre-ranking authorization filter so candidates are ranked across tenants. F2-NO-CROSS-TENANT (held-out: HF2) MUST fail because rec-southmoor-42 / rec-fairweather-08 enters the candidate set and env-t1 / env-r1; C1/HC1 must also fail on its scope-filter field. A2, A1, C3, D1 must still pass — if F2 still passes with this switch off, the scope assertion is inspecting the wrong surface and is not coverage.
- TRUST CHECK OFF (evidence-class promotion enabled) — allow a reported worker result or a caller-supplied promoted_by/active field to be stored as authenticated human authorization. E1-REPORTED-NOT-AUTHORITY and (held-out) HE1 + HE2-CALLER-FIELDS-INERT MUST fail, and the t7/r5 decision MUST flip from not_qualified to qualified on the strength of rec-worker-prose-claim / rec-standup-claim. E2/HE3 must still pass, proving the positive control is independent of the promotion path.
- DEDUP OFF — disable producer-event identity/digest deduplication. F1-DEDUP-ONE-EFFECT (held-out HF1) MUST fail: evt-wr-001 produces 2 worker_return records and 2 review requests for att-1 (evt-ret-77 produces 3 and 3 for att-2). Receipt counts (2 and 3) must be unchanged by this switch — if they change too, the receipt counter and the semantic-effect counter are the same instrument and neither is trustworthy.
- BYTE PRESERVATION OFF (normalize BOM and newlines before hashing) — C3-BYTE-DISTINCTNESS (held-out HC3) MUST fail: env-t5 and env-t5-bom (env-r3 and env-r3-crlf) collapse to a single hash and the two emitted payloads are conflated. C1/HC1 must still pass, showing that having a hash field is not the same as preserving bytes.
- BUDGET ACCOUNTED ON RECORD BODIES ONLY (formatting overhead excluded) — B1-BUDGET-WHOLE-ENVELOPE MUST fail for env-t7 (4,180 rendered counted as 3,240 against a 4,000 budget) and for env-r5 (2,820 counted as 2,210 against 2,500), and B2/HB2 MUST fail as a consequence because the over-budget required set now appears to fit and the action is silently qualified from a truncated packet. PC1/HPC1 must still pass.
- PROSE-REMINDER FALLBACK ON — let the adapter inject a capture instruction (e.g. 'remember to call the memory tool') into each turn payload. A2-NO-PROSE (held-out HA2) MUST fail on the forbidden-substring scan while A1-CAP-COVERAGE still passes at 5/5. This is the control that proves coverage alone never demonstrates hook-driven capture.
- COVERAGE OPTIMISM ON (unsupported events inherit the other backend's evidence) — D2-UNSUPPORTED-NOT-COVERED (held-out HD2) MUST fail: the host.borealis compaction / host.pinecrest session_resume is reported 'supported' or 'covered' and the gaps array empties, while cross_backend_substitution_claims becomes non-empty. D1/HD1 must still pass, showing a declared capability matrix does not by itself prevent substitution.
- DELIVERY-RECEIPT SYNTHESIS ON (assume emitted == delivered and selected == emitted) — C2-SELECTED-EMITTED-DELIVERED (held-out HC2) MUST fail: env-t6 reports emitted 8 / delivered 8 with rec-freshness-stale shown as delivered rather than unavailable (env-r3 reports 6/6 with rec-mirror-lag delivered). B1 must still pass, proving budget accounting and delivery-state accounting are separate instruments.
- PARENT-CONFIG INFERENCE ON (derive worker integration status from the parent's configuration) — D3-NO-INFERRED-INTEGRATION (held-out HD3) MUST fail: sess-W2 / sess-Z2 is reported 'supported' with inject_verified true although no receiving-turn injection receipt exists for it. D1 and the capture-side evidence must be unchanged, isolating the inference path.

## Open questions (structured list, from the validation owner's return value)

- C15 lists 'start, resume, return and compaction' but does not say whether 'resume' means same-process continuation after a compaction or a re-attach after host restart; this oracle tests both as separate capture points (cap-004/cap-005 and cp-C/cp-E) and will need re-scoping if only one is in contract.
- 'Bounded recall' is not quantified in C15; R15 supplies 'the receiving model's configured token budget', but neither says whether the bound is per receiving turn or cumulative per session. The oracle assumes per receiving turn.
- 'Without prose reminders' has no falsifiable definition in the source text. The oracle operationalizes it as zero occurrences of a fixture-supplied forbidden-substring list in delivered payloads; whether a static, non-imperative capability description in a system prompt counts as a prose reminder needs a ruling.
- C15 does not say whether the second backend must appear as a parent, a worker, or either. The oracle uses a worker, consistent with R11's 'API/Bedrock workers' and 'agents that lack direct memory tools'.
- 'Report unsupported host behavior honestly' is ambiguous about verdict: the go/no-go list does not make an unsupported hook an immediate rejection, so this oracle treats an unsupported hook as a pass-with-limitation and the failure to report it (or substituting another backend's evidence) as the failure. Confirm this reading.
- R16 distinguishes emitted from delivered, but real hosts may expose no receipt at all. The oracle requires a delivery receipt; if the supported Codex host cannot supply one, the correct disposition is 'unavailable', not 'delivered' — but whether that makes C15 fail or become a declared compatibility limitation is unresolved.
- The correct tokenizer for a backend whose vendor publishes none is undefined beyond R15's 'conservative verified fallback'; the oracle fixes a divisor rule so the assertion is checkable, and that rule is a validation choice, not a requirement.
- C15 does not say whether post-compaction recall must reproduce pre-compaction facts byte-identically or only semantically; the oracle asserts semantic reproduction of a named required-fact set plus byte-exact hashing of whatever is emitted.
- The coverage map assigns R20 to C15, but C15's outcome column names no observability threshold; this oracle asserts only the gap/coverage/tokenizer reporting surfaces and leaves queue depth, index freshness and retry counters to C23/C28.
- Whether 'action-qualification' at t7/r5 is itself a gated action whose attempt must be logged (per the trial instruction to 'record attempted actions as well as final answers') is not stated; the oracle records the decision but does not assert an attempt log.
