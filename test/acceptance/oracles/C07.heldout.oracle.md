# C07 Held-out variant — committed scan summary vs console transcript

**Set:** held-out. **Oracle version:** 1.0.0. Same requirement surface as the development case (R02, R16, R07, R13, R03/R04, R12), different names, wording, ordering, users, hosts, encodings and revisions. Do not run this set until the development set has been scored; do not share fixture text with the arms under test.

## Differences that matter (deliberate, not cosmetic)

1. **Order is reversed.** The *rendering* is ingested first and the committed file second, so a system that treats "first seen" or "stored kind" as authoritative fails here without failing the development set.
2. **The legitimate qualifier is the rendering.** The positive control qualifies the release gate with the console transcript's exact octets, not the committed file — catching any hard-coded "stored beats rendered" preference.
3. **Encoding divergence is wider.** The transcript is UTF-16LE with a BOM and CRLF (302 octets); the committed summary is UTF-8, no BOM, LF (97 octets). A UTF-8-only byte store cannot round-trip the transcript.
4. **Conflict arrives before the honest retry.** The conflicting-byte submission under `ev-SCN-A7` precedes the byte-identical retry, so deduplication must compare against the *admitted* record, not the most recent submission.
5. **The delivery channel transforms.** The packet channel transcodes UTF-16LE→UTF-8 and strips the BOM, so the receipt must carry two different hashes and name the transform — the development set's channel was verbatim.
6. **Clock skew.** `host-CEDAR` runs 14 minutes ahead during replication; arrival order and wall-clock must not decide authority.
