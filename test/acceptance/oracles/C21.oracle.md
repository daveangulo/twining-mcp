# C21 Oracle — Migrate legacy stores; write new-format records; interrupt and roll back

**Status:** authored from `acceptance-cases.md` (C21 row), `requirements.md` (R02, R03, R19 per the coverage map; R05, R07, R08, R16 where the case's observable surfaces touch them) and `05-verification-and-operations.md` (Migration and rollback section). No Twining source, ADR, plan or existing oracle was read. Expected outcomes below are derived from the requirement text only.

**Case text under test:** *"Migrate legacy stores; write new-format records; interrupt and roll back → Preserve recoverable bytes/IDs/relationships and post-upgrade records. Mark legacy authority ambiguity. Old clients cannot corrupt unknown semantics; rollback and subsequent forward recovery are tested."*

---

## 1. Abstract memory store model (the surfaces assertions read)

The system under test is treated as a black box exposing five observable surfaces. Every assertion below is written against these and nothing else.

| Surface | Read operation assumed available |
| --- | --- |
| **S1 Events/records** | `get(record_id)` → envelope (bytes, hashes, encoding, source URI/anchor/kind, git identity, author, observer, times, scope, version, evidence class, lifecycle); `list(store)` |
| **S2 Current applicable view** | `current(scope)` → the set of records the system would treat as in force now |
| **S3 Delivery/receipt states** | `receipts(record_id)` → distinct `selected / emitted / delivered / unavailable` states, emitted-bytes hash, receiving host+session+turn |
| **S4 Historical view** | `history(record_id)` → prior lifecycle states, superseded/archived/retracted pointers, original asserted field values |
| **S5 Action-qualification decisions** | `qualify(action, scope, cited_records)` → `QUALIFIED` / `DENIED(reason_code)` |
| **S6 Operator observability** | migration state, dry-run report, conflicts, schema-negotiation events, rollback report |

If the implementation exposes no equivalent of a surface, that is reported as **unavailable**, never as passed (05-verification, Final report).

## 2. Synthetic identities

- **Tenant:** `tenant-quarrystone`
- **Humans:** `human:mira.oyelaran` (can produce independently verifiable authorization evidence), `human:tobias.renk` (author of a legacy note, no authentication evidence)
- **Service principals:** `agent:scribe-01` (migrator), `agent:drifter-02` (post-upgrade writer)
- **Hosts/installations:** `host-hollowmere` (upgraded, schema 3), `host-fenwick` (old client, schema 1 maximum)
- **Stores:** `store-legacy-A` (file-backed JSON, schema 1), `store-legacy-B` (SQLite + export dump, schema 2), `store-new` (target, schema 3), `archive-retained` (versioned retained event archive)
- **Repository:** `repo-masonry` (display name `masonry-core`), cloned at two paths — one repository identity
- **Revisions:** `REV_BASE`, `REV_HEAD` (pre-migration), `REV_POST` (written after migration); frozen at fixture build
- **Sessions/turns:** `sess-hollowmere-11 / turn-4`, `sess-fenwick-03 / turn-1`

Byte fixtures are written in token notation (`<BOM>`, `<CRLF>`, `<LF>`). **Fixture build expands the tokens, computes every hash, and freezes them into `manifest.json`. Assertions compare against the frozen manifest, never against a hash written by hand in the oracle.** This keeps the oracle independent of the implementation's hashing choices while still being exact.

### Seed records (see `fixtures_json` for full envelopes)

`L-001` legacy decision with `active:true`, `actor:"mira.oyelaran"`, `promoted_by:"system"`, body carrying a UTF-8 BOM and CRLF line endings, whose prose asserts a human approval with no authentication evidence · `L-000` superseded · `L-002` archived, supersedes `L-000` · `L-003` provisional with ambiguous extraction · `L-004` missing observer and observation time · `L-003-conflict` an export row declaring the same record id as `L-003` with different bytes · `L-006` unpublished dirty draft · `L-007` lesson with no embedding · `L-008` truncated export row.

### Post-upgrade records (schema 3, semantics schema 1/2 cannot represent)

`N-101` multi-part authenticated human authorization (part-A granted, part-B withheld) · `N-102` partial supersession of `N-101` part-B · `N-103` observation whose four hash fields (source bytes, git object id, normalized text, rendered output) must all differ.

## 3. Trigger sequence (exact order)

| Step | Trigger |
| --- | --- |
| T0 | Build fixtures; freeze `manifest.json` (bytes, all hashes, encoding, lifecycle, relations, evidence class, published flag) over both legacy stores |
| T1 | Snapshot legacy store bytes on disk |
| T2 | **Dry-run** migration over both legacy stores |
| T3 | Real migration as `agent:scribe-01`; **SIGKILL the migrator process** after records land in `store-new` but before index build and before the ID-map commit |
| T4 | Restart; resume/rerun migration to completion |
| T5 | Run migration a **third** time against the same sources |
| T6 | Write `N-101`, `N-102`, `N-103` as `agent:drifter-02` on `host-hollowmere`; emit `N-101` into `sess-hollowmere-11 / turn-4`, recording selected/emitted/delivered and the emitted-bytes hash |
| T7 | Connect `host-fenwick` (schema 1): (a) read `N-101`; (b) write a schema-1 update to `N-101` omitting every unknown field; (c) write `active:true` onto the migrated `L-001` successor |
| T8 | **Roll back** to the pre-upgrade implementation and schema; post-upgrade records go to `archive-retained` plus an explicitly restricted legacy view |
| T9 | While rolled back: list and inspect `archive-retained`; collect the unavailable-functionality report; repeat T7b and T7c from `host-fenwick` |
| T10 | **Roll forward**: re-upgrade and re-import `archive-retained` |
| T11 | Re-import `archive-retained` a second time |
| T12 | Qualification requests — **Q1** in-scope citing `N-101`; **Q2** in-scope citing migrated `L-001`; **Q3** scope `repo-masonry/ops/` citing `N-101`; **Q4** Q1 repeated while rolled back |

A separate **clean control run** (uninterrupted migration of the same manifest into a fresh store) is executed for comparison at T4.

## 4. Assertions

Polarity key: **[+]** positive, **[−]** negative (must be false / must be refused), **[PC]** positive control.

### S1 — Events and records

- **A-REC-01 [+] Byte preservation.** For every record in `manifest.json`, `get(id).source_bytes_sha256` equals the frozen manifest value. For `L-001` the stored bytes begin with `EF BB BF` and every line terminator is `0D 0A`. (R02, R19)
- **A-REC-02 [+] Hash distinctness.** For `L-001` and `N-103`, `source_bytes_sha256 ≠ normalized_text_sha256 ≠ rendered_output_sha256 ≠ git_object_id`; no field is a copy of another and none is null-filled. (R02)
- **A-REC-03 [+] Stable ID mapping.** The legacy→new ID map is total over migrated records and injective; `resolve(legacy_id)` and `resolve_back(new_id)` round-trip; the map after T4, after T5 and from the clean control run are identical. (R19)
- **A-REC-04 [+] Relationships preserved.** The post-migration relation set equals the manifest relation set exactly — `L-002 supersedes L-000` present; no relation exists that is absent from the manifest. (R19, R06)
- **A-REC-05 [−] Unknown stays unknown.** `get("L-004").observer` is `unknown` and **is not** `agent:scribe-01`; `observation_time` is `unknown` and **is not** the migration timestamp or `T0`. (R02, 05-verification "never invent missing provenance")
- **A-REC-06 [−] Legacy authority ambiguity marked.** `get("L-001").evidence_class` is a legacy/unverified class **and is not** `authenticated_human_authorization`; an `authority_ambiguous` marker is set and is readable through the same API that serves the record for injection, not only in storage. (R03, R19)
- **A-REC-07 [−] No promotion from caller-controlled fields.** No record in `store-new` has an authenticated-human-authorization evidence class whose only support is a legacy `active`, `actor` or `promoted_by` value. The original three values survive verbatim as asserted-provenance fields. (R03)
- **A-REC-08 [+] Dirty work preserved.** `L-006` exists post-migration with `published=false` and manifest-identical bytes. (05-verification "Preserve dirty/unpublished work")
- **A-REC-09 [+/−] Conflict quarantined.** `L-003` and `L-003-conflict` are both retained with both byte streams; the pair is flagged as a conflict; **neither** is present in `current(scope)` as the resolved value. (R07, R19)
- **A-REC-10 [+] Derived-index rebuild is not data loss.** `L-007` is retrievable by exact ID after the rebuild; the embedding absence is labeled, not silently imputed. (R19)
- **A-REC-11 [+] Truncation is not reconstruction.** `L-008` is quarantined with its recoverable bytes; no field of it carries guessed content; the migration report names it. (R17-adjacent, R19, C21 "recoverable")

### S2 — Current applicable view

- **A-CUR-01 [+]** After T10, `current("repo-masonry/catalog/")` contains `L-001` (legacy-unverified class), `L-002` (archived marker), `N-101 part-A`.
- **A-CUR-02 [−]** `current(...)` contains none of: `L-000` (superseded), `L-003-conflict`, `L-008`, `N-101 part-B` (partially superseded by `N-102`).
- **A-CUR-03 [−] Rollback does not re-label.** During T8–T9 the legacy view never serves `N-101` as an ordinary legacy record with `active:true`. (R19 "never upgrade legacy active into authenticated human authorization" — and its converse, never downgrade-in-place either)

### S3 — Delivery and receipt states

- **A-DEL-01 [+]** `receipts("N-101")` at T6 distinguishes `selected`, `emitted`, `delivered` as separate states and carries the emitted-bytes hash bound to `host-hollowmere / sess-hollowmere-11 / turn-4`. (R16)
- **A-DEL-02 [+]** After T10 the same receipt is still `delivered`, with the **same** emitted-bytes hash; no duplicate emission and no reversion to pending. (R08, R16)
- **A-DEL-03 [−] No silent acknowledged-event loss.** The count of acknowledged events before T8 equals the count recoverable after T10; no acknowledged event id present before T8 is absent afterwards. (R07 rejection condition)

### S4 — Historical view

- **A-HIST-01 [+/−]** `history("L-000")` returns the superseded lifecycle and the `superseded_by` pointer; `L-000` is simultaneously **absent** from `current(...)`.
- **A-HIST-02 [+]** Migration alters no legacy lifecycle state: `L-002` remains **archived, not revoked**; `L-003` remains provisional, not promoted. (R05, R19)
- **A-HIST-03 [+]** `history("L-001")` returns the original asserted `active/actor/promoted_by` values verbatim alongside the not-independently-checked marking. (R03)

### S5 — Action-qualification decisions

- **A-ACT-01 [PC] Positive control.** `qualify(publish_catalog_output, "repo-masonry/catalog/", cite=N-101)` → `QUALIFIED`, after T10, citing part-A.
- **A-ACT-02 [−]** `qualify(publish_catalog_output, "repo-masonry/catalog/", cite=L-001)` → `DENIED` with a reason naming legacy/unverified authority ambiguity. `L-001` remains retrievable and historically visible — denial is not deletion. (R03, R04)
- **A-ACT-03 [−]** `qualify(publish_full_story, "repo-masonry/catalog/", cite=N-101)` → `DENIED`; part-B was withheld and then partially superseded. (R06)
- **A-ACT-04 [−] Scope boundary.** `qualify(any_action, "repo-masonry/ops/", cite=N-101)` → `DENIED` with a scope reason, before and after T10. (R13)
- **A-ACT-05 [−] Rollback honesty.** Q4 → `DENIED` with reason *functionality unavailable while rolled back*, **not** *no such record* and **not** a silent `QUALIFIED`. (05-verification "Report functionality unavailable during rollback separately from data preservation")

### Interruption, idempotency and dry run

- **A-INT-01 [+]** After the T3 SIGKILL, every record present in `store-new` is complete and passes envelope validation — no half-written record. Migration state reads `incomplete`; it does not read `complete`. (R07 atomicity/recovery)
- **A-INT-02 [+]** The T4 resume result equals the clean control run on record content, hashes, relations and ID map. (R19)
- **A-INT-03 [−] Idempotent rerun.** After T5, migrated record count equals the manifest count exactly; no duplicate legacy id appears twice in `store-new`; no new id is minted for an already-migrated record. (R07, 05-verification "idempotent rerun")
- **A-DRY-01 [+/−]** After T2, `store-new` record count is `0` and the legacy store on-disk bytes are unchanged against the T1 snapshot; the dry-run report names the `L-003` conflict and the `L-008` truncation — the same findings the real run reports. (05-verification "dry-run diagnostics")

### Old clients and schema negotiation

- **A-OLD-01 [+]** T7a returns either a refusal or a view explicitly labeled incomplete/restricted. It never returns `N-101` presented as a complete record. (R19 "old-client behavior")
- **A-OLD-02 [−] No corruption of unknown semantics.** After T7b, `get("N-101")` has the same bytes, same hash and the same set of schema-3-only fields (`parts`, `part_status`, authentication evidence) as at T6. The old-client write is either refused or landed in a separate non-authoritative lane; it is never merged in place. (C21, R19)
- **A-OLD-03 [−] No authority change from an old client.** After T7c, the evidence class of every affected record equals its pre-T7 value. (R03, R17)
- **A-OLD-04 [+]** A schema-negotiation event is observable for T7 and again for T9: client max `1`, server `3` (then `1` while rolled back), outcome `refused` or `restricted-read-only`. (R19)

### Rollback and forward recovery

- **A-RB-01 [+]** After T8, `N-101`, `N-102`, `N-103` exist in `archive-retained` with bytes and hashes identical to T6. (05-verification "Rollback includes new writes after migration")
- **A-RB-02 [+]** During T9 the archive is **inspectable**: listing returns three entries with ids, hashes and schema version, and each entry's bytes can be read out. An archive that cannot be inspected does not qualify. (05-verification, explicit)
- **A-RB-03 [+]** The rollback report has a data-preservation section and a separate, non-empty unavailable-functionality section (expected to include multi-part authorization, partial supersession and four-hash envelope queries).
- **A-RB-04 [−]** A plain restore that loses post-upgrade records fails this case: assert `archive-retained` is non-empty and its contents are not a subset that omits any of `N-101..N-103`.
- **A-FR-01 [+]** After T10, `N-101`, `N-102`, `N-103` are back in `current`/`get` with identical ids, bytes, all four hashes, relations, evidence classes; provenance records that they were re-imported from the archive. (05-verification "lossless forward recovery")
- **A-FR-02 [+]** `N-102`'s partial supersession is restored with the same scope and the same target part; no part other than part-B changed status. (R06)
- **A-FR-03 [−]** T11 (second re-import) adds no duplicate record and creates no second receipt for `N-101`. (R07)

## 5. Verdict rule

C21 **passes** only if every assertion above holds **and** every instrument control in `instrument_controls` demonstrates the paired failure when its switch is disabled. Any of A-REC-06, A-REC-07, A-OLD-02, A-OLD-03, A-ACT-01..05 or A-DEL-03 failing is an *immediate rejection* under the go/no-go criteria (authority-changing error, unauthorized action, silent loss of an acknowledged event) — not a scored deduction. Surfaces the implementation does not expose are reported **unavailable**, never converted to passed.

## Invariants (structured list, from the validation owner's return value)

- Every migrated record's stored source bytes hash equal to the pre-migration frozen manifest value, including byte-order marks and line terminators.
- Source-byte hash, git object identity, normalized-text hash and rendered-output hash are four distinct values and none may be substituted for, copied from, or null-filled by another.
- The legacy-to-new identity map is total over migrated records, injective, reversible, and identical across a resumed run, a rerun and a clean control run.
- The post-migration relation set equals the pre-migration relation set exactly: no relation is dropped and no relation is invented.
- Metadata that is missing before migration remains explicitly unknown after it and is never filled with the migrator's identity or the migration clock.
- A legacy record carrying an authority-shaped claim is marked with an unverified evidence class and an authority-ambiguity flag that travels with it into whatever is served for injection.
- A legacy active, actor or promoted_by value never becomes, or contributes support to, an authenticated human authorization.
- Unpublished or dirty legacy work survives migration with its bytes and its unpublished status intact.
- Two source rows declaring the same record identity with different bytes are retained as an explicit conflict and neither is admitted into the current applicable view.
- A truncated or malformed source row is quarantined with only its recoverable bytes and never has its missing content reconstructed.
- Rebuilding a derived index is never a reason for an original evidence record to become unretrievable by exact identity.
- After an uncontrolled kill of the migrator, every record present in the target is complete and the migration state reports itself incomplete rather than complete.
- Re-running a completed migration adds no record, duplicates no identity, and mints no new identity for an already-migrated record.
- A dry run writes nothing to the target, leaves the source bytes unchanged, and reports the same conflicts and defects the real run reports.
- An old client that cannot represent newer semantics is refused or served an explicitly restricted view, and never receives a newer record presented as complete.
- An old client write can neither drop fields it does not understand from a stored record nor change any record's evidence class.
- Every schema negotiation between a client and the store is recorded as an observable event with both declared versions and the outcome.
- Records written after the upgrade survive a rollback intact in a versioned retained archive that can be listed, read and re-imported while the system is rolled back.
- A rollback report states data preservation and unavailable functionality as separate sections, and unavailable functionality is never reported as data loss or as record absence.
- Forward recovery restores post-upgrade records with identical identities, bytes, all hashes, relations and evidence classes, and re-importing a second time creates no duplicate.
- Delivery evidence distinguishes selected, emitted, delivered and unavailable, and a delivered receipt survives rollback and forward recovery with the same emitted-bytes hash, unduplicated and not re-queued.
- The count of acknowledged events before rollback equals the count recoverable after forward recovery.
- Neither rollback nor forward recovery resurrects a record that a tombstone retracted, while the retracted record stays visible in the historical view with its retraction attached.
- Archival and supersession states are preserved unchanged by migration: archived is not revocation and provisional is not promotion.
- An action is qualified only by an in-scope record of a sufficient evidence class; scope, evidence class and rollback-unavailability each produce a distinct, stated denial reason.

## Instrument-can-fail controls

- Byte preservation OFF (migrator normalizes line endings and strips the BOM): A-REC-01 must fail on L-001 / K-19 with a hash mismatch against the frozen manifest, and A-REC-02 must fail because normalized_text_sha256 becomes equal to source_bytes_sha256. If both still pass, the byte assertions are reading a re-derived value rather than stored bytes and the whole byte-preservation result is void.
- Scope filter OFF (authorization applied after ranking, or not at all): A-ACT-04 / R3 must flip from DENIED to QUALIFIED for the out-of-scope action, and at least one out-of-scope record must appear in current(scope). If the out-of-scope request is still denied with the filter disabled, the denial is coming from some other cause and A-ACT-04 proves nothing.
- Trust check OFF (evidence-class promotion enabled, legacy active treated as authorization): A-REC-06, A-REC-07 and A-ACT-02 / R2 must all fail — L-001 / K-19 acquires an authenticated-human-authorization class and qualifies the in-scope publish action. If A-ACT-02 still denies, the denial is not evidence-class-driven and the authority assertion is not actually instrumented.
- Deduplication / idempotency key OFF (migration not keyed on stable identity): A-INT-03 must fail with migrated record count at roughly twice the manifest count after the third run, and A-REC-03 must fail because the ID map stops being injective or mints new ids on rerun. Also A-FR-03 must fail: the second archive re-import creates a duplicate record and a second receipt.
- Old-client guard OFF (schema negotiation disabled, permissive write accepted): A-OLD-02 must fail — N-101 / P-77 loses its schema-3/4-only fields after the old client's write — and A-OLD-04 must fail because no negotiation event is recorded. A-OLD-03 must fail if the guard also gated evidence-class writes.
- Retained-archive OFF (rollback performed as a plain restore of the pre-upgrade backup): A-RB-01, A-RB-02 and A-FR-01 must all fail — post-upgrade records are absent from the archive and unrecoverable after roll-forward — and A-DEL-03 must fail on the acknowledged-event count. This is the control that proves the rollback assertions are not passing merely because nothing was written after migration.
- Unknown-preservation OFF (missing provenance defaulted to the migrator identity and the migration timestamp): A-REC-05 must fail on L-004 / K-23, whose observer becomes agent:scribe-01 / agent:kestrel-7 and whose time becomes the migration clock. If it still passes, the assertion is reading a display default rather than the stored field.
- Crash-fidelity control (replace the SIGKILL with a graceful shutdown): A-INT-01 must be treated as void, not passed. The harness must independently verify the migrator died on signal 9 with no clean-shutdown marker written; if the interruption assertions pass identically under a graceful close, they are not testing a durability boundary and the interruption coverage is withdrawn.
- Conflict detection OFF (last-writer-wins on duplicate declared record ids): A-REC-09 / K-24 must fail — one body silently becomes current and the other disappears — and A-DRY-01 must fail because the dry run no longer reports the conflict. A conflict assertion that still passes with detection disabled is reading a fixture label, not system behavior.
- Receipt-state instrumentation OFF (selected/emitted/delivered collapsed to a single boolean): A-DEL-01 must fail to distinguish the three states and A-DEL-02 must fail to compare emitted-bytes hashes across rollback. This proves the delivery assertions are reading real receipt state rather than an inferred present/absent flag.
- Tombstone enforcement OFF (held-out only, retraction treated as a soft hide): the K-22 exclusion assertion must fail after U8 and again after U10, with K-22 resurrected into current serving. If it stays excluded with enforcement disabled, exclusion is an artifact of the re-import path and the tombstone assertion is not instrumented.
- Manifest-freeze control (recompute the expected hashes from the post-migration store instead of the pre-migration manifest): every byte and hash assertion must become trivially passing. Any assertion that continues to fail under this substitution is correctly anchored; any that starts passing where it previously failed reveals an assertion wired to the system under test rather than to the frozen oracle.

## Open questions (structured list, from the validation owner's return value)

- C21 says 'interrupt and roll back' without saying whether these are one sequence (roll back the interrupted migration) or two independent tests (interrupt a migration; separately roll back a completed one). This oracle tests both, with the interruption before completion and the rollback after post-upgrade writes; if the programme intends only one reading, the unused half should be re-scoped rather than scored as a failure.
- 'Preserve recoverable bytes' does not define recoverable. This oracle treats a truncated export row's surviving prefix as recoverable-and-must-be-retained-in-quarantine; an alternative reading is that an unparseable row may be dropped if reported. Which reading governs changes the verdict on the truncated fixture.
- 'Mark legacy authority ambiguity' does not fix the granularity or the surface. This oracle requires both a per-record evidence class and an ambiguity flag, and requires the flag to survive into the injection-serving path, not just storage. If storage-only marking is acceptable, that must be stated before the run.
- 'Old clients cannot corrupt unknown semantics' does not choose between outright refusal and acceptance into a quarantined non-authoritative lane. R19 requires old-client behavior to be specified but not which behavior. The oracle accepts either and asserts only visibility plus non-corruption.
- Whether post-upgrade records must be readable through the restricted legacy view during rollback, or only retained and inspectable out of band, is unresolved. 05-verification requires 'an explicit restricted legacy view' and 'access to the retained records' without saying they are the same access path.
- Whether the rollback's unavailable-functionality report must be machine-readable (for automated assertion) or may be prose is unspecified. This oracle asserts a structured, separable section; a prose-only report would pass the spirit and fail the assertion as written.
- C21 is silent on whether delivery and receipt evidence for packets emitted before rollback must survive rollback. R08 and R16 imply yes, so this oracle asserts it; if the programme regards receipts as operational telemetry rather than record state (R20 says telemetry is not an immutable authority record), that assertion should move to an advisory finding.
- 'Roll back' is not decomposed into schema rollback, software-version rollback, or both. The oracle rolls both back together; a system that supports only one would need its partial support reported as unavailable rather than failed.
- No corpus tier is bound to C21. The go/no-go criteria require tested restore/rollback within 30 minutes at the declared pilot corpus and the trial design names 1,000 / 10,000 / 100,000 records; which tier C21's timing is judged at must be fixed before the measured run.
- It is unstated whether a schema-negotiation refusal counts as an 'unavailable' result or a 'passed' result for the old-client assertions. This oracle counts a recorded, explicit refusal as a pass; silent success and silent failure both fail.
