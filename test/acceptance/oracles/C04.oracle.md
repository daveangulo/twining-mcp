# C04 Oracle — "Same display name, archived vs current, different immutable revisions and bytes"

**Authority for expected outcomes:** `acceptance-cases.md` C04 row; `requirements.md` R01, R02, R12, R13 (the coverage map lists C04 under exactly these four), with R05/R15/R16 touched where the case needs lifecycle, budget and delivery evidence. Nothing here is derived from any implementation, source tree, ADR or existing oracle.

**One-line restatement:** two memory records carry the *same human-readable display name* for the *same logical artifact*; one is archived and one is current; they sit at different immutable source revisions and hold different exact bytes. A third record in an unauthorized scope carries the *same display name and byte-identical content*. The system must retrieve each by exact identity/scope, keep their source hashes and provenance distinct, keep the historical context of the archived one, never widen scope, and never let a stale record qualify an action that needs live source state.

## 6. Vacuity guards

Every negative assertion is paired with a liveness precondition that must be checked **first** and recorded in the result: the store contains `REC-A01`, `REC-A02`, `REC-A03`, `REC-A04`, `REC-A05`, `EV-A10`, `GRANT-X`; `Q3` returns ≥3 records for `agent:scribe-7`; `Q8` returns `REC-A03` for `agent:probe-2`. If any precondition fails, all negative assertions in this case are reported **not-tested**, never passed.

## Invariants (structured list, from the validation owner's return value)

- INV-01 A display name is a label, never an identity: two records sharing a display name are never merged, deduped, ranked as versions of one another, or resolved to a single result.
- INV-02 A source-byte hash is never an identity: two records with identical bytes in different repositories or scopes remain two distinct records with distinct provenance.
- INV-03 Source repository provenance is recorded independently of memory-store location, and a shared store never binds records across repository or tenant boundaries.
- INV-04 A repository identity survives remote-URL relocation, in-repo file moves and renames; the pre-change label is preserved as a historical label, not as the identity.
- INV-05 Two checkouts sharing the same local filesystem path on different hosts never bind their records to one another.
- INV-06 Exact bytes are preserved on ingest and on read-back: byte length, BOM presence, line endings and indentation are returned exactly as observed.
- INV-07 Source-byte hash, version-control object id, canonical-normalized hash and rendered-output hash are four separately named values, and equality of any one never implies equality of the others.
- INV-08 Equality of canonical-normalized hashes never causes suppression, deduplication or an 'unchanged' verdict between records at different revisions.
- INV-09 Every record retains its immutable source revision, and a record's revision is never rewritten by a later observation of the same path or name.
- INV-10 Archival is not revocation: an archived record stays retrievable by identity, retains its evidence class and bytes, and is excluded only from the current-applicable view.
- INV-11 A supersession or replacement relation exists only when explicitly authored; it is never synthesized from name equality, revision ordering, timestamps, arrival order or model prose.
- INV-12 The historical view preserves each record's original observation time and observer, and is identical across replicas regardless of arrival order.
- INV-13 A record whose source revision has become unreachable remains fully recoverable, and the system reports source reachability as unknown rather than as deleted.
- INV-14 When the authoritative source connector is unavailable, current source state is reported unknown with the last-known fact and its original time attached, never as a confirmed head.
- INV-15 A local working tree, a file-existence test or a successful local index refresh never counts as a live remote-state check.
- INV-16 Authorization filters apply before candidate ranking, expansion, reranking and injection on every retrieval path, including exact-ID, hash lookup, cache and operator diagnostics.
- INV-17 A denied out-of-scope record leaks nothing — no id, name, bytes, hash, path, repository or snippet, and no count that discloses its existence beyond an access-denied signal.
- INV-18 Cross-scope retrieval occurs only through an explicit mode backed by a recorded authorization, and never as a silent fallback when in-scope results are sparse or low-scoring.
- INV-19 Caller-controlled fields such as actor, active and promoted_by never confer human authority, and a model-inference record is labelled as such in every rendering including compact in-packet form.
- INV-20 Selected, emitted, delivered and unavailable are four distinct delivery states, and the actual emitted bytes plus their hash are persisted and linked to the receiving host, session and turn.
- INV-21 The token budget is enforced over the entire delivered envelope including formatting overhead, and every omission is named with a reason inside the delivered packet.
- INV-22 A truncated or incomplete packet can never qualify an action, and a stale record can never qualify an action whose correctness depends on live source state.
- INV-23 Qualifying, requalifying and acting are distinct: the presence of a stored record is never itself a qualification.
- INV-24 No retrieval, assembly or action-gating step performs a source write, commit, checkout, reset or push.
- INV-25 Every negative assertion is scored only after its liveness precondition is verified, so an empty or broken store yields not-tested rather than pass.

## Instrument-can-fail controls

- CTRL-01 scope_filter_off — disable authorization filtering ahead of ranking. MUST make A-SCOPE-1, A-SCOPE-2 and A-ACT-4 FAIL (REC-A03 / MEM-K01 appears in Q3/Q4 results and A3/B3 is no longer denied for scope). If these still pass with the filter off, the queries never touched the foreign-tenant record and the scope assertions are not measuring scope.
- CTRL-02 scope_filter_off_per_path — disable the filter on ONE path at a time (dense, lexical, graph-neighbor, temporal, chunk, exact-ID, hash lookup, cache, diagnostics endpoint). Each single-path disablement MUST make A-SCOPE-1 FAIL on its own. A path whose disablement changes nothing is a path the test never exercised, and must be reported as uncovered rather than as passing.
- CTRL-03 trust_check_off — treat the ingested actor/active/promoted_by fields as authoritative. MUST make A-TRUST-1 FAIL (REC-A05 / MEM-K06 renders as authenticated human authority) and MUST make A-ACT-2 / B1's must-not-be-qualified-by list FAIL (the inference prose qualifies the regeneration action). A-TRUST-2 must still pass, proving the control is targeted at class promotion and not at authority rendering generally.
- CTRL-04 dedup_key=display_name — key deduplication on the human-readable name. MUST make A-ID-4 FAIL (REC-A01 and REC-A02 collapse) and MUST make A-SCOPE-3 / K3's exact_set FAIL (the result set loses a member). Historical view A-VIEW-2 must also lose an entry.
- CTRL-05 dedup_key=source_byte_sha256 — key deduplication on content hash. MUST make A-ID-5 FAIL (REC-A01 and REC-A03 / MEM-K03 and MEM-K01 conflate across the tenant boundary) and MUST make A-SCOPE-2 / K4 FAIL by returning a cross-tenant record. MUST make A-ID-4 and A-BYTE-4 FAIL (the archived and current records collapse even though bytes, lengths, blob ids and revisions all differ). - CTRL-07 byte_preservation_off — normalize on ingest (strip BOM, convert CRLF to LF, reindent, sort keys). - CTRL-08 freshness_check_off — serve the last-known observation as confirmed current state. MUST make A-FRESH-1, A-FRESH-2 and A-ACT-1 FAIL (Q7/K7 reports a confirmed head and A1/B1 is allowed). A-FRESH-4 must still pass, showing the control affects present-state reporting and not historical recoverability.
- CTRL-09 local_signal_counts_as_live_check — let the local working tree or a successful local index refresh satisfy the freshness requirement. MUST make A-FRESH-3 and A-ACT-2 FAIL specifically, while A-FRESH-1 may still pass; this separates 'no live check performed' from 'wrong thing accepted as a live check'.
- CTRL-10 lifecycle_collapse_off — treat archived as revoked (or as deleted). MUST make A-VIEW-4 FAIL and MUST make A-ID-1 or A-ACT-3 FAIL (the archived record becomes unretrievable or the historical citation action is denied). This proves A-VIEW-4 is not passing merely because nothing is archived.
- CTRL-11 supersession_inference_on — synthesize a supersedes edge from name equality plus revision ordering. MUST make A-VIEW-3 FAIL and MUST make A-VIEW-2's supersession_edges list become non-empty. It must NOT change A-ID-4, distinguishing an invented relation from a collapsed identity.
- CTRL-12 receipt_distinction_off — report selected records as delivered. MUST make A-DELIV-1 and A-DELIV-3 FAIL, including for the record that was excluded for scope and the source state that was unavailable.
- CTRL-13 emitted_bytes_not_persisted — skip persisting the emitted packet bytes and their hash. MUST make A-DELIV-2 FAIL. The remaining delivery assertions must still pass, showing A-DELIV-2 tests proof-of-injection rather than injection itself.

- CTRL-15 causal_dependency_off — apply out-of-order lifecycle events immediately, fabricating a placeholder target. MUST make A-VIEW-5 FAIL on the replica (the archival applies to a fabricated record, or is dropped, and the replica's views diverge from the origin's).

- CTRL-17 NO-OP CONTROL reranker_off — disable semantic reranking only. MUST change NO assertion verdict in this case. If any assertion flips, that assertion depends on ranking behaviour rather than on the property it claims to test, and must be rewritten before the measured run.
- CTRL-18 VACUITY CONTROL empty_store — run the whole assertion suite against an empty store. Every positive control (A-ID-1, A-ID-2, A-SCOPE-3, A-SCOPE-4, A-ACT-3, A-TRUST-2) MUST FAIL and every negative assertion MUST report not-tested. - CTRL-19 VACUITY CONTROL decoy_absent — remove REC-A03 / MEM-K01 only. A-SCOPE-1, A-SCOPE-2 and A-ID-5 MUST report not-tested (precondition failure), never pass; A-SCOPE-4 / K8 MUST FAIL. This proves the scope negatives are anchored to a record that actually exists in the shared store.
- CTRL-20 CONTROL-INDEPENDENCE CHECK — each control above is applied singly, with the exact set of flipped assertions recorded. A control that flips assertions outside its declared set indicates coupled instrumentation and must be reported as a measurement defect before any C04 verdict is issued.

## Open questions (structured list, from the validation owner's return value)

- The C04 row says 'fixtures' without defining whether a fixture is a memory record about a source file or the source file itself; this oracle models it as a memory record whose evidence envelope points at an immutable source revision. If the intended reading is a store-internal artifact with no source URI, the R02 assertions about source URI, revision and blob id need restating.
- 'Archived' is used in C04 but only defined in R05 as distinct from revocation. Whether an archived record is excluded from the default current view (this oracle's A-VIEW-1) or merely flagged inside it is not stated; the assertion is written as exclusion-with-explicit-flag and should be confirmed against the foundation contract before scoring.
- C04's 'preserve distinct source hashes' does not say which hash kinds must be exposed. R02 names four values; this oracle requires all four to be separately named. If an implementation legitimately cannot produce a rendered-output hash for a record never rendered, that field should be reported unavailable rather than failed.
- 'Historical context' is not defined. This oracle reads it as original observation time, observer, evidence class, lifecycle events with actors, and the pre-change repository label. A narrower reading (lifecycle events only) would drop A-ID-6 and part of A-VIEW-2.
- The case does not say whether a same-named record in an unauthorized scope should produce a silent omission or a visible access-denied marker. This oracle permits either, provided no content leaks, but the go/no-go 'cross-scope disclosure' rejection condition may require one specific behaviour.
- Whether a second, byte-identical record in a foreign tenant may legitimately share a content-addressed storage block (deduplicated at rest while remaining two logical records) is not addressed. This oracle asserts only logical non-conflation; physical block sharing across tenants may itself be a data-handling concern under R18 and needs a separate ruling.
- The declared tokenizer and version for the budget assertions are not fixed anywhere in the three source documents; R15 requires a declaration. The 600-token and 450-token figures are placeholders and must be restated against the declared tokenizer before the packet assertions are measured.
- C04 is listed under R12 in the coverage map but its row text does not mention freshness. This oracle adds the connector-unavailable and force-push conditions to satisfy the coverage map; if the programme intends C04 to be freshness-free, sections 4.4 and A-ACT-1/A-ACT-2 belong to C01 instead.
- The out-of-causal-order replication at T13/H09 borders on C10/C11 territory. It is included here only to assert that the historical view is arrival-order independent; if the programme prefers strict case separation, that assertion should move and A-VIEW-5 should be reduced to same-content-across-replicas.
- Whether 'deny' or 'defer' is correct for an action blocked by unknown source state is left as a disjunction because the requirements distinguish the two nowhere; a definite expected value should be agreed before the measured run, since a disjunctive oracle is weaker evidence.
