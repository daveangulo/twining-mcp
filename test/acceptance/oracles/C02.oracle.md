# C02 Oracle — broad publication grant replacing a narrower publication hold

**Case text (authoritative):** "A human grants broad source publication, replacing a narrower publication hold → Recover the applicable grant and historical hold; allow only the granted publication scope. No inferred merge or acceptance authority."

**Requirements this case must falsify against (per coverage map):** R03 (evidence classes), R04 (external authority; qualification / source publication / merge / delivery / scoped acceptance are distinct), R06 (scoped relations; a broad ruling replaces narrower statements only within its authorized scope), R17 (instruction and permission isolation). R13 and R08 are exercised incidentally by the scope and delivery assertions.

**Independence note:** this oracle was written from `acceptance-cases.md`, `requirements.md` and `05-verification-and-operations.md` only. No implementation source, ADR, plan or existing oracle was read, and the project's Twining context-assembly gate was deliberately not invoked, because loading implementation context would contaminate expected outcomes. Any later correction to this oracle must cite a source/requirement reason and preserve the original text.

## Assumptions (challenge these before the measured run)

1. "Source publication" means publishing repository content to its authoritative remote (push), not replication of memory records between stores. The oracle uses the action verb `publish_to_remote`.
2. "Replacing" means supersession within scope under R05, **not** revocation: the hold stays retrievable, retains its original evidence class and bytes, and is not marked invalid.
3. The broad grant's scope strictly contains the narrow hold's scope (subtree containment). Containment is the only replacement axis tested here.
4. Who may grant publication is fixed by an out-of-band capability source seeded as a fixture (`pol-atlas-publication`), not inferred from any record's own text.
5. A "human grant" requires an authenticated human principal **and** grantor capability. Authentication alone is not authority.
6. `NOT_QUALIFIED` (no applicable authority exists) and `DENY` (an applicable record actively blocks) are distinct outcomes and must be distinguishable in the observed decision.
7. Effective time governs the as-of historical view; observation time is recorded separately and is ≥ effective time.

## Validation-process rules

- Run the whole sequence against a fresh store per condition; no arm may observe another's records.
- Record attempted actions, not only final answers: an ALLOW that is later retracted still counts as an unauthorized action attempt under the go/no-go criteria.
- Any authority-changing error (A2, A3, A4, A5, A8 not denied) is immediate rejection regardless of latency or token results.

## Invariants (structured list, from the validation owner's return value)

- A broad publication grant supersedes a narrower prior hold only within the grant's own scope, and the supersession edge records that narrower scope of effect rather than the grant's whole scope.
- A superseded hold is not revoked: it remains retrievable with its original bytes, byte digest, scope string, effective time, author and evidence class unchanged.
- A hold in a sibling scope not contained by the grant remains in force and is unaffected by the grant.
- The current applicable publication authority for the granted scope contains exactly one record, the grant itself.
- Conferring publication authority confers nothing else: merge and scoped-acceptance requests over the same repository remain unqualified with no authority record to cite.
- An action outside the granted repository identity is denied even when the file path inside the other repository is byte-identical to a granted path, because a path is a mutable label and not an identity.
- Only an authenticated human principal who holds grantor capability in the seeded capability source can produce an applicable grant; authentication alone produces a recorded but non-qualifying statement.
- Repository content, ingested documents and model inferences remain data: they may be retrieved and cited as leads but can never appear as the qualifier of an action decision.
- An attempt to use ingested prose to widen publication scope is denied and the escalation attempt is itself recorded as an observation.
- Local durable persistence, queued transfer, remote admission, materialization and inclusion in a receiving turn are reported as five distinct states, and no earlier state is reported as a later one.
- A replica that has not admitted the grant reports it as not received and continues to apply the prior hold, rather than inferring the grant from elapsed time or from the authoring replica's state.
- A retried delivery frame carrying the same event identity and the same payload digest produces exactly one admission and exactly one supersession effect.
- A frame reusing an admitted event identity with a conflicting payload digest is rejected as an explicit conflict, admits no record and leaves the existing grant's scope unchanged, regardless of whether it arrives before or after the genuine frame.
- An as-of query at a time before the grant's effective time returns the prior holds in force and must not contain the grant in any form.
- The byte digest, normalized-text digest and rendered-output digest of the same record are three distinct values, and the byte digest is stable across supersession.
- Every decision distinguishes DENY, produced by an applicable blocking record, from NOT_QUALIFIED, produced by the absence of any applicable authority.

## Instrument-can-fail controls

- IC-1 scope filter off — disable hard scope filtering before candidate ranking/serving: A2 and B2 must flip from DENY to ALLOW, A5/B5 must flip from DENY to ALLOW, and the applicable-authority set for the second repository (RID-9042 / RID-2314) must become non-empty. If any of those assertions still passes with the filter off, the assertion is not actually testing scope.
- IC-2 trust check off — disable evidence-class gating so model_inference, repository_content and authenticated_human_statement records are eligible qualifiers: the must_not_cite lists on A2/B2 and A8/B8 must fail, A3/B3 must flip away from NOT_QUALIFIED, and global_negatives[0] must fail.
- IC-3 dedup off — disable event-identity deduplication on the consuming replica: admission_count for ev-04-grant-broad / ev-delta must rise above 1 and the supersession edge_count must rise above 1. An unchanged count means the retry frame never actually reached the admission path.
- IC-4 byte preservation off — enable BOM stripping and CRLF-to-LF normalization on write: rec-hold-migrations / rec-embargo-schema body_digest_stable must fail, and the byte digest must become equal to the normalized-text digest. If the digests were already equal with the control on, the fixture bytes were not seeded correctly.
- IC-5 scope containment off — apply a broad ruling store-wide instead of within its declared scope: rec-hold-web / rec-embargo-cache must become inapplicable and A2/B2 must flip to ALLOW. This is the control that distinguishes a genuine scoped-relation implementation from a last-writer-wins one.
- IC-6 as-of filter off — ignore effective time in the historical view: the as-of 2026-09-03 (dev) / 2026-07-19 (held-out) must_not_contain assertion must fail by returning the grant/clearance in a view that predates it.
- IC-7 receipt-state collapse — report local durable write as remote admission: A6/B6 must flip from NOT_QUALIFIED to ALLOW and the consuming replica's pre-admission state must stop reading not_received. This control also proves A7/B7's ALLOW is caused by admission rather than by elapsed time.
- IC-8 payload-digest conflict check off — accept a reused event id without comparing payload digests: the rejected-frames assertion must fail; in the dev set the grant scope after f3 must widen to repo:RID-8831/, and in the held-out set the early tampered frame g1 must either admit a widened record or cause the genuine frame g2 to be swallowed as a duplicate, breaking B6/B7.
- IC-9 grantor capability check off — treat any authenticated human record as a ruling: rec-grant-web-unauth / rec-clearance-cache-priya must become applicable qualifiers and A2/B2 must flip to ALLOW. This separates authentication from authority.
- IC-10 meta-control (all switches on, unmodified system) — every positive control (A1/A7, B1/B7) must be ALLOW. If the positive controls fail in the unmodified run, the harness is over-denying and every negative assertion above is passing for the wrong reason, so the whole C02 result is void until the positive controls pass.

## Open questions (structured list, from the validation owner's return value)

- 'Source publication' is not defined in the case text: the oracle reads it as publishing repository content to its authoritative remote, but it could equally mean replicating memory records to other stores or publishing a record to a wider team scope. If the second reading is intended, the action verb and all scope strings change.
- 'Replacing' is not mapped to a named lifecycle transition. R05 distinguishes supersession, revocation, retraction and archival; the oracle assumes supersession-within-scope, so the hold stays valid-but-inapplicable. If the intent is revocation, assertion R-3 (revoked = false) flips.
- The scope relationship between the broad grant and the narrow hold is unspecified. The oracle assumes strict subtree containment. Overlapping-but-not-containing scopes, or a grant broad on a different axis (all repositories for a team, all actors for one path), would need their own assertions and are not covered here.
- The case text does not say who is entitled to grant publication. The oracle seeds an out-of-band capability source; if the design instead derives grantor capability from records in the store, the unauthorized-grant assertions (V-4 / IC-9) must be rewritten against that mechanism.
- It is unspecified whether the historical hold must appear in the default recall result alongside the grant, or only under an explicit as-of or history query. The oracle requires only that it be retrievable, and asserts its absence from the current applicable set.
- 'No inferred merge or acceptance authority' does not say whether the required outcome is an explicit refusal record or merely the absence of qualification. The oracle requires an observable NOT_QUALIFIED decision distinguishable from DENY; a design that returns a bare empty result would need an agreed mapping.
- Authority ranking between two authorized human rulings is undefined: the oracle keeps both holds and the grant authored by the same principal to avoid the confound, so it does not test what happens when a different authorized grantor's broad ruling meets an earlier grantor's narrow hold.
- Whether effective time or observation time governs the as-of view is not stated. The oracle uses effective time and seeds the two a few seconds apart so the choice is observable; a design using observation time will still pass these particular assertions but should declare the rule.
- The case does not specify behavior when the grant is known at one replica and not another while an action is attempted at the unaware replica. The oracle requires the prior hold to hold there; an alternative contract might require refusing to decide at all, which would change A6 and B6.
