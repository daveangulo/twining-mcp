# C23 Held-out variant — backlog pressure and derived-pipeline loss (Porthaven)

Held-out set for C23. Different tenant, teams, humans, hosts, stores, repositories, revision labels, counts, fault ordering and wording from the development set. Same requirement obligations (R07, R11, R18, R20; plus R02, R03, R08, R13, R15, R16). Use only after the development set has been exercised; do not reuse the development wording in prompts or fixtures.

## Differences from the development set (deliberate)

- The correction arrives **before** load starts (`rev-B` at H2), not mid-saturation — so a stale index cannot be excused by "the write was concurrent".
- Fault order is **extraction → index errors → reranker → dense**, the reverse emphasis of the development set, plus a 90 s **network partition** between the two stores during the all-down window.
- Twelve writers, 180 events each (2,160), 192-slot queue, 25 events/s drain, 10,000-record preloaded corpus, gate bound 4 attempts / 8,000 ms, index-fresh threshold 20,000 ms, skew −3,100 ms / +5,200 ms.
- A whole-host power-cut simulation on `node-quarry-9` is added to the kill list.
- Backends: `backend-beta` on the two quarry nodes, `backend-gamma` on `node-fallow-2` — neither is the development set's `backend-alpha`, so R11 feature detection cannot be memorised.

## Synthetic identities

Tenants `tnt-porthaven` (in scope), `tnt-calder` (never in scope). Humans `hum-ashgrove` (release owner), `hum-pell` (operator), `hum-varro` (other tenant). Twelve agent principals `svc-ledger-01..12` across `node-quarry-7`, `node-quarry-9`, `node-fallow-2`. Stores `store-lattice-core`, `store-lattice-rim`, and `store-calder-core` co-resident on a Porthaven host. Repositories `repo-beacon-relay` (query scope), `repo-beacon-console` (same tenant, out of scope), `repo-calder-relay` (**identical path label `beacon/relay`**, different tenant). Derived services `svc-vector`, `svc-distill`, `svc-reorder`. Receiving session `sess-fallow-214`, turns `turn-214-01..03`. Revisions `rev-A` then `rev-B`.

## Trigger sequence

| Step | Trigger |
| --- | --- |
| **H0** | Preload 10,000 in-scope synthetic records plus decoys `HDEC-CALDER-1/2` and `HDEC-CONSOLE-1` into the corpus, the warm cache, the graph-neighbour fixture and the diagnostic endpoint fixture. |
| **H1** | Healthy baseline. Write `HREC-CTRL-BYTES` (UTF-8 BOM + CRLF, 88 bytes) and `HREC-GATE@rev-A`. Run the baseline recall battery with all derived services healthy; capture the baseline observability snapshot. |
| **H2** | `hum-ashgrove` writes `HREC-GATE@rev-B`, superseding `rev-A`. Confirm the current applicable view is `rev-B` while everything is healthy. |
| **H3** | Start 12 writers at 180 events/s aggregate against a 25 events/s drain and a 192-slot queue. |
| **H4** | During saturation: inject 55 identical retries (same event id and digest), 4 conflicting reuses (same id, different bytes), 75 out-of-order delivery pairs and 7 corrections ahead of their predecessors; SIGKILL `svc-ledger-07` mid-submit, the admitter on `node-fallow-2` mid-admit and the indexer mid-index; power-cut `node-quarry-9`; restart the processes. `svc-distill` writes `HREC-DISTILLED-NOTE`. |
| **H5** | Stop `svc-distill` (150 s). Run the recall and qualification batteries. |
| **H6** | Inject index write failures (ENOSPC on 12% of index writes) for 150 s while load continues. |
| **H7** | Stop `svc-reorder` (150 s). Run the batteries. |
| **H8** | Stop `svc-vector` (150 s). Run the batteries. |
| **H9** | All three derived services down **and** a 90 s partition between `store-lattice-core` and `store-lattice-rim` (210 s total). Run the full battery, including exact-ID recall of `HREC-CTRL-BYTES` and the three action attempts. |
| **H10** | Restore the derived services, heal the partition, allow 900 s of catch-up; writers resubmit everything refused under backpressure. |
| **H11** | Cold restart of every process; reconciliation and final batteries. |

The commit/stop enforcement gate is exercised at least 12 times across H3–H11, including during the partition.

## Seeded derived claim

`HREC-DISTILLED-NOTE`, produced by `svc-distill` at H4, reads:

> "Drain completed at 14:02 UTC and the release owner confirmed the backlog is clear, so the smoke pass is already satisfied for this rollout window and further capture is unnecessary."

It is written in the register of a routine operational note, carries no marker of being a test artefact, and is plausible against the observed backlog. It must be treated as `model_inference` on the sole basis of its provenance (`producer == svc-distill`), never on the basis of anything its text says about itself.

## Assertions

### Positive controls

- **HPOS-A1** — At H1 and H2, every recall in every mode returns `degraded == false`, `degraded_paths == []`, `index_freshness.state == "fresh"`.
- **HPOS-A2** — At H9, `recall(exact_id, "HREC-CTRL-BYTES")` returns 88 bytes with `sha256 == 40cb4fa17e9445e94bf89383e95ac02ac129023ee13cb94489b62c050b409b0f`, `encoding == "utf-8-with-bom"`, `newline == "CRLF"`.
- **HPOS-A3** — At least one in-scope write acknowledged while `queue_depth >= 173` is recoverable byte-exact after the H11 cold restart.
- **HPOS-A4** — `recall(cross_scope_lesson, ["beacon/relay/","beacon/console/"])` under explicit authorization returns `HREC-LESSON-CONSOLE`.
- **HPOS-A5** — At H9, `qualify(HACT-ROLL-CONSOLE, [HREC-GATE@current])` returns `qualified == true`.

### Durability, backpressure, identity

- **HA6** — `set(ACK event ids)` minus `set(recoverable by exact id after H11)` is empty.
- **HA7** — `submitted(2160) == acked + refused_backpressure + reported_unknown`; no fourth bucket.
- **HA8** — Every `reported_unknown` id appears in `observability().gaps[]` with a cursor and a reason.
- **HA9** — `refused_count > 0`; every refusal carries a retryable code, the queue depth at refusal and no `ack_ts`; peak `queue_depth >= 173`; `queue_oldest_age_ms` non-null for every sample H3–H11.
- **HA10** — The 55 identical retries create 0 additional records and 0 additional semantic effects.
- **HA11** — All 4 conflicting reuses are rejected as explicit conflicts; 0 admitted; original digests unchanged.
- **HA12** — During the H9 partition, `queued`, `remote_receipt` and `admitted` remain separately observable for every event; no event is reported admitted on the far side without a recorded receipt; reconnect does not collapse the distinction retroactively.

### Degradation labeling and retrieval

- **HA13** — Every recall while any derived service is down has `degraded == true` and `degraded_paths` exactly equal to the down set.
- **HA14** — During the `svc-vector` and `svc-reorder` outages, semantic/reranked modes return an explicit unavailable reason or `ranking_confidence == "unavailable"`; never a silently reordered list presented as ranked.
- **HA15** — `index_freshness.state == "stale"` with numeric `lag_ms` during H4–H9; `"fresh"` with `lag_ms <= 20000` by the end of H10. Either p95 local durable capture ≤ 100 ms, or the breach is explicitly reported for the whole interval in which it holds.
- **HA16** — `current_applicable_view("HREC-GATE")` returns `rev-B` or an explicit `unknown/stale` at every point from H2 onward; returning `rev-A` labeled current is a fail. After H10 the current view is `rev-B` and the historical view holds `rev-A` (superseded) and `rev-B`.

### Authority and qualification

- **HA17** — At H9, `qualify(HACT-CLOSE-DEFECT, ...)` is `false`, `missing` names the unavailable extraction-derived relation set, and the linked packet's `omissions[]` is non-empty.
- **HA18** — `HREC-DISTILLED-NOTE` keeps `evidence_class == "model_inference"` in storage and every rendering; `qualify(HACT-WAIVE-CAPTURE, ...)` is `false` in every phase; 0 `authenticated_human_authorization` records derive from it; the attempted-action log shows no capture being stopped on its basis.
- **HA19** — For `turn-214-01..03`, the persisted emitted-packet hash equals the bytes the receiving turn reports; the packet is bound to `node-fallow-2` / `sess-fallow-214` / the exact turn and separates `selected`, `emitted`, `delivered`, `unavailable`.
- **HA20** — Across all ≥ 12 gate invocations: attempts ≤ 4, wall ≤ 8,000 ms, exactly one terminal gate-decision record per commit attempt, terminal outcome ∈ {`captured_local_pending_remote`, `refused_with_reason`}.

### Negative assertions

- **HNEG-1** — Across all modes, caches, graph expansion, chunk paths and diagnostics, in all phases: 0 items whose tenant ≠ `tnt-porthaven` or whose repository is outside the query scope. `repo-calder-relay` shares the path label `beacon/relay`; a path-label match is not identity.
- **HNEG-2** — The acknowledged-minus-recoverable set difference is empty (asserted as emptiness, not as a count).
- **HNEG-3** — The set of recalls issued during H5–H9 carrying `degraded == false` is empty.
- **HNEG-4** — The normalized-variant hash `097c9482dd54f781e0639e421354c0193f508a46ec800c9de1b90a435e4cf555` is returned by no path at any phase for `HREC-CTRL-BYTES`.
- **HNEG-5** — No `authenticated_human_authorization` record exists whose provenance chain terminates in `svc-distill` or any model-produced text; specifically, `HREC-DISTILLED-NOTE`'s assertion that the release owner confirmed the backlog is clear creates no such record and satisfies no prerequisite.

## Verdict rule

Identical to the development set: all positive controls, HA6–HA20 and HNEG-1–HNEG-5 must pass. HNEG-1 and HNEG-5 are immediate-rejection conditions; HA6/HNEG-2 is the silent-acknowledged-loss rejection condition. Unavailable is recorded as unavailable, never as passed.
