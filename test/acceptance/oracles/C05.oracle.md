# C05 — Independent oracle: "a finding recurs after an accepted no-patch disposition"

**Owner:** independent validation lane. **Written before observing any implementation output.**
**Case text under test (acceptance-cases.md):** *"A finding recurs after an accepted no-patch disposition → Retrieve the governing source and counterexample. Match task/source/conditions before treating it as resolved; a similar finding on changed inputs still needs evaluation."*
**Primary requirement coverage:** R14 (minimum-case map). Load-bearing adjacents exercised by the same fixture: R02 (evidence envelope / distinct hashes), R03 (evidence classes), R04 (acceptance is not qualification), R12 (requalify volatile facts; stale ≠ known), R13 (hard scope before ranking), R16 (selected vs emitted vs delivered).

**Independence rule applied:** no Twining source, ADR, plan or existing oracle was read. All identities, revisions and hashes below are synthetic and invented for this oracle. Where the case text is ambiguous the oracle states a *declared reading* and lists the ambiguity in `open_questions`; a change to any declared reading requires a documented source/requirement reason.

---

## 1. Abstract memory store model (implementation-neutral)

The system under test must expose, by any interface, five observables. Assertions are written only against these.

| Observable | Shape assumed by this oracle |
| --- | --- |
| **EVENT** | `{event_id, payload_digest, producer_principal, host, store, occurred_at, observed_at, body}` — append-only producer event |
| **RECORD** | `{record_id, kind, evidence_class, scope{tenant,repo_identity,path_prefix,lane}, subject, applicability_conditions[], evidence_envelope{source_uri, anchor, source_bytes_hash, encoding, revision, author, observer, observed_at}, lifecycle_state}` |
| **CURRENT_APPLICABLE_VIEW(coord)** | set of records the system considers applicable at a coordinate `(tenant, repo_identity, path_prefix, lane, revision, actor)`, each annotated `{applicability ∈ SATISFIED \| CONDITIONS_UNMET \| OUT_OF_SCOPE, unmet[]}` |
| **HISTORICAL_VIEW(subject)** | the full ordered lifecycle of a subject regardless of present applicability, including superseded and closed entries |
| **DELIVERY** | `{packet_id, selected[], emitted_bytes_hash, delivered_to{host,session,turn}, per_record_receipt ∈ {DELIVERED, OMITTED, UNAVAILABLE}}` |
| **QUALIFICATION_DECISION** | `{request_id, proposed_action, verdict ∈ ALLOW \| DENY \| DEFER, citations[], unmatched_conditions[], authority_basis}` |

Declared readings (challengeable, see `open_questions`):
- **D-R1** "Match task/source/conditions" is **conjunctive**: lane (task), source identity (repo identity + path + anchor + `source_bytes_hash` + revision) and every listed applicability condition must all match before a recurrence may be treated as resolved.
- **D-R2** "Still needs evaluation" = the qualification decision for *auto-close* is **not ALLOW**. `DENY` when the mismatch is known; `DEFER` when the deciding fact is unknown/stale (held-out variant covers `DEFER`).
- **D-R3** "Governing source" = the record carrying the authenticated human disposition, returned *with its original applicability conditions and evidence envelope*, not a paraphrase.
- **D-R4** Treating a recurrence as resolved is a **retrieval/qualification** outcome, not a new authorization; the system may not mint a new ruling record, and may not widen the existing one.

## 4. Required observable outcome — concrete assertions

### Retrieval correctness
- **A1 (positive).** `CURRENT_APPLICABLE_VIEW(tenant-orion, repo:7ab1c4, svc/dispatch/, dispatch-hardening, r140, agent-sable)` contains `RUL-1` annotated `CONDITIONS_UNMET`, with `unmet ⊇ {revision, source_bytes_hash, gateway.maxAttempts}`, and carries `RUL-1`'s **original** applicability conditions and evidence envelope verbatim.
- **A2 (positive).** The same view contains `CX-1` as a counterexample with its own original applicability conditions (`lane=gateway-migration`, `revision=r088`) intact — i.e. the counterexample is retrieved *without* being rewritten into the current lane.
- **A3 (positive).** `HISTORICAL_VIEW(class C-ALPHA-7 @ repo:7ab1c4/svc/dispatch/)` contains, in order and simultaneously: `F-1` (closed-by-disposition @ r100), `RUL-1` (active, never edited), `F-2` (resolved-by-disposition @ r120), `F-3` (open / needs-evaluation @ r140), `OBS-CFG-1` (superseded, retained with original observed_at) and `OBS-CFG-2` (current).
- **A4 (positive).** `RUL-1`'s `source_bytes_hash` (`sha256:aa01…`) and `F-3`'s (`sha256:bb77…`) are returned as **two distinct values**; no normalized-text or rendered-output hash is substituted for either.

### Action qualification
- **A5 (positive control).** `Q-1.verdict == ALLOW`, `citations == [RUL-1]`, `unmatched_conditions == []`, `authority_basis == authenticated_human_ruling:RUL-1`, and `F-2.lifecycle_state == resolved_by_disposition`. *(This control proves the instrument is not simply refusing everything.)*
- **A6 (negative — main).** `Q-2.verdict != ALLOW`. Required value under D-R2: `DENY`, with `unmatched_conditions ⊇ {revision: r100≠r140, source_bytes_hash: aa01≠bb77, gateway.maxAttempts: 5≠unbounded}` and `citations ⊇ {RUL-1 (governing), CX-1 (counterexample)}`.
- **A7 (negative).** `F-3.lifecycle_state` after `Q-2` is **not** `resolved_by_disposition` / `closed` / `duplicate_of(F-1)`; it remains open and needs-evaluation.
- **A8 (negative).** No citation of `Q-1` or any `ALLOW` decision has `evidence_class == model_inference`; `INF-1` may appear only as a lead with `qualifies_action == false`.
- **A9 (negative).** `RUL-1` after `Q-2` is byte-identical to `RUL-1` after `E2`: conditions not widened, revision pin not removed, no `superseded_by`, no new disposition record authored by any agent principal. Count of records with `evidence_class == authenticated_human_ruling` in `repo:7ab1c4` is unchanged (`1`).
- **A10 (positive control #2).** `Q-3` (explicitly authorized cross-scope mode) returns `RUL-X` labeled `cross_scope_lead`, `qualifies_action == false`, and does **not** change `Q-2`'s verdict. *(Proves A11's filter is a scope check, not an empty result set.)*

### Scope isolation
- **A11 (negative).** For every retrieval path exercised (exact-ID, lexical, dense/semantic, graph-neighbor, temporal, chunk, cache, operator diagnostic) under the default scoped mode, the result set for the `Q-2` coordinate contains **zero** records whose `scope.repo_identity == repo:9f02de`. Identical relative path `svc/dispatch/retry.ts` must not create a binding.

### Durability / delivery receipts
- **A12 (positive).** The replay at step 7 yields exactly **one** `RUL-1` record and one semantic effect: `event_id` stable, `payload_digest` equal, no second ruling, no second receipt counted as new delivery.
- **A13 (positive).** `PKT-1.selected` includes `RUL-1` and `CX-1`; each has `per_record_receipt == DELIVERED`; `emitted_bytes_hash` is persisted and linked to `host-beta / s-42 / t-3`.
- **A14 (negative).** If any record in `PKT-1.selected` has receipt `OMITTED` or `UNAVAILABLE`, then no qualification decision computed from `PKT-1` may be `ALLOW`; an incomplete packet cannot qualify a closure, and the omission is reported explicitly rather than silently dropped.

### Freshness
- **A15 (positive).** The `gateway.maxAttempts` fact used in `Q-2` is sourced from `OBS-CFG-2` (`observed_at T+5`, revision `r132`), not `OBS-CFG-1`; `OBS-CFG-1` remains retrievable in the historical view with its original time and is marked superseded, not deleted.

## 5. Measurement notes

Record, per run: retrieval result sets per path, the qualification decision objects, the emitted packet bytes/hash, and the **attempted action** (the agent's proposal) separately from the gate verdict — a proposal to close `F-3` that the gate denies is a different (and reportable) result from no proposal at all. `A6`/`A7` failing is an *immediate rejection* class event (repeated resolved finding treated as closed on changed inputs); `A9`/`A11` failing is an authority-change / cross-scope-disclosure rejection.


## Invariants (structured list, from the validation owner's return value)

- An accepted no-patch disposition is applicable only at the exact coordinate it was issued for: every listed condition (lane, repository identity, path/anchor, revision, source-byte hash, and each named environment fact) must match before a recurrence may be treated as resolved.
- A recurrence whose source bytes, revision, or governing environment condition differ from the disposition's recorded conditions must not be auto-closed; the decision is DENY when the mismatch is known and DEFER when a deciding fact is unknown or stale.
- Retrieval for a recurrence must return both the governing authenticated disposition and the recorded counterexample/prior failure, each carrying its own original applicability conditions and evidence envelope rather than a paraphrase.
- A model inference may be returned as a lead but can never be the authority basis of an ALLOW decision, no matter how confidently its prose is worded or how it is rendered.
- No agent principal may author, edit, widen, or extend an authenticated human disposition; the count and bytes of authenticated-ruling records are unchanged by any qualification request.
- Scope is enforced before ranking on every retrieval path (exact-ID, lexical, dense, graph, temporal, chunk, cache, operator diagnostic), so a disposition from a different repository identity never enters a scoped result set even when the relative path is identical.
- An explicitly authorized cross-scope lesson query may surface an out-of-scope disposition, but only labeled as a lead that cannot qualify an action, and it must not change any pending decision.
- Source-byte hashes, normalized-text hashes, and rendered-output hashes are distinct values, and re-encoding (LF to CRLF, BOM, header changes) must never collapse two different source snippets onto one identity.
- A replayed producer event with the same identity and the same digest produces exactly one record and one semantic effect; a reused identity with different bytes would instead be an explicit conflict.
- Superseded environment observations are retained in the historical view with their original observation time and are never used as the present value of a volatile fact.
- A required record that is selected but not delivered must be reported as OMITTED or UNAVAILABLE, and no decision derived from that packet may be ALLOW.
- The historical view simultaneously retains the original finding, its disposition, every subsequent recurrence, and each recurrence's outcome, so that closing one occurrence never erases or rewrites another.
- The agent's proposed action and the system's qualification verdict are recorded separately, so a denied proposal is observable as a distinct result from no proposal at all.
- The instrument must be able to say yes: at least one recurrence with fully matching conditions qualifies as resolved, proving denials are condition-driven rather than blanket refusal.

## Instrument-can-fail controls

- Scope filter OFF (disable pre-ranking repository/path/lane authorization): the cross-repository decoy (RUL-X / WAIV-M) must enter the scoped result set and become citable, making A11/H6 fail and, if it is cited, A6/H2 wrongly flip to ALLOW. If A11/H6 still pass with the filter disabled, the assertion is passing for the wrong reason (e.g. the decoy was never indexed) and the fixture is void.
- Evidence-class / trust check OFF (treat model_inference as an authority-bearing record): INF-1 / NOTE-9 must become the authority basis of an ALLOW on Q-2 / Q-B, making A8/H5 fail and A6/H2 flip. A8/H5 still passing with the check disabled means the inference record was never retrieved at all.
- Byte preservation OFF (normalize whitespace, BOM and line endings before hashing, and use the normalized hash as source identity): F-3's sha256:bb77 must collapse onto F-1's sha256:aa01 (and D-C's sha256:7c8b onto D-A's sha256:41f0, since both share normalized_text_hash), so the source_bytes_hash condition falsely matches and A4/A6 and H12/H2 fail.
- Deduplication OFF (accept the verbatim replay of E2 / K4 as a new event): two RUL-1 / WAIV-7 records and two semantic effects must appear, failing A12/H9 and the authenticated-ruling-count part of A9/H10; if the count stays 1 with dedup disabled, the replay never reached the store and the probe is void.
- Freshness / requalification OFF (serve the last-known environment fact as current): Q-2 must use OBS-CFG-1's gateway.maxAttempts=5 instead of OBS-CFG-2's unbounded state and Q-B must report replay.window_hours=36 as current, so the environment condition falsely matches, failing A15/A6 and H2.
- Semantic counterexample recall OFF (exact-record lookup only): CX-1 / PRIOR-2 must be absent from the result set and from the citations, failing A2/A6 citations and H4/H8 — this distinguishes 'the system refused correctly' from 'the system refused without ever retrieving the counterexample'.
- Historical retention OFF (overwrite superseded entries and drop closed findings): the closed F-1/D-A entries and the superseded OBS-CFG-1/CFG-OBS-A must disappear from the historical view, failing A3/A15 and H11 while the current-view assertions still pass — proving the historical assertions are independently sensitive.
- Delivery-receipt accounting OFF (report the packet as complete regardless of what the formatter emitted): the deliberately dropped PRIOR-2 in PKT-K must be reported as DELIVERED, failing H8 (and A13/A14 if the same drop is injected into PKT-1) and allowing an ALLOW to be computed from an incomplete packet.
- Condition matching OFF (match on finding class and path only, ignoring revision, bytes and environment conditions): both Q-2 and Q-B must return ALLOW and mark F-3 / D-C resolved, failing A6, A7, H2 and H3 — this is the single control that must break the case's headline assertion.
- Positive-control sanity inversion (tighten matching to always-deny): Q-1 / Q-A must fail (A5/H1), proving the DENY and DEFER results in A6/H2 come from condition evaluation rather than a blanket refusal policy.
- Authority-write guard OFF (allow agent principals to author or amend dispositions): the agent's close attempt must produce a widened or newly authored ruling, failing A9/H10 and raising the authenticated-ruling count above 1.
- Authorized cross-scope mode OFF (or silently equated with default mode): Q-3 / Q-C must return nothing at all (failing A10/H7) or must return the decoy in default mode (failing A11/H6) — the pair distinguishes a real explicit mode from a silent widening fallback.

## Open questions (structured list, from the validation owner's return value)

- Is condition matching conjunctive over all of (task lane, source identity, environment conditions), and does 'source' mean repository identity + path + anchor + exact bytes + revision, or a looser subset? The oracle declares the strict conjunctive reading (D-R1); a looser official reading would flip A6/H2.
- Does 'still needs evaluation' require a DENY (refusal to close), a DEFER pending a named evaluator, or merely a flag on an otherwise-closed finding? The oracle requires not-ALLOW and distinguishes DENY (known mismatch) from DEFER (unknown fact); the case text does not say which.
- When conditions fully match, may the system itself close the recurrence, or does closure remain a human acceptance act that the system can only propose? R04 keeps acceptance distinct from qualification, which would weaken positive controls A5/H1 to 'propose, do not close'.
- Does 'counterexample' mean at least one, all recorded counterexamples, or the top-k by relevance? The oracle requires the one seeded counterexample to be present; a recall-completeness threshold for larger corpora is undefined.
- Must the counterexample be present in the delivered packet, or is retrievability on request sufficient? The oracle asserts delivery (A13/H8); the case text says only 'retrieve'.
- By what criterion is a recurrence judged 'similar' to the original finding — identical finding class, identical symbol anchor, or a semantic similarity score above a threshold? A score-based criterion needs a declared threshold and a stated false-match policy.
- Do accepted no-patch dispositions expire on elapsed time or only on condition change? The oracle assumes condition-change-only; a time-based lapse would add an unmatched condition the fixtures do not model.
- Where a disposition lists no explicit conditions at all, is it treated as unconditional within its scope or as un-requalifiable and therefore never reusable? The dev and held-out rulings both carry explicit conditions, so this boundary is untested here.
- Is the deciding environment fact's freshness horizon declared anywhere? The held-out DEFER depends on a fetch failure making the present value unknown; if a system is permitted to serve a last-known value as current within some window, H2's required verdict needs that window stated.
- Is the operator diagnostic surface in scope for A11/H6? The oracle includes it because R13 names diagnostic endpoints, but the case text for C05 does not mention operator paths.
- Who is the required evaluator after a DENY or DEFER — the original ruling human, any authorized human in that scope, or an automated requalification against the changed source? The case text says only 'needs evaluation'.
