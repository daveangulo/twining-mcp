# C03 oracle — three consumers, three different prerequisites

**Case text (acceptance-cases.md, C03).** Setup/trigger: *"Three consumers require, respectively, catalog-output review, catalog-only acceptance and full-story acceptance."* Required observable outcome: *"Recover each consumer's own prerequisite and evidence. No one global rule; a missing acceptance remains missing."*

**Requirements exercised** (coverage map): R04 (external authority — qualification, publication, merge, delivery and scoped acceptance stay distinct), R06 (scoped relations — a narrow statement must not alter neighbouring scopes), R14 (useful recall — return original applicability conditions and source evidence). R03 (evidence classes) and R16 (prove injection) are load-bearing for the negative assertions and are asserted here even though C03 is not their minimum case.

**Independence note.** Expected values below were fixed from `acceptance-cases.md`, `requirements.md` and `05-verification-and-operations.md` only. No Twining source, ADR, plan or existing oracle was read. Project gate tooling that returns implementation-derived prior decisions was deliberately not invoked, because its output would contaminate the oracle. Changing any expected value requires a written source/requirement citation; the original and corrected values are both retained.

## 1. Oracle assumptions (challengeable, stated up front)

| # | Assumption | Why it is needed | What would invalidate it |
|---|---|---|---|
| A1 | A prerequisite binds to an exact revision of its target scope. | The case says "a missing acceptance remains missing" but is silent on revision drift; without binding, "missing" is untestable after a source change. | A contract that declares prerequisites revision-independent, in writing, before the run. |
| A2 | Scope containment is one-directional: a whole-story acceptance covers its parts; a part acceptance never covers the story. | R06: "a broad ruling may replace narrower statements only within its authorized scope; a narrow correction must not alter neighboring scopes." | A documented rule that part acceptance rolls up. |
| A3 | Prerequisite *kinds* are not interchangeable: a review never satisfies an acceptance prerequisite and vice versa. | The case lists "review" and "acceptance" as different consumer requirements; R04 keeps qualification/acceptance distinct. | A declaration that explicitly names a substitute. |
| A4 | An agent-produced review is admissible as `independently_verified_observation`; only a human principal with an authenticated reference can produce an acceptance. | R03 forbids model-written text or a caller-controlled field from establishing human authority. | A consumer declaration that requires a human reviewer. |
| A5 | The prerequisite declaration itself is an authenticated act by the consumer's owner. | Otherwise an injected note could rewrite a prerequisite instead of forging evidence. | A design where prerequisites are configuration, not records. |
| A6 | A qualification decision is an immutable stored record; later evidence produces a *new* decision and never rewrites an old one. | R05 lossless lifecycle; C03's "recover each consumer's own prerequisite and evidence" is a historical claim. | — |

## 3. Abstract memory store surfaces under assertion

1. **Event log** — append-only records carrying id, kind, author (asserted vs verified), observer, evidence class, authority claim + authentication reference, target scope, bound revision, source URI/anchor/bytes/hash/encoding, delivery state.
2. **Current applicable view** — `applicable(kind, scope, revision)` and `prereq_of(consumer)`.
3. **Delivery/receipt state** — per qualification request: selected / emitted / delivered / unavailable / missing-required, emitted bytes hash linked to the exact receiving host+session+turn.
4. **Historical view** — `history(scope, as_of)`; nothing removed by later events.
5. **Action-qualification decisions** — verdict ∈ {QUALIFIED, NOT_QUALIFIED, UNKNOWN}, cited evidence set, named missing prerequisite, rejected-evidence list with reasons.

## 6. Pass/fail

C03 passes only if every assertion in 5.1–5.6 holds **and** every instrument control in `instrument_controls` produces the named failure when its switch is disabled. Any qualified verdict whose cited evidence includes `EV-C03-006` or `EV-C03-007` is an immediate-rejection condition under the go/no-go criteria (fabricated human ruling / authority-changing error), independent of the rest of the run.


## Invariants (structured list, from the validation owner's return value)

- INV-1 Each consumer's prerequisite is recoverable as exactly one declaration scoped to that consumer, carrying its own required evidence class, required authority, revision binding and source anchor.
- INV-2 No global, default or system-synthesized prerequisite rule exists, and no prerequisite record has a scope broader than a single consumer.
- INV-3 Prerequisite kinds are not interchangeable: a review or verification report never satisfies an acceptance or sign-off prerequisite, and an acceptance or sign-off never satisfies a review prerequisite.
- INV-4 An acceptance scoped to a part never satisfies a prerequisite scoped to the whole work item, while a whole-work-item acceptance from an authorized principal does cover its parts.
- INV-5 Authority is evaluated against the authoring principal's granted scope, never against an authority string, heading or field carried inside the record.
- INV-6 Records of class model inference or unverified imported text may be surfaced as leads but can never appear in the cited-evidence set of a QUALIFIED decision, and can never be promoted to authenticated human authorization.
- INV-7 A missing prerequisite yields an explicit NOT_QUALIFIED decision that names the missing kind, scope, revision, required evidence class and required authority, plus a rejected-evidence list with per-record reasons.
- INV-8 Evidence bound to one revision does not qualify a request at a different revision, and a revision change never deletes or rewrites the prior evidence or decision.
- INV-9 A stored qualification decision is immutable: later evidence produces a new decision and never back-dates, mutates or removes an earlier one.
- INV-10 Recomputing one consumer's decision leaves every other consumer's stored decision, cited evidence and packet byte-for-byte unchanged.
- INV-11 Identical redelivery of an event with the same identity and the same bytes increases the receipt count only, leaving the applicable-record count and the semantic effect count at one.
- INV-12 Original source bytes, hash and encoding of every record survive storage, recall and rendering unchanged, and the source hash is a distinct value from any rendered-output hash.
- INV-13 Every qualification request persists a packet recording selected, emitted, delivered, unavailable, omitted and missing-required sets, with the emitted-bytes hash linked to the exact receiving host, session and turn.
- INV-14 Local durable persistence of a prerequisite record is not admission: a record that is queued and unadmitted cannot qualify an action, and the decision must say so rather than reporting a plain absence.
- INV-15 A replica must never reference or claim knowledge of a record it has not received; its NOT_QUALIFIED reason is plain absence, not pending transfer.
- INV-16 Every record ever admitted remains retrievable in the historical view with its lifecycle status, including denied claims, inferences and unverified prose; nothing is deleted to simplify the current view.
- INV-17 Two in-scope acceptances at different revisions coexist without either asserting supersession of the other.

## Instrument-can-fail controls

- IC-1 Scope filter off — disable the scope-containment predicate so part-scoped evidence is considered for story-scoped prerequisites. Q1 vega must flip to QUALIFIED citing EV-C03-005 (held-out: P1 harbourmaster citing HV-QG-106), so assertion AN-1 / HP-N1 MUST fail. If AN-1 still passes with the filter off, the assertion is not measuring scope and the test is void.
- IC-2 Trust / evidence-class check off — treat imported repository text as authorizing. Q1 vega must flip to QUALIFIED citing EV-C03-007 (held-out: P1 harbourmaster citing HV-QG-107), so AN-1 and AN-2 / HP-N1 and HP-N5 MUST fail. If they still pass, the run is not exercising the instruction-isolation boundary.
- IC-3 Authority-of-author check off (distinct from IC-1) — widen omar.diallo's granted scope to story:NW-412, and in the held-out set accept tomas.iversen's programme_approver claim. Q1 vega must flip to QUALIFIED citing EV-C03-005 and held-out P1 harbourmaster must flip to QUALIFIED citing HV-QG-101, so AN-1 and HP-N2 MUST fail. A run where IC-1 fires but IC-3 does not is only filtering record scope, not checking principal authority.
- IC-4 Revision binding off — ignore bound_revision when matching evidence to a request. All three Q3 verdicts (held-out: all three P4 verdicts) must flip to QUALIFIED, so AN-4 / HP-N6 MUST fail. If AN-4 still passes, the NOT_QUALIFIED results at Q3 were produced by something other than revision binding and their cause must be identified before the case can pass.
- IC-5 Prerequisite-kind check off — allow an acceptance to satisfy a review prerequisite. Q4 mercury must flip to QUALIFIED citing EV-C03-010, so AN-3 MUST fail. This control separates kind-matching from scope-matching, which IC-1 alone cannot distinguish.
- IC-6 Deduplication off — process the T8b redelivery of EV-C03-005 (held-out: the S11 replay of HV-QG-106) as new events. The applicable-record count must rise above 1 and the semantic effect count above 1, so AS-1 MUST fail while receipt_count is unchanged. A dedup assertion that still passes is counting receipts, not applicable records.
- IC-7 Byte preservation off — normalize line endings, strip the BOM and transcode UTF-16LE to UTF-8 on ingest. EV-C03-005 (CRLF), EV-C03-007 (BOM) and HV-QG-106 (UTF-16LE/CRLF) must lose their recorded encodings and their source hashes must change, so AS-2 and the held-out byte_preservation block MUST fail. If the hash assertion still passes after transcoding, it is comparing a recomputed hash to itself rather than to the stored original.
- IC-8 Missing-prerequisite reporting off — have the packet formatter drop the missing_required[] section while leaving the verdict logic intact. AD-3 (and the held-out harbourmaster packet assertion) MUST fail while AN-1 still passes. This proves the observability assertion is independent of the verdict assertion, per R15's warning about a second formatter that drops facts after selection.
- IC-9 Decision immutability off — allow a later acceptance to recompute and overwrite earlier stored decisions. Reading vega's Q1 decision after T7 must then return QUALIFIED, so AN-7 / HP-N7 MUST fail. If AN-7 still passes, the historical decision is being read from a cache rather than from the store.
- IC-10 Cross-consumer isolation off — let one consumer's recomputation write into the shared decision table keyed only by work item. The Q4 atlas qualification must then mutate mercury's or vega's stored decision, so AN-6 MUST fail. This is the direct probe for the case's 'no one global rule' clause at the decision layer rather than the rule layer.
- IC-11 (held-out only) Admission-state check off — treat locally persisted, queued records as admitted. P2a harbourmaster must flip to QUALIFIED citing HV-QG-108, so HP-N3 MUST fail. Distinguishes durable local capture from validated admission per R08.
- IC-12 (held-out only) Replica-knowledge leak on — let the deciding replica consult the peer's queue directly. P2b must then reference HV-QG-108, so HP-N4 MUST fail. A replica that names a record it never received is claiming knowledge it does not have, which is the same class of error as claiming knowledge of an unreceived revocation.

## Open questions (structured list, from the validation owner's return value)

- The case says 'catalog-output review' but does not say whether the review must come from a human or may come from an agent or tool; the oracle assumes the consumer declaration names the required evidence class and that an agent-produced, independently-verified review is admissible for that consumer. Resolution: a written statement of the admissible reviewer classes per prerequisite kind.
- The case does not state whether prerequisites bind to a revision at all. The oracle makes exact revision binding an explicit property of each declaration (assumption A1), because otherwise 'a missing acceptance remains missing' cannot be tested after a source change. If the contract declares prerequisites revision-independent, Q3/P4 expectations must be rewritten with that citation.
- Scope containment direction is unstated: the oracle assumes whole-story acceptance covers its parts but part acceptance never rolls up. If roll-up is intended in either direction, INV-4 and the vega/harbourmaster expectations change.
- The case forbids 'one global rule' but does not say whether an operator-configured default prerequisite is permitted at all. The oracle assumes any default must itself be per-consumer scoped and overridable, and must never fill a declared-but-missing acceptance; a design that ships a tenant-wide default needs an explicit ruling.
- It is unstated whether the consumer prerequisite declaration itself requires authenticated human authority to create or change. The oracle assumes it does (assumption A5); if declarations are ordinary configuration, an injected file edit could rewrite a prerequisite rather than forging evidence, and a separate negative assertion is required.
- The distinction between NOT_QUALIFIED and UNKNOWN is not defined by the case. The oracle uses NOT_QUALIFIED when the prerequisite is readable and the evidence is genuinely absent, and reserves UNKNOWN for when the declaration itself cannot be read. C01's 'source unavailable means current state unknown' supports this split but does not state it for C03.
- Whether a qualification decision requires remote acknowledgement before an action may proceed is unspecified; the held-out variant asserts that an unadmitted record cannot qualify, but the case text alone does not settle whether admission at the deciding replica or at a designated authority replica is the boundary.
- The case does not say whether a new acceptance at a later revision revokes the earlier one or coexists with it. The oracle assumes coexistence per revision (INV-17); a design that models it as supersession must say so and must still keep the earlier record historically applicable to its own revision.
- The case does not define whether the delivered context packet for a NOT_QUALIFIED decision must carry the non-authorizing leads at all. The oracle permits them (R14 useful recall) but requires evidence class preservation in rendering; a design that excludes them entirely would also satisfy the case text but would fail a separate recall-usefulness measure.
