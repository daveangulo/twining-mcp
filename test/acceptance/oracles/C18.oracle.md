# C18 Oracle — Crash at every durable step; recovery, uncertainty exposure, idempotent replay

**Case text under test:** "Kill writer/consumer between each durable step: source write, outbox, export, commit/transfer, admission, index and ack → Recovery preserves every acknowledged event and exposes uncertain/incomplete effects; replay into a real consumer remains idempotent. Test restart, not merely closing a connection."

**Requirements exercised (coverage map):** R07, R08, R16, R20. Authority/scope invariants R13/R17 are carried as guard assertions because recovery is a common place to lose them.

Expected outcomes below were fixed before any implementation observation. They are stated over an abstract memory store, not over any product's schema, file layout or transport.

---

## 1. Abstract model the assertions are written against

Five views must be queryable. A system that cannot answer these fails C18 by construction (not "not tested").

| View | Query | Returns |
| --- | --- | --- |
| `V1 events` | `events(store, event_id)` | 0..n stored event/record versions with `event_id`, `payload_digest`, exact stored bytes, `byte_len`, `scope`, `producer`, `revision`, `observed_at` |
| `V2 current` | `current(store, scope, [revision])` | the applicable-now record set a consumer would act on |
| `V3 delivery` | `delivery(event_id)` on producer **and** consumer independently | one state per side from the vocabulary in §2, plus `attempts[]` and `receipt_ref` |
| `V4 history` | `history(event_id)` | every attempt, every state transition, crash-truncated attempts included, with the reason each ended |
| `V5 gate` | `qualify(action, event_id)` | `{verdict: allow|deny, reason_code, evidence_refs[]}` for a proposed consequential action |
| `V6 ops` | `ops_report()` | queue depth/age, gaps, retries, failures, rejected records, index freshness, scope denials |

### Delivery-state vocabulary (producer side unless noted)
`recorded_local` → `queued` → `exported` → `transfer_unknown` → `transferred` → `admitted` (consumer) → `indexed` (consumer) → `acknowledged` (producer holds receipt bound to a consumer admission).
Terminal error states: `conflicted`, `rejected`, `abandoned_incomplete`.
`transfer_unknown` is mandatory vocabulary: a producer that cannot represent "I attempted the transfer and do not know the outcome" cannot satisfy C18.

### Declared durable-acknowledgement boundary `B`
R07 requires the implementation to *declare* its durable acknowledgement boundary before the run. This oracle admits exactly two declarations and asserts a deterministic outcome for each:

- **B = D1+D2 atomic** — source write and outbox enqueue commit in one transaction. Then kill point K1 is unreachable, and the implementation must *demonstrate* that crash injection between D1 and D2 yields either both or neither. Every event in §3 must terminate `acknowledged`.
- **B = D2** — the outbox commit is the boundary. Then an event killed after D1 and before D2 may terminate `recorded_local`, but it MUST appear in `ops_report().gaps` with an explicit uncaptured-downstream reason, and MUST NOT be `acknowledged`.

Any third declaration, or no declaration, is a C18 failure. A declaration made after seeing results is a failure (per acceptance-cases.md §"Never lower a threshold after seeing failure").

### Durable steps
`D1` source write (producer store commit) · `D2` outbox enqueue commit · `D3` export/serialize durable bytes + digest · `D4` commit/transfer handed to transport and transport reports success · `D5` consumer admission commit (validate + store) · `D6` consumer derived-index update · `D7` producer records the receipt.

## 3. Trigger sequence

Events `E-01` … `E-12`; exact bytes and expected digests are in `fixtures_json`. Every event is authored by `svc.forge-writer@anvil` in `sess-A7` on behalf of `u.rowan.mbele`, scope `repo-quarry-service:src/ingest/`, revision `r-c40d`, unless stated.

**Phase 0 — seed.** Start producer and consumer clean. Confirm `ops_report()` shows zero gaps, zero queued.

**Phase 1 — one kill per durable boundary.** For each scenario, submit the event, let the pipeline advance to exactly the stated point, kill the stated process, restart it, then let the system run to quiescence (bounded: 120 s of no state change) before asserting.

| Scn | Event | Kill target | Kill point | Notes |
| --- | --- | --- | --- | --- |
| KS-1 | `E-01` | producer | after `D1`, before `D2` | the `B` branch point |
| KS-2 | `E-02` | producer | after `D2`, before `D3` | |
| KS-3 | `E-03` | producer | after `D3`, before `D4` | payload carries a UTF-8 BOM and CRLF terminator |
| KS-4 | `E-04` | producer | during `D4`, **after** the consumer side durably received the bytes, before the producer learns the outcome | response-loss case |
| KS-5 | `E-05` | consumer | during `D5`, mid-admission (torn write) | |
| KS-6 | `E-06` | consumer | after `D5`, before `D6` | index lags a durable record |
| KS-7 | `E-07` | consumer | after `D6`, before `D7` (before the receipt reaches the producer) | |
| KS-8 | `E-08` | producer | after `D7` | restart must be a no-op |

**Phase 2 — replay idempotence into a real consumer.** After Phase 1 quiesces, replay `E-04` three more times over `chan-quarry` from a fresh producer process `sess-A8`, byte-identical, same `event_id`, same digest. The consumer is the same live process/store that served Phase 1 — not a stub.

**Phase 3 — conflicting reuse.** Submit `E-09`: the `event_id` of `E-03` with different bytes (LF wording instead of CRLF wording), same author and scope.

**Phase 4 — scope guard during recovery.** While the consumer is still draining its recovery backlog, deliver `E-10` (`repo-mesa-billing:src/rating/`) over `chan-quarry`.

**Phase 5 — positive control.** Submit `E-11` with no kill anywhere; let it run end to end.

**Phase 6 — model-authored claim.** Submit `E-12`, a `note` record authored by the writer *model* (evidence class: model inference), whose text states that sync finished for every queued item and nothing is pending. No human authenticated it. Submit it after Phase 1, before final assertions.

**Phase 7 — restart-vs-close discriminator.** Repeat KS-3 as **KS-3c**, but instead of killing the producer, only close the transport connection and let the same process continue. Record both results separately.

## 4. Required observable outcome — assertions

Assertions are `MUST` unless marked. `P*` are positive controls, `N*` are negative assertions, `G*` are guards.

### A. Acknowledged events are never lost
- **A1** For every event whose producer-side `V3` state is `acknowledged`, `events(store-basalt-local, event_id)` returns exactly one record whose `payload_digest` equals the producer's `payload_digest`.
- **A2** For every event acknowledged before a kill (`E-08`), the post-restart producer state is still `acknowledged`, the receipt reference is unchanged, and `V4` shows no new attempt created by the restart.
- **A3** No event present in `events(store-anvil-local, ·)` before a kill is absent from it after restart. Set equality on `event_id` before/after, per kill.
- **A4** After all phases, `|{e : producer_state(e) = acknowledged}|` = `|{e : consumer holds admitted record for e}|` restricted to in-scope events, and every member pairs 1:1 by `event_id`.

### B. Uncertain and incomplete effects are exposed, not smoothed over
- **A5** `E-04` (KS-4) must, at the instant after producer restart and before reconciliation completes, report producer state `transfer_unknown`, not `transferred` and not `queued`. `V4` must contain the interrupted attempt with an `outcome_unknown` termination reason.
- **A6** After reconciliation, `E-04` producer state is `acknowledged` with exactly one consumer record; the earlier `transfer_unknown` attempt remains visible in `V4` (history is not rewritten).
- **A7** `E-05` (torn admission) must, post-restart, be either (a) absent from `events(store-basalt-local, ·)` and re-drivable, or (b) present and complete with a digest equal to the producer's. A partially-written record that is readable but whose bytes/digest differ from the producer's is a failure.
- **A8** `E-06` (killed between admission and index) is present in `V1`/`V2` on the consumer after restart even if the index is stale; `ops_report().index_freshness` reports the lag or the rebuild. The durable record must not depend on the index for visibility.
- **A9** `ops_report()` after Phase 1 enumerates every incomplete effect it still carries: each such event appears with a state, an age and a reason. The count of enumerated incomplete effects equals the count derivable from `V3` (no silent omissions).
- **A10** `E-01` under declaration `B = D2` appears in `ops_report().gaps` with an explicit reason; under `B = D1+D2 atomic` it terminates `acknowledged` and the K1-unreachability demonstration is recorded.

### C. Replay is idempotent into a real consumer
- **A11** After Phase 2 (3 extra byte-identical replays of `E-04`), `events(store-basalt-local, "E-04")` returns exactly **one** admitted record.
- **A12** The consumer's semantic effect count for `E-04` is 1: `current(store-basalt-local, "repo-quarry-service:src/ingest/")` contains `E-04` exactly once, and no derived counter, relation or index entry for `E-04` has multiplicity > 1.
- **A13** `V4` for `E-04` shows 4 delivery attempts and 3 explicit `duplicate_suppressed` outcomes — deduplication is *recorded*, not invisible. Suppression with no trace is a failure of R20 even though A11/A12 pass.
- **A14** The receipt returned for each replay is the *same* receipt identity as the first admission, not a new one.

### D. Byte and identity preservation across crash and recovery
- **A15** `E-03` bytes stored at the consumer are byte-identical to the producer's source bytes: BOM present, CRLF preserved, `byte_len = 127`, digest `sha256:85c5…7e37`. No normalization on export, transfer, admission, index or recovery re-export.
- **A16** Re-export of `E-03` after producer restart yields the same digest as the pre-crash export; if the implementation cannot guarantee byte-stable re-export it must mark the event `exported_bytes_unverified` rather than assert equality.
- **A17** `E-09` (same `event_id` as `E-03`, different bytes) terminates `conflicted`: both digests are retrievable via `V4`, the consumer's admitted record for that `event_id` is unchanged, and `ops_report().rejected` includes it. (R07: "A reused identity with conflicting bytes is an explicit conflict.")

### E. Action qualification
- **A18** `qualify("publish_ingest_fix", "E-04")` issued while `E-04` is `transfer_unknown` returns `deny` with a reason code naming delivery uncertainty. It must not return `allow`, and must not return `deny` for an unrelated reason such as "not found".
- **A19** `qualify(·, "E-01")` under `B = D2` while `E-01` is `recorded_local` returns `deny` citing undelivered/uncaptured, not `allow`.
- **A20** No `V5` verdict cites the index as its sole evidence for an event whose durable record is absent.

### F. Positive controls
- **P1** `E-11` (no kill) reaches producer state `acknowledged`, consumer `indexed`, exactly one record, digest match, and `qualify("publish_ingest_fix", "E-11")` returns `allow`. If P1 fails the run is void — the harness, not the crash handling, is broken.
- **P2** After every restart, a fresh legitimate write (`E-08` path) still completes end to end; recovery does not wedge the pipeline.
- **P3** `ops_report()` at the end of Phase 5 shows zero gaps attributable to `E-11`.

### G. Negative assertions
- **N1** At no point does any event report producer state `acknowledged` while `events(store-basalt-local, event_id)` is empty. Sampled continuously during Phases 1–2, not only at quiescence. (This is the single most important assertion in C18.)
- **N2** `E-10` is never admitted, never appears in `current(store-basalt-local, ·)`, never appears in any consumer index, cache or diagnostic output, and appears in `ops_report().scope_denials`. Recovery backlog draining is not an exemption.
- **N3** `E-12`'s claim that nothing is pending changes no delivery state, no receipt, no `V5` verdict, and does not clear any entry from `ops_report().gaps`. Its evidence class remains model inference in `V1` and in any rendering.
- **N4** No kill produces a consumer record with a digest that differs from the producer's recorded digest for the same `event_id` while being reported as admitted (torn-write acceptance).
- **N5** The system makes no exactly-once *network delivery* claim in any output; at most it claims idempotent application (R08, explicit).
- **N6** KS-3c (connection close only) must **not** be reported as satisfying C18's kill requirement. If KS-3c passes while KS-3 fails, the report must state that the kill test failed; a suite in which KS-3c and KS-3 are indistinguishable has not tested restart.

---

## 5. Pass / fail

C18 passes only if: all `A*`, `P*`, `N*` hold; the durable boundary was declared before the run and the matching branch holds; the two-computer topology was real or its substitution was reported; and KS-1..KS-8 used actual process kills. Any single `N1` violation is an immediate rejection under "silent loss of an acknowledged event". Any `N2` violation is an immediate rejection under "cross-scope disclosure".


## Invariants (structured list, from the validation owner's return value)

> **Normalization note (lane 05, 2026-09-15).** The validation owner's return value carried ONE invariant while §1-§5 of this oracle carried the rest, so C18 was the only oracle in the corpus whose structured list was unusable by the index (every other case returns 14-25). The entries below restate invariants **already present in this document**, each tagged with the assertion it is drawn from so a reviewer can check that nothing was invented, weakened or strengthened. The original single entry is kept first, verbatim, as INV-1. No expectation in §1-§5 was edited; if a restatement and §4 ever disagree, **§4 governs**.

- **INV-1** (original return value, verbatim) Every event that ever reached the acknowledged/receipted state on the producing side has exactly one matching record with an identical payload digest on the consuming side, at every sampled instant and after every restart.
- **INV-2** (A2, A3) A kill never removes an event from the producer's store and never manufactures a new delivery attempt for an event already acknowledged before the kill; the set of stored event ids before a kill is contained in the set after restart.
- **INV-3** (A4) After all phases the set of producer-acknowledged in-scope events and the set of consumer-admitted records have equal cardinality and pair 1:1 by event id.
- **INV-4** (A5, A18) A producer that attempted a transfer and does not know the outcome says so explicitly (`transfer_unknown`) rather than reporting `transferred` or `queued`, and no consequential action is qualified from an event in that state.
- **INV-5** (A6) Reconciliation adds the resolved state; it never rewrites the interrupted attempt out of the history view.
- **INV-6** (A7, N4) A consumer record that is readable but whose bytes or digest differ from the producer's is never reported as admitted; a torn admission is either absent and re-drivable, or complete and digest-equal.
- **INV-7** (A8) A durable record's visibility never depends on a derived index; index lag or rebuild is reported rather than concealing the record.
- **INV-8** (A9) The operations report enumerates every incomplete effect the system still carries, each with a state, an age and a reason, and its count equals the count derivable from the delivery view.
- **INV-9** (A10) The durable acknowledgement boundary is declared before the run, and an event killed at that boundary follows the declared branch: `acknowledged` under `B = D1+D2 atomic`, an explicitly reasoned gap under `B = D2`.
- **INV-10** (A11, A12) Byte-identical replays of an event produce exactly one admitted record and exactly one semantic effect; no derived counter, relation or index entry for it has multiplicity greater than one.
- **INV-11** (A13) Deduplication is recorded rather than invisible: each suppressed replay appears in the history view with an explicit `duplicate_suppressed` outcome.
- **INV-12** (A14) Every replay returns the same receipt identity as the first admission, never a new one.
- **INV-13** (A15, A16) Source bytes survive export, transfer, admission, indexing and post-restart re-export unchanged - byte-order mark, line terminators and byte length included; an implementation that cannot guarantee byte-stable re-export marks the event `exported_bytes_unverified` instead of asserting equality.
- **INV-14** (A17) A reused event identity carrying different bytes terminates `conflicted`, with both digests retrievable and the already-admitted record for that identity unchanged.
- **INV-15** (A19, A20) Action qualification denies on uncaptured or undelivered evidence with a reason naming that condition, and never cites a derived index as its sole evidence for an event whose durable record is absent.
- **INV-16** (N2) Draining a recovery backlog is not a scope exemption: an out-of-scope event is never admitted, never enters the current view, index, cache or diagnostic output, and appears in the report's scope denials.
- **INV-17** (N3) A model-authored claim that nothing is pending changes no delivery state, no receipt and no gate verdict, clears no gap, and keeps its model-inference class in storage and in every rendering.
- **INV-18** (N5) No output claims exactly-once network delivery; at most idempotent application is claimed.
- **INV-19** (N6) Closing a connection is not a restart: an implementation that buffers state in memory must pass under close-only and fail under SIGKILL, so a close-only result is never reported as satisfying the kill requirement.
- **INV-20** (P1, P2, P3) The positive controls are load-bearing: an unkilled event completes end to end and qualifies, a fresh legitimate write still completes after every restart, and the report shows no gap attributable to the control. If the positive control fails, the run is void rather than green.

## Instrument-can-fail controls

- Deduplication off (consumer admits by arrival rather than by event id + digest): replay assertions A11/A12/A13 (held-out: the X-A4 single-record and single-semantic-effect statements) MUST fail, producing 4 records for E-04 / 3 for X-A4. If they still pass with dedup disabled, the replay test is measuring something other than deduplication and is not coverage.
- Byte preservation off (export or admission normalizes BOM/CRLF/trailing newline): A15/A16 MUST fail — E-03 must come out with byte_len != 127 and a digest != sha256:85c54116...7e37 (held-out: X-A3 byte_len != 131, digest != sha256:2956dd5a...70a24). A suite where a normalizing build still reports byte-identical storage is reading a normalized hash, not the source bytes.
- Scope filter off at the consumer (authorization applied after ranking, or skipped entirely while draining the recovery backlog): N2 MUST fail — E-10 (held-out: X-B1) must become visible in the consumer's current view, index, cache or diagnostic output, and must disappear from ops_report().scope_denials. This is the only control that proves the cross-scope assertion is live rather than vacuously true because the event never arrived.
- Trust/evidence-class check off (model-authored text is allowed to set delivery state or clear gaps): N3 MUST fail — E-12 (held-out: X-D1) must clear at least one gap or flip at least one delivery state. If N3 still passes with the trust check disabled, the assertion is passing because nothing consumes note records, not because authority is enforced.
- Digest validation off at admission (consumer stores whatever bytes arrive under the claimed id): A17/N4 MUST fail — E-09 (held-out: X-A9) must be admitted and must overwrite or shadow the record stored for E-03/X-A3 instead of terminating conflicted.
- Ack emitted before the admission commit (receipt written at receive time rather than after the consumer's durable commit): N1 and A1 MUST fail on KS-5/KS-7 (held-out: H-7/H-1) — at least one event must read acknowledged/receipted while records(consumer_store, id) is empty. If N1 still passes, the sampling is only at quiescence and is not catching the window the case is about.
- Restart replaced by connection close (the KS-3c / H-CLOSE substitution applied to all kill scenarios): any assertion that depends on losing process-resident state MUST change verdict — specifically, an implementation that buffers outbox entries in memory must pass under close-only and fail under SIGKILL. If the two modes give identical verdicts for every scenario, the harness is not actually restarting processes and C18's 'test restart, not merely closing a connection' clause is untested.
- Uncertainty state collapsed (handoff/transfer_unknown mapped onto transferred, or onto queued): A5 and A18 MUST fail — E-04 (held-out: X-A4) must read transferred/handed_off or enqueued after restart, and the gate must return allow (or deny-for-not-found) instead of deny-for-uncertain-delivery.
- Gap/observability reporting off (ops_report omits incomplete effects): A9/A10 MUST fail — the enumerated incomplete-effect count must diverge from the count derivable from the delivery view, and E-01/X-A6 must vanish from the gaps list under the D2/W2 boundary declaration.
- History retention off (recovery rewrites the attempt trail to its final state): A6 and A13 MUST fail — the interrupted transfer_unknown attempt for E-04 and the duplicate_suppressed outcomes must disappear from V4/trail while the final states still look correct, demonstrating that the history assertions are reading history and not the current state.
- Positive-control sabotage (E-11 / X-C1 deliberately routed through a broken path): P1 MUST fail and the whole run MUST be declared void rather than reporting the crash-scenario results as passes; a harness that reports A1-A20 as green while the positive control is red is scoring the absence of evidence.

## Open questions (structured list, from the validation owner's return value)

- C18 says "ack" without saying which acknowledgement is meant; R08 separates remote receipt, validated admission, materialization, context inclusion and task-level acknowledgement, so the oracle assumes ack = a producer-held receipt bound to a committed consumer admission (D7/W7) and treats task-level acknowledgement as out of scope for this case.
- C18 does not say where the durable acknowledgement boundary lies, and R07 only requires that it be defined; the oracle therefore branches on a pre-declared boundary (D1+D2 atomic vs D2) rather than assuming one, which means a system could technically pass by declaring a very late boundary and reporting everything earlier as a gap.
- "Recovery preserves every acknowledged event" is silent on whether recovery must also auto-redrive non-acknowledged in-flight events to completion or may simply leave them visible as gaps; the oracle requires visibility unconditionally and requires completion only where the declared boundary has been crossed.
- "Replay into a real consumer" does not define "real": a second live process on a second host is assumed, but the case does not say whether a second process on the same host, or a container pair, counts; the oracle requires the substitution to be reported rather than ruling it out.
- It is unstated whether losing a derived index is a C18 failure or an acceptable rebuildable loss; the oracle treats index loss as acceptable provided the durable record remains visible and the lag or rebuild is reported, but a stricter reading is possible.
- The case does not bound recovery time; the oracle uses a 120 s quiescence window and a 900 s cap per scenario, which are validator-chosen and should be agreed before the measured run per the acceptance-cases rule on thresholds.
- For a torn consumer admission, C18 does not say whether the partial record must be rolled back or may be completed on restart; the oracle admits both and forbids only a readable-but-digest-mismatched record reported as admitted.
- It is unclear whether deduplication suppression must itself be a recorded event (R20 observability) or may be silent as long as counts are right; the oracle requires a recorded suppression, which is an interpretation, not a literal reading of C18.
- C18 does not say how many replays constitute a test of idempotence; the oracle uses three (development) and two (held-out), which is arbitrary and may be too weak for a system whose dedup window is time-bounded.
- Whether the producer may automatically retry a transfer left in an uncertain state is unaddressed; the oracle permits it because dedup is separately required, but a system that instead parks such events for operator decision would also be defensible and would change A6/X-A4 expectations.
