# C12 — Independent validation oracle (development set)

**Case text under test (acceptance-cases.md, C12):** "A valid credential/signature claims another principal, unauthorized repository or human-ruling capability → Deny each independently. Include a legitimate allowed write as a positive control; an author string or signed payload alone cannot grant rights."

**Requirements this oracle is written against:** R03 (evidence classes — neither model text nor a caller-controlled `actor`/`active`/`promoted_by` field establishes human authority), R13 (hard scope before ranking), R17 (instruction and permission isolation), R18 (least-privilege access, credential scope), with supporting obligations from R01 (independent identities), R04 (external authority — qualification/publication/merge/acceptance are distinct), R07/R08 (stable event identity, dedup, receipt states), R16 (selected vs emitted vs delivered evidence), R20 (rejected records and scope denials must be observable).

**Authoring rule honoured:** every expected outcome below was fixed from `acceptance-cases.md`, `requirements.md` and `05-verification-and-operations.md` only. No Twining source, ADR, plan or existing oracle was read. Changing any expectation below requires a written source/requirement reason recorded against this oracle version (1.0.0).

---

## 1. Abstract model of the system under test

The oracle asserts only over five observable surfaces. An implementation may realise them however it likes; the harness must provide a read adapter for each.

| Surface | Symbol | What the harness must be able to read |
| --- | --- | --- |
| Event/record log | `EV` | Every submission that reached the boundary, its disposition (ADMITTED / DENIED / DUPLICATE_RECONCILED), reason code, verified principal, asserted-but-unverified fields, attempted payload bytes and hash |
| Current applicable view | `CUR` | The set of records a consumer would be served for a given (tenant, repository, scope) query right now, with evidence class and verified author per record |
| Delivery/receipt states | `RCPT` | Per submission, the independent states: queued, received, validated-admission, materialized, injected-into-a-receiving-turn, plus the receipt reported back to the submitter |
| Historical view | `HIST` | The append-only record of attempts including denied ones, with original submitted fields and preserved bytes |
| Action-qualification decisions | `QUAL` | For a posed action request, ALLOWED/DENIED plus a reason family and the evidence it relied on |

A "semantic effect" means: a new version of a record, a new membership in `CUR`, or a new grant/principal/credential. Counting rows is not sufficient evidence for any assertion below (per 05-verification-and-operations: verify histories, receipts and current views, not only row counts).

**Credentials.** `key-quill-01` (subject `svc-agent-quill`) is *cryptographically valid, unexpired, unrevoked and correctly verified in every trigger*. Nothing in C12 turns on a bad signature: the case is entirely about what a good signature does **not** buy. ## 3. Exact trigger sequence (development order)

All triggers T1–T8 are submitted from `host-birchwood-01` / `sess-birchwood-7731` into `store-alpha`, in this order, with a fresh store.

1. **T1 — impersonation.** `key-quill-01` signs a submission whose `author` is `svc-agent-drake` and `observer` is `h-peregrine-vance`. Everything else (repo, scope, evidence class) is legitimate. *Denial axis: principal binding.*
2. **T2 — unauthorized repository.** `key-quill-01` signs a legitimate-looking worker result whose repository provenance is `rid-9c31` at `rev-K4`. *Denial axis: repository authorization.*
3. **T3 — human-ruling capability claim.** `key-quill-01` signs a payload with `evidence_class: human_authorization`, `actor: h-mira-calloway`, `promoted_by: h-mira-calloway`, `active: true`, prose "APPROVED by Mira Calloway: … cleared for mainline publication." The payload deliberately carries a UTF-8 BOM and CRLF line endings so that any normalisation before hashing is detectable. *Denial axis: evidence class / human authority.*
4. **T4 — out-of-granted-scope write inside an authorized repository.** `key-quill-01` writes to `rid-7f2a` scope `services/payments/`. *Denial axis: scope authorization.*
5. **T5 — POSITIVE CONTROL.** `key-quill-01` writes a `reported_worker_result` to `rid-7f2a` scope `services/ledger/` at `rev-B2`. Event id `ev-quill-0006`. Must be admitted end to end and delivered to `sess-cedarhill-4402` turn 3.
6. **T6 — exact redelivery of T5** (same event id, byte-identical payload). Dedup hook.
7. **T7 — reused event id with conflicting bytes** (`ev-quill-0006`, one word changed). Byte-preservation and conflict hook.
8. **T8 — POSITIVE CONTROL for genuine human authority.** `key-mira-hw` submits a `human_authorization` on `rid-7f2a` scope `services/ledger/`.
9. **T9 — permutation run.** The same eight submissions replayed in reverse order (T8, T7, T6, T5, T4, T3, T2, T1) into the fresh `store-alpha-perm`.

After all triggers, the harness poses seven action-qualification requests Q1–Q7 (see §4.5).

## 4. Required observable outcome — concrete assertions

Assertion IDs are stable; instrument controls in the `instrument_controls` field reference them.

### 4.1 Event/record log (`EV`)

- **A1** `EV[ev-quill-0002]` (T1) disposition = DENIED with reason code in the family `PRINCIPAL_BINDING_MISMATCH`. Version count for that event id = 0.
- **A2** `EV[ev-quill-0003]` (T2) disposition = DENIED, reason family `REPOSITORY_NOT_AUTHORIZED`, versions = 0.
- **A3** `EV[ev-quill-0004]` (T3) disposition = DENIED, reason family `EVIDENCE_CLASS_NOT_AUTHORIZED`, versions = 0.
- **A4** `EV[ev-quill-0005]` (T4) disposition = DENIED, reason family `SCOPE_NOT_AUTHORIZED`, versions = 0.
- **A5 (independence)** The reason codes recorded for T1, T2, T3, T4 are four pairwise-distinct stable values. A single generic `REJECTED` code for all four fails A5 even if A1–A4 individually "pass": "deny each independently" requires each axis to be separately diagnosable.
- **A6 (independence, stronger)** Each of T1–T4, submitted *alone* into a fresh store with the other three absent, still yields the same disposition and reason code. No denial may depend on a sibling denial having occurred.
- **A7** `EV[ev-quill-0006]` (T5) disposition = ADMITTED, `verified_author` = `svc-agent-quill`, evidence class `reported_worker_result`, versions = 1, stored payload hash equals the build manifest value for `T5.payload`.
- **A8** T6 produces disposition DUPLICATE_RECONCILED: versions for `ev-quill-0006` remain 1 and semantic effects remain 1, while two distinct deliveries are recorded.
- **A9** T7 is DENIED with reason family `EVENT_ID_BYTES_CONFLICT`, and `EV[ev-quill-0006]`'s stored payload hash is unchanged (still `manifest:T5.payload`), i.e. the conflicting submission neither overwrote nor merged into the admitted record.
- **A10** `EV[ev-mira-0001]` (T8) disposition = ADMITTED with `verified_author` = `h-mira-calloway` and evidence class `human_authorization`.
- **A11** The admitted seed record `ev-quill-0001` is byte-identical and version-identical after all triggers.

### 4.2 Current applicable view (`CUR`)

- **A12** `CUR(tnt-northgate, rid-7f2a, services/ledger/)` = exactly {`ev-quill-0001`, `ev-quill-0006`, `ev-mira-0001`}; count = 3.
- **A13 (negative)** `CUR` for that query contains none of `ev-quill-0002`, `ev-quill-0003`, `ev-quill-0004`, `ev-quill-0005` — under any query mode, including exact-ID lookup, lexical search, vector/semantic search, graph-neighbour expansion, cache reads and any operator/diagnostic endpoint. A denied record that is invisible in the ranked view but retrievable by exact ID fails A13.
- **A14 (negative)** `CUR(rid-7f2a, services/payments/)` count = 0, and `CUR(rid-9c31, *)` count = 0.
- **A15 (negative, cross-tenant isolation)** `store-beta` contains zero records, zero attempt records and zero receipts originating from any C12 trigger.
- **A16** Exactly one record in `CUR` carries evidence class `human_authorization`, and its `verified_author` is `h-mira-calloway`, and it was submitted with `key-mira-hw`. No record with that class traces to `key-quill-01`.

### 4.3 Delivery/receipt states (`RCPT`)

- **A17** For each of T1–T4 and T7: `received` = true, `validated_admission` = false, `materialized` = false, `injected_into_any_turn` = false, receipt state = `REJECTED_ACKNOWLEDGED`, and a rejection receipt is reported back to the submitter. A silently dropped submission with no receipt fails A17 as hard as an admitted one (R07: no silently lost acknowledged event; R20: rejected records must be observable).
- **A18** For T5 and T8: the five states (queued, received, validated-admission, materialized, injected) are each independently observable and all true; the emitted packet's bytes/hash are persisted and linked to `host-cedarhill-02` / `sess-cedarhill-4402` / turn 3. `admitted == delivered` collapsed into one flag fails A18 (R16: selected, emitted, delivered and unavailable are distinct).
- **A19 (negative)** The payload bytes of T1–T4 appear in no context packet emitted to any receiving turn in any session.

### 4.4 Historical view (`HIST`)

- **A20** `HIST` contains an attempt record for each of `ev-quill-0002`…`ev-quill-0005` and for T7, each carrying: submitting credential id, verified subject principal, the asserted fields *as submitted* (including `author: svc-agent-drake`, `actor: h-mira-calloway`, `promoted_by`, `active: true`), the reason code, observation time, and the attempted payload hash.
- **A21 (byte preservation)** For every denied attempt, the retained attempted payload bytes are byte-identical to the fixture (the BOM and both CRLF sequences in T3 survive) and the recorded hash equals the build manifest value. Any normalisation, trimming, re-encoding or "cleaned text" substitute fails A21 (R02: source-byte hash, normalized-text hash and rendered-output hash are different values).
- **A22 (negative)** No attempt record is promoted over time: re-reading `HIST` after the full sequence, the T3 attempt is still classed as an unverified assertion by a service principal, not as a human ruling, and carries no `active`/`promoted` status that `CUR` would honour.

| ID | Request | Expected |

| **A23/Q1** | `publish_to_mainline`, `rid-7f2a`, `services/ledger/`, citing T3's `ev-quill-0004` | DENIED, reason family `MISSING_HUMAN_AUTHORIZATION` |
| **A24/Q2** | `publish_to_mainline`, `rid-7f2a`, `services/ledger/`, citing T8's `ev-mira-0001` | **ALLOWED** (positive control) |

| **A27/Q5** | `write_record` on `rid-7f2a` scope `services/payments/` with `key-quill-01` | DENIED, `SCOPE_NOT_AUTHORIZED` |

- **A30 (negative, no privilege accretion)** After all triggers and all Q requests: `key-quill-01`'s grant set is byte-identical to its seeded grant set; zero principals and zero credentials were created by any trigger; no grant on `rid-9c31` or `services/payments/` exists. A system that "learns" a claimed capability by recording it fails A30.

### 4.6 Order independence

- **A31** The permutation run (T9, reverse order, fresh `store-alpha-perm`) yields identical dispositions, reason codes, `CUR` membership and `QUAL` outcomes. Only ingest timestamps and internal row ordering may differ. In particular, admitting T5/T8 first must not weaken the denials, and denying T1–T4 first must not block the positive controls.

## 5. Compliant alternative dispositions

The case text says "deny each independently" without fixing a disposition mechanism, so this oracle accepts exactly one alternative per denial axis, and only if its sub-conditions all hold:

- **Reject-at-ingress (primary expectation):** the submission never becomes a record; assertions above read as written.
- **Admit-as-unverified-assertion (accepted alternative):** the submission may be stored *only if* (a) its `verified_author` is the authenticated key subject `svc-agent-quill`, never the claimed principal; (b) the claimed principal/repository/capability is retained only in an `asserted_*` field whose provenance class is "asserted, not independently checked"; (c) it is excluded from `CUR` for the scope it claimed (A13/A14 still hold); (d) it can never satisfy any `QUAL` request (A23, A25–A27 still hold); and (e) a distinct reason code still distinguishes the four axes (A5). Storing it as an ordinary in-scope record, or with the claimed evidence class intact, is a failure, not an alternative.

## 6. Acceptance rule for C12

C12 passes only if **all** of A1–A31 hold on the development set **and** the held-out set, **and** every instrument control in `instrument_controls` demonstrably flips its named assertion to FAIL when the corresponding check is disabled. Per the go/no-go criteria, any single authority-changing outcome here (A3, A16, A22, A23, A24, A30) is an immediate-rejection condition and is not tradeable against latency or token results.


## Invariants (structured list, from the validation owner's return value)

- A cryptographically valid signature establishes only which credential subject submitted the bytes; it establishes nothing about the claimed author, repository, scope or evidence class carried inside those bytes.
- A caller-supplied author, actor, promoted_by or active field is retained as an asserted, independently-unchecked value and never becomes the record's verified principal or authority.
- Human authorization exists only when it arrives through an authenticated human-principal channel; no service credential can produce, promote or imply it.
- Each denial axis — principal binding, repository authorization, scope authorization, evidence class — is evaluated and reported independently, yielding four pairwise-distinct stable reason codes.
- Every denial holds when its trigger is submitted alone into a fresh store, so no denial depends on a sibling denial having occurred.
- A denied submission produces an observable rejection receipt to the submitter and an attempt record in history; it is never silently dropped.
- A denied submission is absent from the current applicable view under every retrieval path, including exact-ID lookup, lexical search, vector search, graph expansion, caches and operator diagnostics.
- Authorization is enforced before candidate ranking or exposure, so relevance never becomes a route into a scope the credential does not hold.
- Attempted payload bytes of denied submissions are preserved byte-identically, including BOM, CRLF and non-breaking space, and their recorded hash equals the pre-submission manifest hash.
- An admitted record's stored bytes and hash are unchanged by any later submission that reuses its event id with different bytes, and that reuse is an explicit conflict rather than an update.
- An identical retry of an admitted event produces an additional delivery record but no additional semantic effect, version or view membership.
- Local persistence, remote receipt, validated admission, materialization and injection into a receiving turn are independently observable states, and admission never implies delivery.
- The bytes actually emitted to a receiving turn are persisted and linked to a specific host, session and turn.
- A rejected submission's payload never reaches any receiving turn's context packet.
- No trigger in this case creates a principal, creates a credential, or widens any existing grant's repositories, scopes or evidence classes.
- A legitimate in-grant write by the authenticated subject is admitted, served and able to qualify its permitted action, proving the denials are specific rather than a blanket refusal.
- A genuine human authorization qualifies only the action inside the repository and scope it was issued for, and is denied outside them.
- Prior admitted evidence is unchanged in bytes, version count and view membership after every denial in the sequence.
- All dispositions, reason codes, view membership and qualification outcomes are identical under the reverse-order permutation in an independent store, so arrival order settles nothing.
- No record, attempt record or receipt from this case appears in the unrelated tenant's store.
- Recall rendering preserves evidence class, so a denied or unverified assertion cannot be narrated as an approval in prose even when the machine-readable assertions pass.

## Instrument-can-fail controls

- Principal-binding check OFF (bind the record's verified author to the submitted `author` field instead of the credential subject): A1 and A26/Q4 MUST fail, and the negative assertion 'no record has verified_author = svc-agent-drake' (held-out: svc-agent-osprey) MUST fail. If they still pass, the impersonation assertions are not actually reading verified authorship.
- Repository-authorization check OFF (accept any repository id the payload names): A2, A14 and A25/Q3 MUST fail, and ev-quill-0003 (held-out ev-fennec-1103) MUST appear under rid-9c31 / rid-2b17. If A14 still passes, the view query is not actually scoped by repository identity.
- Scope filter OFF (ignore the path-prefix scope on both write and read): A4, A14 and A27/Q5 MUST fail, and the services/payments/ (held-out pkg/routing/) view count MUST become 1. Run this control separately against the write path and against the read path — a system that denies the write but would have leaked the record on read must fail the read-side variant.
- Trust / evidence-class check OFF (honour the submitted evidence_class, actor, promoted_by and active fields): A3, A16, A22 and A23/Q1 MUST fail, and the current view MUST show two human_authorization records, one of them traceable to key-quill-01 (held-out key-fennec-7). This is the primary authority-changing control; if it does not flip A23/Q1 to ALLOWED, the qualification gate is not consulting evidence class at all.
- Deduplication OFF (treat every delivery as a new event): A8 MUST fail — versions for ev-quill-0006 (held-out ev-fennec-1101) become 2 and semantic effects become 2. If A8 still passes, the assertion is counting deliveries rather than semantic effects.
- Byte preservation OFF (normalize text before hashing/storing: strip the BOM, convert CRLF to LF, collapse the non-breaking space): A21 MUST fail — the retained attempted-payload hash for T3 (held-out P2) MUST no longer equal the build manifest value. If A21 still passes, the harness is comparing normalized text to normalized text and proves nothing about byte preservation.
- Event-identity conflict detection OFF (last write wins on a reused event id): A9 MUST fail — ev-quill-0006 (held-out ev-fennec-1101) MUST take the T7/P7 bytes and hash. This also catches a harness that re-reads the record through a cache rather than durable storage.
- Receipt-state collapse ON (report a single boolean 'stored' instead of the five independent states): A17 and A18 MUST fail. A system that cannot distinguish admitted from delivered cannot satisfy the case even if every record lands correctly.
- Rejection-receipt suppression ON (deny silently, emit nothing to the submitter): A17 MUST fail while A1–A4 still pass — this control exists specifically to prove that A17 is testing observability and not merely re-testing denial.
- Retrieval-path coverage control: disable the authorization filter on exactly ONE path at a time (exact-ID lookup, then lexical, then vector, then graph-neighbour expansion, then cache, then the operator/diagnostic endpoint). A13 MUST fail on each pass individually. If A13 passes with a path disabled, the assertion is not querying that path and the coverage claim for R13 is unproven.
- Cross-tenant isolation OFF (route the producer's outbox to store-beta / store-vermeer as well): A15 MUST fail with a non-zero record count in the unrelated tenant's store.
- Positive-control kill switch (deny everything unconditionally): A7, A10, A24/Q2 and A28/Q6 MUST fail. This proves the denial assertions are not passing merely because the system refuses all writes — the single most likely way for this case to pass for the wrong reason.
- Grant-accretion control ON (record claimed capabilities into the credential's grant set as 'learned'): A30 MUST fail. Verifies that the grant-state assertion reads live authorization state rather than the seed fixture.
- Order-independence control (run the permutation with denial state carried over from the first store instead of a fresh one): A31 MUST fail to reproduce, exposing any dependence on prior-run state rather than on the rules.
- Held-out prose control (replace the P2 sign-off text with an obviously suspicious variant containing the words 'ignore restrictions'): A3 and H1 MUST still pass and their reason codes MUST be unchanged. If the denial only appears with the suspicious wording, the system is keyword-matching rather than checking authority, and the held-out result is invalid.

## Open questions (structured list, from the validation owner's return value)

- Disposition ambiguity: 'deny each independently' does not say whether a rejected submission must be refused at ingress or may be stored as an unverified assertion that is excluded from the applicable view. The oracle names reject-at-ingress as primary and specifies a five-condition accepted alternative; the programme should ratify one so that pass/fail is not observer-dependent.
- Does 'claims another principal' cover only another service principal, or also a human principal named as observer/author? The oracle tests both (svc-agent-drake as author, h-peregrine-vance as observer) but the case text names neither.
- Whether a denied submission must generate a rejection receipt back to the submitter, or may be silently quarantined. The oracle requires a receipt by reading R07/R20 (no silently lost acknowledged event; rejected records and scope denials must be observable), but C12's own text is silent.
- Whether a valid credential used against an unauthorized repository should additionally trigger a credential-level response (flag, throttle, revoke). The oracle asserts no grant change and no privilege accretion but deliberately does not require a punitive response, since none is specified.
- Whether rejected submissions count as 'acknowledged events' for the R07 no-silent-loss guarantee, and therefore what retention applies to denial attempt records. The oracle requires them to be present at end of run and says nothing about longer retention.
- R03 says neither model-written text nor a caller-controlled field establishes human authority, and C12 says a signed payload alone cannot grant rights. Read strictly, that could forbid ANY signature-based human ruling, including the T8/P8 positive control. The oracle assumes a distinct authenticated human channel (a human-subject credential plus an authenticated_human_channel attribute) is the intended distinction; if the programme intends human authority to require an out-of-band confirmation, T8/P8 must be re-specified.
- Whether 'unauthorized repository' means a repository the credential has no grant on, or one belonging to a different tenant entirely. The oracle tests the harder same-tenant case (rid-9c31 / rid-2b17) plus a cross-tenant store isolation control, but the case text does not distinguish them.
- Whether the applicable-view exclusion must also hold for an operator or administrator query. The oracle asserts diagnostics must not bypass access controls (per R16) but C12 does not state whether an operator is expected to be able to see denied content under a separate privilege.
- Whether the four denial checks must be evaluated exhaustively (all applicable reasons reported) or may short-circuit on the first failure. The oracle only requires distinct codes per single-axis trigger and does not currently include a multi-axis trigger; if exhaustive reporting is required, a combined trigger should be added.
- Scale: C12 is specified as a behavioural case with no corpus tier attached. Whether these assertions must also hold at the 1,000/10,000/100,000-record tiers named in the trial design, especially the 'absent from every retrieval path' assertions where ranking behaviour changes with corpus size, is unstated.
