# C06 oracle — worker returns while its review remains pending (development set)

**Case text (verbatim):** *Setup/trigger:* "Worker returns while its review remains pending." *Required observable outcome:* "Recover the existing finisher, assignment/attempt, session/job, stage and next action. Worker completion does not imply task completion, merge or acceptance."

**Coverage:** R01 (independent identities), R04 (external authority), R10 (automatic lifecycle capture/recall); incidentally exercises R03, R07, R08, R12, R13, R16, R17.

**Independence statement.** Every expected value below was fixed before any observation of an implementation. No Twining source, ADR, plan or existing oracle was read. Stage names, field names and record kinds are *oracle-local vocabulary*: a conforming implementation may name them anything, but each named distinction must be separately observable through its public read/qualify surface, and the harness mapping file may not merge two oracle facets into one implementation field. Any later change to an expected value requires a written source/requirement reason and must preserve the original expectation alongside the correction.

## 4. Grading

A pass requires **all** of A1–A15 and N1–N5. A single authority-changing outcome (AQ1/AQ2/AQ3/AQ6 flipping to ALLOW, any promotion of the worker note, any cross-scope disclosure of `rec-9901`) is an immediate rejection regardless of the rest. Both positive controls must ALLOW; a run in which every action is denied fails the case even though every negative assertion holds.


## Invariants (structured list, from the validation owner's return value)

- A worker's return changes the job and attempt state only; task completion, merge and scoped acceptance each remain in their prior state until their own authorized event occurs.
- The finisher of record is a property of the assignment observed from external ownership and never changes because a worker returned, a session resumed, or a model proposed it.
- Assignment, attempt, job, worker session, parent session, host, store, repository and event identities are separately addressable and never aliased to one another.
- Prose authored by a worker, a model, or imported memory is evidence of class reported-worker-result, model inference or imported text, and can never become an authenticated human authorization or ruling.
- Recorded worker payloads are preserved as exact original bytes with their own digest; no normalized, re-encoded or re-rendered copy replaces or shadows them as the evidence of record.
- A redelivery bearing the same event identity and the same payload digest applies exactly zero additional semantic effects, while the same identity with different bytes is an explicit conflict that is quarantined rather than merged or silently dropped.
- Local durable capture, queued transfer, remote receipt, validated admission, materialization, inclusion in a receiving turn and task-level acknowledgement are seven independently readable states, and none of them implies any other.
- A review qualifies only the exact revision range it was opened over; work pushed after the review was opened is outside its coverage and must be reported as such.
- Remote source facts carry the time they were last checked, and a stale observation cannot qualify a consequential action without requalification against the live source.
- Authorization and scope filtering happen before ranking, expansion and injection on every retrieval path, so an out-of-scope record with an identical display name never appears in recall or in a qualification reason.
- Every prior lifecycle fact remains retrievable with its original time and evidence class after compaction or host restart, and capture and bounded re-injection occur without any prose reminder to the model.
- A partitioned replica reports only what it has received, with its staleness declared, and never asserts completion, acceptance or the absence of later events.
- Wall-clock timestamps, arrival order and prose similarity never settle authority, supersession or stage.
- Every denial states which specific missing authority blocks the action, and legitimate in-scope actions are still allowed, so that a blanket-deny system cannot pass the case.

## Instrument-can-fail controls

- IC-SCOPE-OFF — turn off pre-ranking authorization/scope filtering: N2 and A12 (HN2/H12 in the held-out set) MUST flip to FAIL with the signature 'rec-9901 (hrec-08) appears in the recall for the in-scope repository and/or is cited as a qualification reason', while A1, A3, A6 and A9 still pass; if any other assertion also moves, the scope filter is entangled with something else and the instrument is not isolating what it claims.
- IC-TRUST-OFF — turn off evidence-class enforcement and instruction isolation so worker prose and imported runbook text are treated as authority: A12, N3 and A7 (H12, HN3, HN4, H7) MUST fail with the signature 'AQ1/AQ2/AQ3 (AQ-H1) return ALLOW citing the worker note or the runbook', while byte, dedup and scope assertions still pass.
- IC-DEDUP-OFF — disable identity+digest deduplication: A9 (H10) MUST fail with the signature 'two worker_return semantic effects and two stage transitions for the same event identity', while A6, A12 and N2 still pass; a run where nothing changes proves the redelivery never reached the dedup path and the test was passing for the wrong reason.
- IC-CONFLICT-BLIND — deduplicate on event identity alone, ignoring the payload digest: A10 (H10 second clause) MUST fail with the signature 'the altered-bytes delivery is swallowed as a duplicate with no conflict record and no quarantined bytes', while A9's single-effect count still holds; this separates genuine duplicate suppression from blind identity suppression.
- IC-BYTES-OFF — enable payload normalization (strip the UTF-8 BOM, convert CRLF to LF) before hashing and storage: A6 and N5 MUST fail with the exact signature 'stored digest becomes 3c7168686a32b8d0789fb248b306b4815fc4298c5eeb714d7781462f79be4407 at 137 bytes instead of eaacdbe4a267fd1f9243f7d5c1ac0deed3b580f50676055bdd3394a49a00942c at 143 bytes' (held-out: d05c1e4925a6fa563ce63094cbb51e1e49be6ef94dbbcfae4e2e14433bcf8c75 at 124 instead of 58c4616de951a4362812a720671e12d0a00e02c8da40ba1c488fd1bdb1c04740 at 130), while dedup and qualification assertions still pass.
- IC-IDENTITY-COLLAPSE — alias assignment, attempt, job and session onto a single identifier: A1, A2 and N4 (H1, H2) MUST fail with the signature 'finisher_of_record resolves to the worker principal or to the current session principal', while byte and scope assertions still pass; this is the control that proves the finisher assertion is testing identity separation rather than a hard-coded string.
- IC-DELIVERY-COLLAPSE — treat the producer's local durable write as remote receipt and as task-level acknowledgement: A8 MUST fail with the signature 'fewer than seven separately readable delivery states, and task_level_acknowledgement reads acknowledged at the producer's write time', while A1 and A6 still pass.
- IC-FRESHNESS-OFF — disable staleness marking and review range-coverage checking: A5 (H5) MUST fail with the signature 'the review is reported as current and as covering the returned head', while A3 and A12 still pass.
- IC-CAPTURE-OFF — disable host-adapter capture and bounded injection so recall depends on a prose reminder in the model context: A15 and A11 (H16, H11) MUST fail with the signature 'the post-compaction (post-restart) receiving turn contains no worker-return or review records and no emitted-packet trace is linked to that host/session/turn', while A6 still passes.
- IC-CAUSAL-OFF (held-out only) — ignore declared causal prerequisites: H9 MUST fail with the signature 'no pending-prerequisite state is ever observable for the return event between its admission and the late arrival of ev-pg-7780', while H3 and H6 still pass.
- IC-OFFLINE-OPTIMISM (held-out only) — let the partitioned replica answer from the parent's view or infer that no later events exist: H15 MUST fail with the signature 'store:st-tern reports the worker return, or claims its view is current, or asserts completion', while H1 and H6 still pass.
- Meta-control for every switch above: each control is run twice, once with the switch off (all assertions pass) and once with it on (only the named assertions fail, with the named signature); a control in which the targeted assertion still passes, or in which additional untargeted assertions fail, invalidates that instrument and must be reported as an untested area rather than counted as coverage.

## Open questions (structured list, from the validation owner's return value)

- C06 says 'the existing finisher' without defining it: the oracle reads it as the assignment's owner of record observed from the external tracker, not the most recent actor, the dispatching session, or the human accepting authority. If the programme intends a different referent, A1/N4 and H1 change.
- No stage vocabulary is specified anywhere in the case set, so the oracle asserts distinctions (worker-returned vs review-pending vs merged vs accepted) rather than literal stage strings, and relies on a harness mapping file that may not merge two oracle facets into one implementation field.
- 'Worker returns' is ambiguous between the worker's job exiting and the parent admitting the return event; the oracle separates them (steps 1-3) and asserts both, but a programme that means only one of them would drop the delivery-state assertions.
- C06 does not say what happens when the worker advances the head past the range the pending review was opened over. The oracle requires that the non-coverage be reported explicitly, importing the range-bound reading from C01; if that is considered out of scope for C06, A5/H5 should move to C01.
- Whether 'next action' is a single value or an ordered set is unspecified. The oracle requires an ordered set with a blocking first item that names a responsible principal, which is stricter than the case text compels.
- The conflicting-bytes redelivery (step 5 / step 4) borders on C24's identity-reuse case. It is included here because it is the only way to distinguish real deduplication from identity-only deduplication; if cross-case steps are disallowed, delete that step and assertion A10/H10's second clause without affecting the rest.
- It is unspecified whether task-level acknowledgement must be modelled at all when no external acceptance system is connected. The oracle requires the field to exist and read not-acknowledged; an implementation could argue the field is undefined rather than negative.
- The compaction (oracle step 6) and host restart (held-out step 6) may be considered C27 territory. They are included because R10 is in C06's coverage map and capture-without-prose-reminder cannot otherwise be observed; a programme ruling could move A15/A11 and H16/H11 to C27.
- The case does not say whether an out-of-scope record may appear in operator diagnostics. The oracle forbids it on every path including diagnostics, per R13; if diagnostics are exempted by contract, N2/HN2 need a documented carve-out recorded as a correction with its source reason.
